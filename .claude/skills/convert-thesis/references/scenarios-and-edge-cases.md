# 典型场景与边界案例

## 典型场景

### 只有学校模板，没有已整理证据

先检查已有格式证据。模板含义没有证据支持时，暂停受影响的操作并请求明确的来源和适用结论；证据就绪后再规划编辑。

### 前置页嫁接导致正文页码变化

把前置页面、节边界、正文起始页和目录视为联动范围。先建立结构，再渲染前置页和正文起始区域，最后更新目录并检查全部目录页。

### 一次编辑反馈看起来正确

编辑反馈只证明局部结果。继续完成最终候选渲染和结构验证后，才能判断可交付。

### 大论文可以按章节分析

只有稳定对象边界和跨章节依赖明确时，才委派只读分析。章节编号、目录、脚注连续性和全局样式仍由主 Agent 合并。

### 学校要求与模板冲突

停止受影响操作，保留两方来源。只有权威关系明确或用户确认后才选择一种规则，并在最终证据中保留解决记录。

## 反例

- 直接打开 DOCX 内部 XML 修改格式。
- 把 subagent 提出的操作当作已经执行。
- 用结构验证成功替代视觉复核。
- 用旧候选页面证明新候选没有版式问题。
- 因为学校规则常见，就在没有当前证据时套用。
- 为了“看起来更好”改写论文论述或删除无法排版的内容。

## 必须停止交付的情况

关键学校证据缺失、源内容可能丢失、视觉关键页不可见、验证失败、候选与证据哈希不一致，或写入/输出路径未授权时，明确返回不可交付或需要补证据。
