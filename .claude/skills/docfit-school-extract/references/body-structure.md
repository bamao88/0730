# 正文代表结构

## 目标

正文模板表达可重复的写作能力，不复制学校源模板中的每个具名样例章。通常用一个
`body.chapters` 结构承载本校真实展示的代表成员：

```text
body.chapters
├── body.heading.outline1    章标题
├── body.heading.outline2    一级节标题
├── body.heading.outline3    二级节标题
├── body.paragraph           普通正文
└── 本校确有证据的图、表、公式、列表等代表成员
```

这不是代码固定的“第几章”规则。先理解学校材料，再选择最能代表通用正文的一个物理连贯块。

## 选择方法

- 优先选择不绑定具体主题的通用演示；若没有，比较多个具名区域，选择能完整证明本校层级与版式的
  最小代表集合。
- 成员来自同一个结构上连贯的学校正文块，并按真实文档顺序提交。不要从不同章拼接出虚构结构。
- 标题层级综合显式编号、相对视觉层级、要求文件、TOC 关系和上下文判断；Word 样式名相同不证明
  层级相同，编号外观也不能脱离学校上下文成为代码规则。
- 先保住每种关键版式的唯一证据，再清理其他写作样例。文献综述、结论等具名模块通常复用同一
  正文能力，但学校若明确赋予特殊结构责任，则保留其真实差异。
- 图表、公式、列表、引文等只在本校材料确实展示且后续填充需要时增加，不因 Registry 有字段就
  凭空创建。

## 物化

在一次 `docx_edit` 的 `materialize_structure` 中，由你明确提交：结构锚点、结构字段、按文档顺序的
成员 ref 与每个成员的 Registry field ID。Tool 只验证对象存在、类型可承载、成员同属可形成结构的
物理块，并执行原子包装；它不替你挑选代表或推断层级。

若后续证据表明更好的代表块，可用新 snapshot refs 原子替换结构；先比较全局影响，避免为了局部
样式改进丢失已经证明的成员类型。

## 复核

- 结构在最终 Word 中只有一个有意的可复用实例；
- 每个成员都来自当前学校材料并有清楚角色；
- 结构外没有因样例清理遗漏而残留的重复正文接口；
- 删除具名样例后仍保留学校要求的固定标题/章节责任；
- 结构内样式、顺序、分页、表格和节边界在重新渲染后正常。
