# 集合与可选区

## 集合

Registry 的 `cardinality=many` 通常表示一个接口内部承载多条数据，不表示“每种样例类别一个槽”。
对参考文献、成果等区域：

- 先判断固定标题/地标覆盖的逻辑集合边界；
- 选择一个能代表本校真实条目版式的对象作为集合接口；
- 删除同一集合中的其他类别标签和条目实例；
- 只有新地标、独立容器或明确学校规则证明另一个独立责任时，才建立第二个接口。

若只有说明而无真实条目，说明仍证明内容责任；在合适的正文位置建立接口后清理说明，不能留下
无承载能力的固定标题。

## 致谢与附录

- “致谢”通常是固定标题；从真实正文样例保留 `acknowledgement.body` 接口，再清理其余样文。
- “附录”固定标签与学生标题同段时，保留标签，只在可变标题对象上建立 `appendix.title`；另用真实
  内容样例建立 `appendix.body`。
- 若附录没有真实内容样例，可复用说明段的正文位置作为 body，但不要把说明文字保留下来。
- 多个连续 run 共同承载一个学生值时，应形成一个逻辑接口，而不是按文字碎片制造多个槽。

## 可选区

把“最终论文是否一定出现”与“出现时如何填写”分开。学生可选并不意味着模板中应删除该能力；
学校证据未明确排除时，保留结构并提供接口。只有证据明确该条件不适用，才删除整区，同时复核
分节、分页、页眉页脚和后续页面。

任何保留区域都要责任闭合：不能只剩孤立标题、空节或没有填写承载的表格。具体字段组合来自当前
学校材料与 Registry，不是本 reference 的跨学校清单。
