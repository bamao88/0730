# 委派策略

委派是主 Agent 的可选认知工具，不是固定流水线。简单模板直接处理；只有独立分析能降低上下文
负担或提供第二视角时才委派。

## 适合委派

- 大模板可按封面/声明、摘要、正文、目录、附录等互不重叠范围并行做只读分析；
- 将结构角色分析与视觉缺陷检查分开；
- 对冲突区域请独立分析者给出证据和不确定性；
- 批量候选很多时，让 Subagent 比较某一明确范围，但不直接修改。

## Task packet

Subagent 不应依赖隐含父上下文。任务包至少给出：

- 局部目标及它对全局结果的作用；
- 精确 DOCX snapshot/hash、对象 refs 或 render ref/页码；
- 必要的学校要求、Registry 字段和已确认跨区事实；
- 允许使用的只读 Tool 与明确禁止的写入；
- 需要返回的 findings、证据、置信度、冲突、依赖、待取证项和建议操作；
- 与其他区域可能共享的字段、标题、集合或结构关系。

## 合并

主 Agent 保留全局事实、语义冲突合并和最终修改权。检查 Subagent 结论是否使用同一 snapshot、是否
把局部证据误当全局事实、是否与其他区域重复职责。多个 Subagent 的建议不是投票结果；回到原始
证据解决分歧。

避免并行修改同一 Word。当前安全默认是 Subagent 只分析，主 Agent 串行提交原子 edits；只有未来
Tool 明确支持可证明无冲突的分支合并时，才考虑并行写入。
