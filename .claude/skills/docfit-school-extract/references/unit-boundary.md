# 单元边界

## 用途

帮助 Agent 按学校功能划分模板单元，形成可覆盖、不可重叠、可交接的判断范围。单元边界用于组织
语义判断和后续复核，不是运行时状态或编辑顺序。

## 触发条件

- 模板很长，需要先拆成封面、声明、摘要、目录、正文、附录、表单等功能区。
- 一个页面、表格或分节同时承载多种学校责任。
- 页眉页脚、页码、装饰线、印章位或跨页表格影响多个功能区。
- 后续局部分析需要可复用的 unit 范围，主 Agent 必须先给出明确边界。

## 核心判断规则

- 先阅读给定源对象的完整原文与布局线索，再按学校功能划分；始终引用输入中已有的源对象身份。
- 边界可以位于对象开始、对象结束，或对象内部。内部切分应逐字保留切点前后的完整原文；两段合起来
  正好是该对象全文。空文本结构对象只在对象开始或结束处分界。
- 相邻正文功能区首尾相接，范围包含起点、不包含终点；全部正文对象与空白结构都应归入正文连续分区。
- 最后一个正文功能区的终点引用最后一条正文源对象的 `end`；不要引用后续页眉、页脚等辅助 story 条目的 `start`。
- 边界应覆盖正文中当前判断需要的真实对象，包括标题、包装段、表格外壳、字段和锚点。
- 页眉、页脚、脚注和尾注由 Harness 按原 Word story 建立独立的辅助取证范围，后续仍逐条判断，
  不并入最后一个正文 unit。不能仅凭页眉页脚出现的名称新增同名 unit；它们出现的学校名、论文类型或章节名不自动表示正文中存在同名功能区；
  只有正文、表格或页面布局中存在真实功能内容时，才能建立该 unit。
- 同一对象可以横跨两个功能区，各区拥有其中不同的连续片段，对象身份保持不变。后续按对象提交一次
  全文判断，结合它涉及的全部功能区上下文；语义片段应在已确认的功能区切点处分开。
- 跨单元依赖应显式记录，例如目录依赖最终标题树。
- 目录、图目录或表目录的固定标题与成组缓存条目共同构成一个生成区时，整体作为一个功能 unit。
  目录缓存中的条目不是正文、摘要、参考文献等真实功能区的边界；不要按缓存里列出的每个标题拆出
  同名 unit。只有在目录生成区之外看见对应的真实内容与布局时，才为真实功能区另设边界。
- 字段、生成、样式、删除和清理责任只作为后续 post-unit 判断，不作为 unit-boundary 输出要求。
- 边界证据不足时返回顶层 `needs_input`；不要把字段、样式、清理或后续 open questions 放进 unit 输出。
- 边界不清会影响最终文件时，先补可读上下文或缩小问题；不要用页码粗分掩盖职责冲突。

## 反例

- 把第一页永久等同于封面，忽略第一页还包含声明或页眉页脚规则。
- 把页眉中的“图目录”“致谢”或论文名称当成正文里真实存在的图目录、致谢或封面单元。
- 每个表格行都拆成独立单元，导致同一个表单骨架的固定责任被重复判断。
- 把目录缓存里的“摘要”“第一章”“参考文献”等条目当成真实功能区，反复切分同一个目录生成区。
- 正文样例、目录来源和目录缓存互相依赖时，只在目录单元里处理全部问题。
- 只给“第 3 页”或一段重复文字作为边界，没有引用给定源对象。

## 不负责事项

- 不定义 Harness 覆盖检查、状态推进或 payload 字段。
- 不规定工具 inspect/edit 的参数。
- 不保存当前学校的最终单元清单；每次任务必须从当前模板材料生成。
