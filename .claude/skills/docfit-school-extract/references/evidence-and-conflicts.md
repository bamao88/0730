# 证据、对象安全与冲突

## 证据层级

对实际使用的学校模板、书面要求、官方示例和用户确认记录 hash、定位、版本与适用范围。Knowledge
和本 Skill 只提供方法，不能提供某所学校的具体规则。

一项学校结论只有在来源可定位、适用对象/条件明确、必要视觉关系已查看且同范围冲突已处理时才算
确认。模板与书面要求不一致时同时保留两类证据；只有材料明确优先级或用户裁决时才消解冲突。

## 最小问题原则

先尝试以下路径：比较模板其他位置、读取要求、扩大结构 focus、查看页面、检查 Registry meaning、
委派独立只读分析。仍无法判断且两种选择会产生不同最终文档时，才询问用户；问题只包含会改变
结果的选择和证据。

## 有效样式

可见格式可能来自默认值、段落/字符样式链、主题和直接格式。判断正式/说明色由 Agent 负责；执行时
给出期望有效结果（当前模板操作支持 `color=black`、`underline=none`），不要指挥 Tool 删除某一层
OOXML。修改后以重新 inspect/render 的有效结果为准，不做无语义的全文颜色清洗。

## 结构边界

段落或 run 可能承载分节、分页、书签、批注范围、字段、脚注/尾注、图片锚点或表格包装段。选择
最小能表达语义的对象；Tool 负责保留已知边界并在不能安全修改时失败。收到
`preserved_boundaries`、`migrated_boundaries` 或其他机械回执后，仍要查看相邻结构/页面是否符合你的
语义意图。

父对象删除与子对象物化是真实冲突，拆分或重新选择；不要通过 OOXML locator、过期 ref 或绕开 Tool
强行执行。`lastRenderedPageBreak` 只是历史缓存，不能单独证明逻辑分页。
