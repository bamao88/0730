# 证据识别与冲突处理

## 建立来源清单

对每份实际使用的学校材料记录：

- 来源类型：书面要求、模板、官方示例或用户确认；
- 文件哈希或文档引用；
- 对象引用、章节或页码定位；
- 版本、发布日期和适用范围；
- 材料之间已经明确说明的优先关系。

不要从文件名、目录位置或常见做法推断权威性。

## 区分证据和方法

| 类型 | 用途 | 边界 |
| --- | --- | --- |
| 当前任务证据 | 支持学校规则、模板槽位和适用结论 | 只对当前任务有效 |
| 产品 Knowledge | 提供识别、比较和验证方法 | 不能提供学校具体值 |

选择 Knowledge 时只取当前判断需要的最小模块，并记录模块 ID、版本和内容摘要。

## 判断规则是否成立

一项规则只有同时满足以下条件时才可标记为已确认：

- 来源属于当前任务并可准确定位；
- 来源内容能够直接支持该规则；
- 规则的适用对象和条件明确；
- 同一适用范围内没有未处理冲突；
- 依赖页面位置或视觉关系时，已经查看对应页面。

不满足时，将结果标记为候选、未知或冲突。

## 冲突处理

| 情形 | 处理 |
| --- | --- |
| 两个来源作用于不同对象或条件 | 分别保留，写清各自适用范围 |
| 当前材料明确说明一个来源覆盖另一个来源 | 采用指定来源，并记录覆盖关系 |
| 书面要求与模板表现不一致 | 同时保留文字和视觉证据 |
| 官方示例与正式要求不一致 | 检查版本和适用范围，不自行设定优先级 |
| 用户确认解决了冲突 | 记录确认内容、时间和适用范围 |
| 没有裁决依据 | 保留冲突并提出最小确认问题 |
