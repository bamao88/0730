# 学校模板提取

你负责学校模板语义判断：根据当前学校模板和学校要求，判断哪些内容应保留、填写、生成、清理或人工处理。目标是干净、可填写、可复用的模板资产；不读取学生论文，不注入本次学生内容。

**完成标准是每个原文片段的责任都得到正确表达，填写后仍保留完整含义和学校要求。** 字段选对不代表范围选对：如果替换一个值后标签消失、相邻值被吞掉或同一值重复出现，分段仍然有误。

宿主系统负责原文关联、编辑安全、样式捕获、写入和交付。Agent 判断文本的含义和责任，无需选择底层 Word 对象或证明能否安全修改。工具成功和历史样本结论不能代替当前学校材料。

## 当前阶段

- 系统要求划分学校功能区（`unit-boundary`）时，只判断各区名称和起止边界，依据可见文本、页面和布局关系；先读 [单元边界](references/unit-boundary.md)。目录、图目录或表目录的成组缓存整体属于对应生成区，目录缓存条目不能作为其他功能区的边界；页眉页脚标签不能单独创建功能区或充当正文边界。此时不输出局部 parts，不提前判断字段、样式或清理。
- 系统已提供功能区和拆好的文本时，进入下述语义判断流程。文本块是阅读边界，不代表语义边界；同一块可以包含多种责任。原文关联按当前输入和输出格式处理，不推导或另建标识。

## 判断流程

1. **理解当前区域。** 结合功能区用途、相邻文本、学校要求和必要的页面线索判断。颜色、括号、空白、下划线和样式名只能提供线索，不能单独决定责任。逻辑功能区与物理分页分开看。
2. **判断需要局部分析的范围。** 已确认整体只承担固定内容或人工责任的区域，可整体判断。表单同时包含学生基础信息和记录、签名、评语时，需要分别分析；不能用整表名称覆盖局部填写责任。
3. **先读涉及的专题，再分段。** 标签、题名提示、示例值或格式说明混在一起时，先读 [模板文字分类](references/template-text-classification.md)；正文、目录、人工表单和集合按下方专题路由阅读。专题未在当前上下文中出现时，不能仅凭文件名或旧批次结论完成判断。
4. **确定完整值及其替换范围。** 使用下一节的替换检查；需要字段时先读 [Registry 与接口绑定](references/registry-interface-binding.md)，从当前词表选择含义、内容类型、数量和允许角色均匹配的字段。确认说明约束的内容；材料不足且会改变结论时返回 `needs_input`。

内容较多时可分批读取并合并判断；当前 post-unit 语义判断不委派。是否继续读取，由缺少的语义证据决定。

## part 与拆分

**part 是原文中具有一致语义责任和处理方式的连续片段。输出是在原文上分段标注。** 责任、字段或处理方式变化时拆分，没有变化就保持完整；不依赖空格、标点、段落、单元格或 run 的边界。

确定填写范围时，先看填写后的含义：

- **哪些文字仍应出现？** 固定标签、标签分隔符和正式内容留在填写范围之外。标签旁有独立值位置时，字段只绑定那个值位置。提示文字若独占最终值的位置且另无填写区，它本身也可能是待替换内容。
- **这里需要几个完整值？** 相邻的姓名、职称等独立值分别判断；词表中的一个复合字段承担的完整值不拆成重复接口。同一填写区的续行留白与另一处要求重复显示完整值的真实镜像不同，见布局专题。
- **说明约束谁，位于哪里？** 相邻的格式说明通常单独判断。若说明夹在同一个完整值的连续占位中间，且仅约束该值，按文字分类专题判断一次替换范围，避免把同一值填写两遍；这不允许合并不同字段或吞掉固定文字。
- **换成正常值后是否成立？** 检查标签仍在、相邻值各归其位、每个位置只出现所需的完整值，以及说明的有效要求仍有承载。效果不对就回到原文修正范围，不能只在 `reason` 中解释正确意图。

整条原文完整承担一种责任时，明确声明整条用途；存在不同责任时按原文分段，不能为省去分段而把固定标签、填写值和说明一并绑定。需要提交文本的 part，其 `text` 直接取自当前输入，按原文顺序完整表达该文本块，不改写、不漏字、不重复；保留原有标点及不同种类的空白，不归一化视觉相似字符。假想填写结果只帮助检查，不能加入 parts。输入明确提供的空白若由相邻标签和布局确认是值位置，可以承担填写责任；不得虚构未提供的空位，也不得仅因空白就绑定字段。

### 分段示例：原文、parts 与填写效果

上下文明确说明 `□` 只代表排版间距，原文是 `□□档案编号：S20××××`，词表提供档案编号字段：

| 原文 part | role | 字段或责任 |
| --- | --- | --- |
| `□□` | style_only | 保留前导间距要求，符号字面不进入最终内容 |
| `档案编号：` | fixed_label | 保留标签和分隔符 |
| `S20××××` | fill_slot | 档案编号 |

假设填写 `S202601`，最终可见文字为 `档案编号：S202601`，并保留前导间距。若整行都标为 fill_slot，标签会消失；若把 `□□` 并入固定标签，示意符号会被当成正式文字。这个判断依赖上下文对符号含义的明确说明，不能套用到复选框或正式名称中的同形符号。

更多成对例子见文字分类专题：相同文字作为标签或值位置、尾随或内嵌说明、独立值或复合值。

常用角色按语义选择：

| 角色 | 片段的责任 |
| --- | --- |
| `fixed_label` | 学校固定文字、标签、正式内容或应保留的学校标识图片。 |
| `fill_slot` | 该片段将被字段值整体替换，可能表现为空白、下划线、提示或示例值；按其实际填写责任判断。 |
| `manual_region` | 签名、盖章、评语或人工表单等保留给人工处理的内容。 |
| `style_only` | 样式或布局义务；说明作用内容及最终显示预期，区分真实留白与说明文字。 |
| `cleanup` | 不应进入干净模板的提示、说明或样例；其仍有用的责任需先明确。 |
| `body_structure` | 正文代表结构中的标题、段落、图表、公式等成员。 |
| `generated_content` | 目录、题注、编号等生成机制或由它接管的结果文本。 |

## 字段选择

需要字段时先读 [Registry 与接口绑定](references/registry-interface-binding.md)。以当前 `field_id_vocabulary` 为依据，匹配字段含义、内容类型、数量及允许角色；名称相似只是候选依据。先确定语义，底层接口能否安全写入由宿主处理。

只有需要字段的 `fill_slot`、`body_structure`、`generated_content` part 写 `field_id`；固定内容、人工区、样式说明和清理片段不绑定字段。词表没有语义匹配或允许用于该角色的字段时，保留已确认的文本责任，以 `needs_input` 说明需要承载什么内容、缺少什么字段。字段缺口不能成为把填写位置改判为固定文字或清理说明的理由，也不能用近似字段凑数。

同一字段在多个真实位置出现时分别判断。若以“另一位置已承载”为依据，必须确认实际输出中存在对应填写判断，且语言、用途和内容责任一致；不能把只有固定标签的位置视为已有填写接口。

## 专题路由

进入对应判断前读取相关专题，只加载当前问题需要的内容。正文、目录和集合的专门规则决定其成员或接口范围，通用文字分类不能替代这些规则。编辑安全始终由宿主负责。

| 当前问题 | 读取专题与判断重点 |
| --- | --- |
| 学校标识图片、标签、题名提示、示例值、混合说明或人工表单 | [模板文字分类](references/template-text-classification.md)：区分固定图片本体、正式文字、填写位置与说明；限定人工责任范围，参照成对分段例子。 |
| 字段含义或复合填写责任 | [Registry 与接口绑定](references/registry-interface-binding.md)：按责任选择字段，不因同段合并。 |
| 参考文献、成果、致谢、附录或条件区 | [集合与可选区](references/collections-and-optional-sections.md)：保留真实代表接口并确认适用条件；不能清理后只剩标题。 |
| 正文、章节结构、图表公式样本 | [正文代表结构](references/body-structure.md)：按文档顺序判断每个代表成员及层级并选择字段，不用目录缓存或样式名替代层级依据。 |
| 目录、图表清单、题注、编号、字段缓存 | [生成内容与目录](references/generated-content-and-toc.md)：分开固定标题、生成机制、结果样式与缓存；说明来源标题族和收录层级，不能只删除缓存或整体保留了事。 |
| 样式说明、有效格式或唯一格式样本 | [Style Contract 边界](references/style-contract-boundary.md)：判断要求及其作用内容，不能因清理丢掉唯一依据；捕获和交接由宿主完成。 |
| 模板、要求或局部证据互相矛盾 | [判断上下文与冲突](references/judgment-context-and-conflicts.md)：补充会影响结论的材料；没有依据时保留不确定性。 |
| 空白、间距符号、续行填写区或跨页布局 | [对象边界与布局安全](references/object-boundary-and-layout-safety.md)：区分真实留白、间距说明、填写位置与镜像，无需选择编辑对象。 |
| 反馈涉及写入、渲染或交付 | [完成与视觉复核边界](references/completion-and-visual-review.md)：区分学校语义缺口与宿主执行问题。 |

## 输出与反馈

按当前输出格式提交语义判断。格式和关联要求由系统提供；Skill 不另设协议。`reason` 解释判断依据，不能替代缺失的 part：声称保留、填写、清理或另有承载位置时，必须与实际 parts 一致。总结只陈述实际输出的判断。

提交前用已输出的 parts 复核整块含义：把每个 fill_slot 想象成相应字段的一个正常值，应保留的标签是否仍在、相邻值是否各归其位、说明的有效要求是否有承载。若整体效果不对，回到原文修正分段和角色；输出格式被接受不代表这项语义工作已经完成。

反馈指出文本缺失、重复、字段不匹配或判断冲突时，重读受影响文本及相邻上下文，修正对应 parts；若拆分暴露原有语义错误，一并纠正。只涉及原文字符缺失或空白表示错误时，仅修正原文字符或空白传输，保持原判断中的字段责任不变；机械反馈本身不是重新分类的依据。整体功能区与局部判断冲突时，先复核学校要求实际约束的范围。不要为了满足机械反馈而给纯人工区域增加自动填写责任或删除其填写须知，也不要用整表名称覆盖其中已被材料证明的学生基础信息填写责任。

`needs_input` 和 `open_questions` 只表达会改变当前学校语义判断的材料、字段、样式依据或适用条件缺口；属于后续阶段的问题不阻断当前阶段。写入、渲染或交付失败由宿主处理，只有反馈揭示语义错误时才修改判断，不把执行失败改写成学校材料不足。
