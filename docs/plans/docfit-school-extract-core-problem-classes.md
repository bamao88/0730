# 学校论文模板整理中的六类通用问题

> 状态：设计分析
>
> 用途：解释 `docfit-school-extract` 需要掌握的通用问题模型。本文中的学校案例用于说明问题，
> 不直接构成其他学校的格式规则，也不定义固定工作流或新的产物 Interface。

学校论文模板整理面对的并不是一组“封面怎样处理、目录怎样处理”的孤立技巧。更稳定的
抽象，是六种容易被混淆的对象关系：

| 问题 | 真正需要回答的事情 |
|---|---|
| 内容所有权 | 这部分属于谁，最终应该保留、填写、生成、删除还是人工处理？ |
| 逻辑单元与物理分页 | 内容在语义上属于哪个单元，和它当前显示在哪一页是不是一回事？ |
| 说明语义迁移 | 一段说明文字删除以后，它承载的规则有没有留下？ |
| 有效格式 | Word 最终实际采用了什么格式，而不只是界面上挂了哪个样式名？ |
| 复合生成对象 | 看起来是一段文字的东西，实际上是不是由多个相互依赖的结构共同生成的？ |
| 分层验证 | 文件结构正确，是否真的意味着目标 Word 环境中的结果正确？ |

## 1. 内容所有权

这里的“所有权”不是版权概念，而是某部分内容由谁提供、由谁控制，以及模板整理时应该
怎样处置。

学校模板中的内容通常可能承担以下角色：

- 学校固定内容：校名、声明正文、表单标签和固定标题；
- 学生填写内容：姓名、题目、学号、摘要和正文；
- 系统生成内容：目录、页码、自动编号和图表目录；
- 人工完成内容：签名、盖章、评语和审批意见；
- 模板说明内容：填写教程、格式说明和示例提示；
- 条件内容：只在某种论文类型、评审方式或提交条件下出现；
- 来源不明的内容：当前材料不足以确认其用途。

同一张声明页可能同时包含学校固定声明、学生姓名、签名区域和填写说明。它们位于同一页，
但处置方式不同：固定声明应保留，姓名应成为填写接口，签名应保留为人工区域，填写说明
可以清理，但其承载的规则必须先迁移。

常见错误是从表面特征直接推出处理动作，例如把红字全部删除、把方括号文字全部视为
占位符、把空白单元格全部视为槽位，或者把整张声明页设为可填写区域。颜色、字体、括号
和“是否为空”都只能作为识别信号之一，不能替代内容角色判断。

可复用原则是：**先识别内容角色和所有权，再决定处置方式。**

## 2. 逻辑单元与物理分页分离

逻辑单元回答“这部分内容在论文结构中承担什么职责”；物理分页回答“Word 当前把它排到
了哪一页”。二者不能等同。

例如，封面和声明通常是不同逻辑单元；一个行政表单即使跨两页，仍可能是一个逻辑单元；
两个不同表单也可能共享同一物理页。正文中的第一章和第二章通常只是同一正文结构的重复
实例，不会因为分别另页开始就自动成为两个顶层模板单元。

自然分页尤其容易造成误判。假设源文件中的顺序是：

```text
封面末尾 → 空段 A → 空段 B → 声明标题
```

在 Word 中，它可能实际呈现为：

```text
第 1 页：封面末尾 + 空段 A
第 2 页：空段 B + 声明标题
```

如果拆分模板时在两个空段之前增加显式分页，两个空段都会落到声明页。结果不是恢复源版式，
而是让声明标题多向下移动一行。

这里真正需要识别的是：

- 空段 A 属于封面页末尾；
- 空段 B 属于声明页开头；
- 分页边界只能有一个所有者；
- 新文件边界已经承担分页职责时，不能继续叠加原来的分页机制。

另一个常见错误是把模板中的多个示例章节理解为多种模板能力。若这些章节使用同一套
标题、正文、编号、图表和页眉页脚契约，它们只是同构实例。通常只需保留一个覆盖完整
正文能力的代表性结构；只有横向页面、不同栏数、不同页眉页脚等真实结构差异，才构成
独立变体。

可复用原则是：**先按内容职责确定逻辑单元，再分析分页、分节和空段怎样承载它；不能先按
物理页切割，再反推内容结构。**

## 3. 说明语义先迁移后删除

模板说明文字通常不应出现在最终论文中，但“不进入最终模板”不等于“没有需要保留的
语义”。例如：

```text
目录标题前空三行，标题后空两行。
参考文献另页开始。
此页仅实名评审时填写。
附录为可选部分。
```

如果只删除说明文字，就会同时丢失标题间距、起页要求、条件页面的适用条件和附录的可选
状态。正确处理是把说明承载的语义迁移到真正负责执行或表达它的位置：

| 说明中的语义 | 合适的承载位置 |
|---|---|
| 标题前后空行 | 段前、段后或页面布局约束 |
| 另页开始 | 分页或分节结构 |
| 必填、选填 | 槽位或区域的基数与缺失处理 |
| 特定条件下使用 | 条件区域及其适用条件 |
| 签字、盖章 | 人工处理区域 |
| 目录包含若干级标题 | 目录生成语义 |
| 装订顺序 | 模板逻辑单元顺序 |

第三方或社区模板中的说明还可能混合学校要求声称、标准建议、模板作者的实现方式、Word
操作教程和维护信息。它们不能整段照收，也不能整段删除。应先区分性质：真正的规则进入
模板结构或槽位索引；实现方式作为当前模板机制处理；纯教程和维护信息可以清理；证据不足
的学校要求不能冒充已确认事实。

可复用原则是：**允许删除说明文字之前，先确认它承载的语义已经有新的承载者。**

## 4. 有效格式，而不是样式名

Word 中一个对象最终怎样显示，不只由它的样式名称决定。简化后的格式来源关系是：

```text
文档默认值
  → 样式继承链
  → 当前命名样式
  → 段落直接格式
  → run 直接格式
  → 编号、内容控件等外层结构
```

例如，一个段落虽然使用“正文”样式，正文样式也定义为两端对齐，但段落自身带有左对齐
直接格式，最终仍会显示为左对齐。

“假居中”也是同一类问题：段落可能已经设置居中，却继续保留源示例的首行缩进或左右
缩进。属性上存在 `center`，视觉中心却依然偏移。

目录的缓存更容易掩盖问题。某份模板可能存在下面的组合：

```text
TOC 1 样式：加粗
旧目录缓存中的 run：显式取消加粗
```

旧目录看起来正常，只是缓存结果抵消了错误样式。清除缓存并由 Word 重建目录后，直接覆盖
消失，目录会重新变粗。因此“当前目录看起来正常”不能证明“目录结果样式正确”。

可复用原则是：**处理和验证面向最终生效属性，样式名只是格式来源之一。** 对样式继承、
直接覆盖、编号属性、内容控件外层格式和生成结果缓存尤其如此。

## 5. 复合生成对象原子处理

有些内容看起来像普通文字，实际上由多个相互关联的结构共同生成。目录是最典型的例子：

```text
正文标题层级
+ 标题大纲级别
+ 自动编号
+ TOC 域指令
+ TOC 1/2/3 结果样式
+ 制表位与点引导符
+ 页码结果
+ 目录缓存
+ 更新策略
```

只保留目录文字，目录不能更新；只保留 TOC 域，但标题大纲级别错误，目录内容会错；域和
标题都正确，但 TOC 样式错误，Word 更新后的版式仍会错。因此目录不是一组普通目录行，
而是一个复合生成对象。

同类对象还包括：

- 自动编号：编号定义、编号实例和段落引用共同构成结果；
- 参考文献引用：可见编号、目标书签和内部链接共同构成跳转；
- 图表编号：题注、编号域、章号和交叉引用相互关联；
- 页码：页码域、分节、起始值和页眉页脚继承共同决定结果；
- 图片：绘图对象、媒体文件和 relationship 必须闭合；
- 内容控件：可见占位、唯一标签、承载范围和外层格式共同构成填写接口。

参考文献编号可能完全不在正文字符中，而是由 Word 编号系统生成。只比较可见文字，会把
编号定义或段落编号引用的丢失静默放过。

这里的“原子处理”不是要求底层只能执行一次操作，而是要求在语义上把完整关系闭包当作
一个对象，不能只处理其中当前可见的部分。

可复用原则是：**识别复合对象的完整组成与关系，修改和验证都覆盖整个关系闭包。**

## 6. 结构完整性与目标渲染分层验证

Word 文档的验证包含不同层次，每一层只能证明自己的结论。

### 6.1 包和 XML 合法

检查 DOCX ZIP、XML 和 relationships 是否合法，图片、页眉页脚等目标部件是否存在。这一层
只能证明文件没有明显损坏。

### 6.2 内容和结构完整

检查源内容块是否全部且只分配一次，固定文字是否保留，槽位是否唯一，表格、字段、书签、
编号和媒体关系是否完整，以及是否存在遗漏、重复或未声明修改。

这类检查能够发现“页面看起来正常，但无文字结构块被遗漏”或者“全部源块都复制了一次，
却有边界空段归错单元”的问题。

### 6.3 语义行为正确

检查目录能否更新、标题是否进入正确层级、页码是否按分节连续、引用是否跳到正确目标，
以及必填、选填、条件和人工区域是否保持正确语义。这一层检查文档是否真正能够工作。

### 6.4 目标应用中的可见结果正确

检查目标环境中的页数、页首锚点、空白页、表格跨页、字体和换行、目录点引导线、公式
裁切、页眉页脚、页码以及更新全部域后的最终版式。

这些层次不能互相替代：

```text
XML 合法
  ≠ 内容完整
  ≠ 语义行为正确
  ≠ 目标 Word 环境中的版式正确
```

LibreOffice 等渲染器可以发现明显溢出和跨平台风险，但不能自动替代用户最终采用的 Word
环境裁决分页、域结果和制表位。反过来，Word 中视觉正常也不能证明隐藏关系、源结构覆盖
和包级数据一定完整。

可复用原则是：**确定性程序验证结构不变量，目标渲染验证可见结果；两类证据都要成立，
发生冲突时不能用其中一层掩盖另一层。**

## 7. 统一理解

这六类问题可以归纳为同一个处理思路：

```text
先确认对象是什么、属于谁
  → 确认它与相邻内容、逻辑单元和页面的关系
  → 删除前迁移它承载的语义
  → 修改时保护完整结构与关系
  → 以最终生效格式而非表面标签判断
  → 分别验证结构、行为和目标应用结果
```

这不是要求 Agent 按固定阶段机械执行，也不是把每个对象都写进一张强制表单。它提供的是
跨学校仍然成立的理解框架：面对目录、声明、表单、正文示例或其他未知结构时，Agent 可以
用同一组问题识别对象、控制修改边界并判断结果，而不需要为每个学校重新发明处理逻辑。

因此，`docfit-school-extract` 的主 Skill 应优先表达这些通用关系和处理原则。学校案例与
Word 机制可以放在 references 中用于解释和消歧，但不能把某次案例的具体数值或修复动作
提升为所有学校的默认规则。
