# 场景与边界案例

## 明确说明文字和唯一槽位

书面要求解释了一段模板文字用于填写指导，结构引用和相邻语义共同定位唯一对象时，
可以在工作副本中清理。最后一次编辑后重新 inspect，并在最终 hash 上建立槽位。

## 重复占位符

多个对象具有相同文字时，文字不是唯一 locator。使用结构和语义证据进一步区分；仍然
多命中时记录多个 manual 区域或一个 gap，不选择“看起来最像”的对象。

## 彩色或括号文字

颜色、括号和下划线不是删除证据。若正式材料没有解释其功能，保留为 unknown。

## 签名、盖章和手写区域

即使能够定位，也通常属于 manual。不要把它转换成普通 scalar 槽位，除非当前材料
明确允许机器填入并说明内容形态。

## 条件内容

院系、学位、语言或材料类型仍未知时，不选择性删除。把条件、候选区域和所需最小确认
写入 unresolved/manual。

## 文本框、内容控件和合并单元格

底层对象不受支持、映射不稳定或跨多个容器时，保留原内容并记录 gap。视觉上看似一个
区域不代表存在可安全编辑的单一对象。

## 模板编辑后旧索引仍存在

任何 hash 变化都使旧槽位、固定区域、页面和验证引用失效。重新生成完整 manifest；
不要只替换顶层 hash 后沿用旧 locator。

## 输入混入待转换论文

忽略其内容填充请求并说明边界。学校提取产物不得包含待转换论文正文、对象或个人信息。
