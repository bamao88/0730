# 模板清理与槽位判断

## 文字功能

| 类别 | 含义 | 产物处置 |
|---|---|---|
| `fixed_content` | 必须保留的学校标题、声明或标签 | 保留并登记固定区域 |
| `conditional_content` | 只在特定院系、学位、语言或材料类型下出现 | 已确认适用性后处理，否则 manual/unresolved |
| `slot_placeholder` | 等待后续任务填入内容的位置 | 建立槽位或 manual 区域 |
| `format_instruction` | 指导填写、排版、删除或选择的说明 | 证据充分且目标唯一时清理，并记录决定 |
| `example_value` | 官方示例中的具体姓名、题目、日期等 | 证据充分时清理；否则保留为 unknown |
| `unknown` | 现有证据无法安全分类 | 保留，不删除 |

不要依据颜色、括号、下划线、占位符外观或是否为空直接分类。结合书面要求、对象结构、
相邻语义和页面关系；需要删除时至少两个独立信号共同支持。

## 槽位建立

槽位必须同时回答：填到哪里、允许什么内容形态、允许多少项、依据是什么。

- 标量：姓名、日期、题目等单值内容。
- 段落流：摘要、正文或其他连续段落。
- 复合内容：可能包含段落、表格、图片或公式的有序对象集合。
- manual：可以定位，但自动填写风险过高。

同一占位符出现多次、签名/盖章区、跨文本框边界、低可信内容控件或无法确认的合并
单元格都不应被强行压成自动槽位。

## 清理后的重新取证

所有槽位 locator 必须在最后一次模板编辑之后生成。清理动作改变 hash 后，之前的对象
引用、页码和 locator 只保留为历史证据，不能进入冻结 manifest。

缺失样式属性保持 unresolved；本 Skill 不根据经验或 Knowledge 补造目标值。
