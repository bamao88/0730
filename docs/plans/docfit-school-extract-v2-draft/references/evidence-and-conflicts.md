# 来源证据与冲突

## 建立来源清单

对每份实际使用的材料记录来源种类、hash/ref、版本、发布日期、适用范围和当前材料
明示的优先关系。不要从文件名、目录位置、颜色或常见做法推断权威性。

产品 Knowledge 只提供识别和比较方法。学校具体值、固定文字、槽位、适用条件和清理
决定都必须回到当前任务来源。

## 规则可以进入产物的条件

一项学校规则只有在以下事实同时成立时才能标记为 confirmed：

- 来源属于当前任务且可准确定位；
- 来源内容直接支持该规则；
- 适用对象和条件明确；
- 同一适用范围没有未处理冲突；
- 依赖页面关系时，已经查看绑定当前 hash 的页面。

否则保留为 candidate、conflict 或 unresolved。candidate 不能直接变成固定内容、清理
决定或自动槽位。

## 冲突处置

| 情形 | 处置 |
|---|---|
| 来源作用于不同对象或条件 | 分别保留并写清范围 |
| 当前材料明示覆盖关系 | 采用指定来源并记录覆盖证据 |
| 书面要求与模板表现不同 | 同时保留文字和模板/页面证据 |
| 官方示例与正式要求不同 | 核对版本与适用性，不自设优先级 |
| 用户确认解决冲突 | 记录确认范围和关联证据 |
| 没有裁决依据 | 不猜测，提出最小问题或保留 unresolved |

只有能够改变固定内容、槽位或清理决定的问题才值得打断用户；其余不确定性可以作为
manual/gap 随产物发布。
