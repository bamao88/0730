# 已验证失败模式

以下模式由多份学校模板清理、Word 实机复核、逻辑单元拆分和学生稿转换复盘归纳而来。
保留的是跨任务机制，不是原学校的具体数值、页数或修复动作。

| 看似合理的捷径 | 实际失败 | 可复用结论 |
|---|---|---|
| 标题前有两个空段，所以新页可见两行空白 | 一个空段可能在上一页消耗，增加显式分节后两个空段反而都进入新页 | 页面空白由完整排版上下文和边界所有权决定，不能数 XML 空段 |
| 已经新增下一页分节，原分页结构可以全部保留 | 新旧边界叠加，产生多一行、空白首页或空白末页 | 一个边界只由一种机制承担，旧的空间填充结构要重新归属 |
| 说明文字不进入成稿，直接删除即可 | 目录、题名、后置单元的空白、顺序或必填语义随说明一起消失 | 先迁移说明承载的合同，再移除说明载体 |
| 命名样式设置正确，实际格式就正确 | 直接格式、编号或容器覆盖样式，短占位内容又掩盖了差异 | 验证最终有效格式，并用能暴露边界的内容复核 |
| 当前目录看起来正常，目录结构可以复用 | 旧缓存用直接格式抵消了错误样式，重新生成后字重、缩进或制表位失真 | 动态对象必须验证重建能力，不能把缓存外观当作合同 |
| 删除示例值后留下空白位置就算干净模板 | 人和程序都无法稳定知道应该填什么，标题也不能进入生成目录 | 每个被移除的可填实例都要转成明确接口；干净模板仍需自解释 |
| 五个示例章节说明模板应保留五章 | 同构示例被误当作论文基数，目录、页数和后续清理成本都增加 | 示例数量不决定实例数量；重复能力用容器或代表性样例表达 |
| 所有源块都分配一次，逻辑单元拆分就正确 | 无遗漏无重复的块仍可能归错单元，导致上一单元多空白页、下一单元丢页首结构 | 覆盖完整性和所有权正确性是两项独立检查 |
| 没有可见文字的块可以清理 | 空段、分节段、表后包装段和内容控件可能承担高度、分页或包结构 | 不以可见文字筛选结构；删除需要证明其职责已经消失或迁移 |
| 文件能打开且结构校验通过，模板就可交付 | 字段重建、目标渲染、关系闭包、未用媒体或个人元数据仍可能失败 | 包合法、行为可重建、可见结果和包级清洁分别验证 |

使用这些模式时不要寻找与历史案例一模一样的页面。应检查当前方案是否采用了同一种
错误假设：把一次可见结果当成稳定能力、把物理载体当成逻辑职责，或让内容在没有明确
去向时消失。
