# 整理学校论文模板

把学校材料中表达的论文结构、填写责任和文档行为，整理成一个可重复填充的 Word
文档接口。

## 输入与产物

输入可以包括学校模板 DOCX、格式要求，以及可选的官方示例或用户补充说明。来源文件
保持不变，所有修改发生在新的模板副本上。

产物固定为：

1. 冻结干净模板 DOCX；
2. 绑定该模板的槽位索引。

槽位索引描述模板提供了哪些固定结构，后续可以填入什么、怎样填入，以及哪些内容需要
生成、重复、按条件保留、人工完成或继续确认。

## 模板处理模型

不要根据颜色、空白、括号、下划线或文件中的示例数量直接决定处理方式。先确定一项
内容在可重复使用的模板中承担什么责任：

| 责任 | 处理方式 |
|---|---|
| 固定 | 保留学校拥有的文字、标识、表单骨架和结构 |
| 填充 | 建立语义明确的填写位置，并说明期望内容形态和基数 |
| 生成 | 保留可更新的生成机制及其目标样式，不把缓存结果当作固定内容 |
| 重复 | 建立可容纳可变数量内容的区域，不把示例数量冻结成论文数量 |
| 条件 | 保留适用条件和对应区域，不在条件未知时替用户取舍 |
| 人工 | 保留签字、盖章、审批等人工职责，不伪装成自动槽位 |
| 移除 | 只移除不会进入成稿的示例、教程和过程数据；先迁移其承载的规则 |
| 未决 | 保留当前无法可靠解释的内容，并在索引中说明影响 |

同一区域可以组合多种责任。例如，一个学校表单可以同时包含固定标签、填写位置、条件
区域和人工签章区；不要为了得到单一类别而破坏它。

## 完成模板整理

1. 结合全部输入材料理解模板要表达的论文结构、内容责任和适用范围。
2. 在工作副本中保留固定骨架，把示例性的具体值转换为填充、生成、重复、条件或人工
   接口。
3. 删除说明和示例之前，先把其中仍然有效的结构、格式、顺序、必填性和生成规则落实
   到模板或槽位索引中。
4. 检查清理是否改变了逻辑单元、分页关系、有效格式、生成对象或包内关系；修正的是
   模板能力，而不是当前截图。
5. 完成最后一次模板修改后，生成与最终模板绑定的槽位索引，并检查两个产物能够共同
   支撑后续论文转换。

这些步骤说明任务要完成什么，不限制 Agent 为了理解复杂模板而回看材料、比较页面或
重新检查已经处理的区域。

## 容易做错的地方

- 干净模板不是空白模板。删除具体内容之后，模板仍应自解释、可填写、可生成并保持
  学校结构。
- 可见文字不是完整的文档语义。编号、域、书签、内容控件、空段、分节、页眉页脚、
  媒体和关系都可能承担模板能力。
- 逻辑单元不等于物理页。不能先按页切分，也不能用空段数量推断页面上可见的空白；
  分页边界及其周围结构必须有明确归属。
- 样式名称不等于最终格式。命名样式、继承、直接格式、编号和容器格式共同决定实际
  结果。
- 生成结果不等于生成机制。目录、图表清单、编号和交叉引用即使当前看起来正确，也要
  在重新生成后仍然正确。
- 源内容全部出现一次，不等于归属正确。模板结构既要无遗漏、无重复，也要留在正确的
  逻辑区域中。
- 多份同构示例只证明一种模板能力，不证明最终论文必须有相同数量的实例；只为真实的
  结构或页面变体保留独立接口。
- 学校材料没有规定的样式或行为保持未决，不从历史学校、常识或示例偶然外观补造。

## 检查产物

确认冻结模板仍然保留学校固定内容、逻辑结构和可见版式；所有需要后续处理的职责都在
槽位索引中有对应表达；生成型和重复型区域没有被压成若干普通文本槽位；人工、条件和
未决区域没有被隐藏；说明、示例、学生内容和无用过程数据没有进入交付模板。

只有最终模板通过程序检查后，槽位索引才绑定该版本。模板随后发生任何修改，都需要
重新生成索引。
