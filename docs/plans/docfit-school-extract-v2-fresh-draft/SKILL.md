# 准备冻结学校模板

把当前任务的学校材料整理成一份可信的模板主干：它能够独立打开，保留学校固定内容，
去除有充分依据移除的说明或示例，并用绑定最终模板 hash 的槽位索引说明程序可以在哪里
填写什么。

你的职责不是把材料改写成一张学校规则表，而是让后续使用者不必重新解释原始材料，也
不会因为模板清理过度、定位歧义或旧证据而破坏学校模板。

## 交付内容

至少交付：

- 冻结干净模板 DOCX；
- 绑定该 DOCX 精确 hash 的槽位索引；
- 固定区域、manual 区域和无法安全表达的 gap；
- 来源、清理决定、冲突、未决项和适用范围；
- 绑定同一最终 hash 的全页视觉检查和确定性验证摘要。

这些产物只服务当前任务。不要创建学校 profile、学校目录、跨任务模板包或 Knowledge
写入请求，也不要在模板中填入学生论文内容。

## 始终遵守的原则

1. **来源文件只读。** 在新的工作副本上清理；不要覆盖模板、要求或示例原件。
2. **先理解整份模板，再改局部。** Word 模板是结构、文字和版式共同组成的文档，不是
   一组可以独立删除的字符串。
3. **删除比保留需要更强证据。** 不确定的内容保留并标为 unknown、manual 或 gap。
4. **只处理当前材料能支持的学校事实。** 通用 Knowledge 可以帮助理解概念，不能提供
   当前材料没有声明的学校字号、页边距、文案或默认样式。
5. **结构证据与视觉证据相互补充。** 能打开、能转换或结构验证成功，都不能代替查看
   当前快照的实际页面。
6. **程序硬门不能由自报替代。** hash 绑定、槽位唯一性、固定内容保护、原子发布和
   package 完整性必须由 Tool 或应用壳实际验证。

## 默认工作方法

下面是一套领域操作方法，不是固定 Tool 调用图。根据材料复杂度调整粒度、重复局部检查
或跳过不适用分支，但不要打乱由事实依赖决定的先后关系。

### 1. 先确定这次要准备什么

- 盘点当前授权的模板、书面要求、官方示例、适用性说明和用户确认。
- 记录每份来源的身份、版本、适用对象和作用：它是在声明要求、展示结果，还是仅提供
  参考外观。
- 明确本次模板要保留哪些学校页面，哪些区域需要后续填写，哪些事项只能人工完成。
- 如果缺少决定模板适用范围的关键信息，先提出最小问题；不要根据文件名或常见学校
  格式猜测。
- 对来源模板取 hash，并创建新的工作副本。后续所有修改只写工作/输出目录。

当来源身份、适用范围或冲突无法直接解释时，读取
`.claude/skills/docfit-school-extract/references/source-decisions.md`。

### 2. 建立修改前的模板全貌

- 检查整份模板的节、段落、表格、合并单元格、图片、文本框、内容控件、书签、域、
  页眉页脚、分页边界、编号和样式覆盖。
- 获取修改前的页面证据，浏览全部页面，并对缩略图无法辨认的关键区域查看放大图。
- 建立一张面向工作的模板地图：每个逻辑页面或区域的用途、可见内容、主要结构、可能
  的固定边界以及尚未理解的对象。
- 特别留意空段落、表格行高、隐藏占位、分节符和空内容控件；它们可能在控制版式，
  不能因为“没有正文”就删除。

遇到复杂 Word 结构或需要确定观察范围时，读取
`.claude/skills/docfit-school-extract/references/template-analysis-and-slot-design.md`。

### 3. 按功能给内容和区域分类

对每个可能改变或填写的区域，选择最符合当前证据的类别：

- **fixed**：学校要求永久保留的文字、图形、表单外壳或版式结构；
- **slot**：后续可由程序放入明确类型内容的区域；
- **guidance/example**：只帮助作者理解填写方式、且有充分证据允许从干净模板移除的
  说明或示例值；
- **conditional**：是否保留或填写取决于当前仍未确定的条件；
- **manual**：签名、盖章、手写或无法安全自动填写的区域；
- **unknown/gap**：现有材料不足以解释，或当前 Tool 无法可靠表达的内容。

按功能分类，不要按颜色、括号、字体、页码或“看起来像占位符”分类。同一对象可能既
承载说明文字又控制表格尺寸；可以清空其文字，不代表可以删除其容器。

### 4. 形成清理与槽位方案

- 为每个拟变更区域写清预期结果：完整保留、只移除文字、保留空壳、变成自动槽位、
  变成 manual，还是暂不处理。
- 说明决定来自哪些当前来源和观察事实；冲突没有裁决依据时，不选择一个结果冒充
  已确认规则。
- 为自动槽位确定语义用途、允许内容种类、基数、固定边界和定位信号。一个“姓名”
  文本出现多次，不等于已经识别出哪个是作者姓名槽位。
- 预想清理对分页、表格几何、页眉页脚继承、域结果和后续填写空间的影响，优先选择
  破坏最小的修改。
- 只在用户回答能够改变产物时询问；能够安全保留并暴露为 manual/gap 的事项不必用
  大量问题阻断整个任务。

复杂分类、槽位设计和固定边界示例见
`.claude/skills/docfit-school-extract/references/template-analysis-and-slot-design.md`。

### 5. 在工作副本上谨慎实施

- 行动前要求至少两个相互独立的信号共同指向当前快照中的唯一目标。结构引用、对象
  指纹、相邻语义和来源说明可以相互印证；页码、bbox、颜色或一次近似文字命中只能
  缩小候选范围。
- 把同一局部、语义上不可分割的修改作为小范围原子编辑提交，并带上当前快照的前置
  条件。不要一次混入彼此无关的整份模板修改。
- 每次写入后重新检查受影响结构和页面。写入产生新 hash 后，旧对象引用和旧页面证据
  只能说明历史状态，不能继续驱动当前修改。
- 零命中、多命中、前置条件失效或视觉结果意外时，停止这一项，重新观察并缩小范围；
  不要放宽匹配条件直到“碰巧成功”。
- 使用 DocFit Tool 修改 DOCX，不直接编辑 OOXML，也不通过 Bash/Write 绕过文档操作和
  验证合同。

需要选择 Tool 或根据错误语义恢复时，读取
`.claude/skills/docfit-school-extract/references/tools-and-recovery.md`。

### 6. 把候选重新当作一份完整模板检查

- 清理完成后重新 inspect 整份工作副本，而不是只复查改过的对象。
- 重新查看全部页面，对照修改前基线确认固定文字、学校标识、表单外壳、分页、节、
  页眉页脚和填写空间没有意外变化。
- 检查说明文字或示例是否仍有遗漏，也检查是否把本应保留的标签、空容器或条件页面
  误删。
- 如果发现问题，返回必要的局部步骤继续处理；不要因为已经做过一次“全页检查”就把
  后续修改后的旧检查当作有效证据。

重复占位符、文本框、合并单元格、签章区、条件页面等长尾情况见
`.claude/skills/docfit-school-extract/references/complex-template-cases.md`。

### 7. 在最后一次写入之后建立冻结产物

- 确认不再写入模板后，重新取得最终 DOCX hash。
- 只在这个最终快照上建立 slot locator、固定区域指纹、manual 区域和 gap。任何后续
  DOCX 写入都会使索引、视觉证据和验证结论失效。
- 每个自动槽位必须在最终快照中唯一定位，并声明期望内容种类与基数；不能可靠定位的
  区域降级为 manual 或 gap。
- 使用同一最终 hash 完成全页视觉检查和确定性验证，再由 Tool/应用壳原子发布完整
  package。验证失败时不发布半成品冒充冻结产物。

实际组织和发布产物前，读取
`.claude/skills/docfit-school-extract/references/artifact-contract.md`。

## 两个不可放宽的判断阈值

### 目标足够唯一才行动

至少两个独立信号共同支持，并且当前快照中只有一个候选，才可以编辑或建立自动槽位。
“有一个看起来很像的命中”不等于唯一定位。

### 内容消失需要更强证据

删除说明、示例、页面或结构，以及决定某项不进入冻结模板，都需要比保留更强的证据。
没有观察到用途不等于已经证明它无用；无法确认时保留并暴露不确定性。

## Tool 使用原则

| 目的 | 使用 |
|---|---|
| 观察当前 DOCX 的结构、样式、对象和 hash | `mcp__docfit__docx_inspect` |
| 在工作副本上提交有前置条件的修改 | `mcp__docfit__docx_edit` |
| 生成修改前、编辑反馈或最终候选页面证据 | `mcp__docfit__docx_render` |
| 查看已有 render 的整页、裁剪或对比图片 | `mcp__docfit__docx_visual_review` |
| 从来源和最终候选独立核对文档与产物合同 | `mcp__docfit__docx_validate` |

这张表是能力说明，不是调用次数或固定顺序。根据风险选择范围，但修改前必须有当前
观察，最后一次写入后必须重新取证，冻结结论必须绑定最终 hash。

## 可选委派

材料量大、局部证据密集或需要独立复核时，可以把边界清楚的只读分析交给
`docfit-unit-analyst`。主 Agent 仍负责跨区域合并、编辑、渲染、验证、用户询问和最终
决定。准备任务包前读取
`.claude/skills/docfit-school-extract/references/delegation.md`。

## 结束状态

只有程序已经验证模板可打开、索引绑定最终 hash、自动槽位唯一、固定内容受保护、全页
视觉证据对应最终快照且 package 完整时，才报告 `complete`。

- 需要用户提供会改变模板语义或适用范围的信息时，报告 `needs_input` 并只问最小问题。
- 当前 Tool/App 无法验证必要硬门时，报告 `blocked`，列出 capability gap，不把 Agent
  自己整理的 DOCX 或槽位表称为冻结产物。

## 最终回复

说明状态、冻结模板和 manifest 的位置、最终 hash、槽位/fixed/manual/gap 数量、采用的
来源、重要清理决定、视觉与确定性验证结果，以及仍需用户确认或当前能力无法证明的
事项。不要复制材料正文，也不要把当前任务产物描述成已经发布的跨任务学校资产。
