# 目录与生成内容

## 核心模型

目录、题注和交叉引用由固定外壳、字段指令、目标对象、结果样式、内部关系和当前显示缓存共同组成。可见缓存只是一次历史结果，不是内容真值。

## 目录整理

1. 保留“目录”标题、真实 TOC 字段和学校的 TOC 分级样式。
2. 先完成当前学校应进入目录的最终标题树，再选择实际标题对象及其 1–3 级目录层级。若当前区域先于摘要和正文出现，先保留目录机制并继续导航；不要拿目录缓存行代替尚未确认的最终标题对象，也不要提前刷新。
3. 最终标题树稳定后，对目录标题或承载完整字段边界的目录对象提交一次 `refresh_toc`；不要逐行清空或删除缓存段落。
4. 目录样例颜色/下划线不属于正式样式时，在同一操作请求：

   ```json
   {"effective_format": {"color": "black", "underline": "none"}}
   ```

   Tool 会展开段落样式、字符样式（包括 `Hyperlink`）、直接格式和主题来源，写入覆盖并回读有效结果。只检查没有直接 `w:color` 不足以证明成功。
5. `refresh_needed`、样例标记数量和缺失的已物化标题类型是机械反馈。候选标题仍由 Agent 决定是否进入当前学校目录。
6. 修改后检查非空缓存、层级缩进、点引导线和标题范围。字段更新会改变真实页码，当前代表缓存的页码只是占位证据。

## Word 原生验证

LibreOffice 图像只用于近似风险扫描，不能证明 Microsoft Word 更新域后的精确格式。最终验收应在 Word 中：

1. 打开精确最终版本；
2. 只更新目标 TOC 域；
3. 检查 1–3 级缩进、点引导线、页码、黑色和无下划线；
4. 保存、关闭并重新打开，再确认结果没有被字段更新或字符样式恢复。

不要用全局字段更新误伤其他字段，也不要把 Word 自动化引入产品核心依赖。

## 其他生成对象

清理题注、编号、书签或交叉引用附近内容时，先读[对象安全](object-safety.md)。不要把样例中的可见编号当成生成规则，也不要在只看到文字时删除字段边界或关系目标。
