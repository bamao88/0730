# 目录与其他生成内容

## 何时读

只在当前对象涉及目录/图目录/表目录、点引导线、页码、题注编号、书签、交叉引用，或 Word 字段的当前显示文字时读。

## 核心模型

生成对象由以下职责组成：

- 学校固定外壳（例如“目  录”标题、位置和页面样式）；
- 字段指令或生成规则；
- 生成所依赖的标题、题注或目标对象；
- 当前显示缓存；
- 结果段落样式和内部关系。

可见缓存只是一次历史生成结果，不是可复用的内容真值。

## 目录整理

目录是一个复合生成对象，不能按可见行逐个删除：

1. 保留“目  录”等固定外壳、真实 TOC 字段和 `TOC 1/2/3` 结果样式。
2. 先完成最终模板中的标题结构。代表内容通常应包含中文摘要、英文摘要、一个能展示所需目录深度的
   正文章节，以及参考文献、附录、成果、致谢等当前学校模板实际要求进入目录的标题。
3. 找到承载 TOC begin/instruction/separate 的目录对象，对它调用一次 `refresh_toc`；`entries` 只提交
   最终模板中应展示的实际标题对象及其 1–3 级层级。
4. Tool 会复用学校已有的各级 TOC 段落样式，重建非空代表缓存，保留 live TOC 域，并设置 Word 首次
   打开时更新字段。它会把样例行中分散于样式链、段落直接格式和 run 直接格式的有效字体、字号、
   字重、制表位、缩进和行距固化回 `TOC 1/2/3`，避免 Word 更新字段后恢复错误样式。旧样例条目、
   `XXX`、`XX` 和旧页码不会继续作为内容真值。若你已判断红蓝色只用于样例说明，在同一
   `refresh_toc` 操作中提交 `clear_direct_format: ["color"]`。
5. 检查返回图：目录不为空，条目层级、缩进、点引导线和标题范围符合当前模板。
6. 目录通常在最终标题树之前出现，不能只靠同一会话记住稍后回来处理。每次 `open`/`next` 返回的
   `checkpoint_summary.toc.sample_marker_count` 是持久反馈；只要大于 0，就说明 live TOC 的可见缓存
   仍含 `XXX`、`XX` 或“第 X 章”等样例，完成标题结构后必须执行 `refresh_toc`，不能发布。
7. 所有视觉区域完成后，Tool 会在 `pending_generated_content` 中同时给出 TOC 根对象、它的局部裁剪图
   和最多 16 个最终标题候选。候选只按对象样式和固定标题信号收集，不代表 Tool 已决定目录语义；你
   负责选择条目并分配 1–3 级。直接用这些短引用完成一次 `refresh_toc`，不要再跨短会话逐个搜索。
8. `toc.missing_body_heading_types` 是机械比对结果：正文中已经由你分类和物化的
   `body.heading.level1/2/3` 若没有出现在目录缓存，就会列在这里，并同时出现在
   `required_body_heading_candidates`。这些不是新语义猜测，必须按对应 level 加入代表目录，以明确本校
   正文目录展示到哪一级；完成后 `toc.refresh_needed` 应为 false。
9. 源目录与正文共同证明的具名首章/末章（例如文献综述、结论与展望）应同时存在于正文标题位置和
   代表目录。不要因为中间章节可重复，就把这些学校特定地标一并删除；`第 X 章` 本身可以是合法的
   章节号占位，只有 `XXX`、`XX` 等残留样例标记才会触发样例缓存反馈。

不要对目录结果行调用 `clear_content`，不要把目录转成静态文字，也不要整段删除字段边界。目录内容
必须来自最终标题对象，而不是 Agent 手写的一份脱离文档的字符串列表。

## 样式和验证限制

旧目录缓存可能用 run 直接格式暂时遮住错误的 `TOC 1/2/3` 样式。Tool 会以既有分级样式重建代表
缓存并标记真实域更新，但 LibreOffice 截图不能证明 Microsoft Word 原生更新后的精确分页。

因此：

- 必须保留域机制，并让缓存与最终标题树一致而非留空；
- 不用 LibreOffice 截图宣称 Word 原生更新后的字重、缩进、点引导线和页码已得到证明；
- 最终候选在 Word 中打开后应更新这个 TOC 域；不要用全局字段更新误伤其他字段。

## 题注、编号和交叉引用

当前清理目标若与图、表、公式、书签或内部链接共存，先读取 `boundaries-and-object-safety.md`。不把学生稿或样例中的可见编号直接当成生成规则，
也不在只看到文字时删除其书签、字段或关系目标。

## 修改后看什么

- 固定标题与生成字段仍存在；
- 代表缓存非空、层级正确且旧缓存不再污染最终模板；
- 清理没有孤立字段边界、书签或超链接；
- 只回看当前修改区域，不为了覆盖率进行全文逐页复核。
