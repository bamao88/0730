# 正文代表结构

## 核心模型

正文是当前学校展示的一套可重复能力，不是复制所有样例章，也不是一个大字符串槽。Agent 根据当前学校实际出现的对象，选择一个有代表性的章节或局部块：

```text
body.chapters
└── 当前学校实际展示的成员
    ├── 标题层级（可能是一层、三层或更多）
    ├── 普通正文、列表、引文
    ├── 图、表、公式与题注
    └── 当前学校确有的其他独特对象
```

代码内置语义对象类型，但它们不是固定语法。Tool 只验证对象类型能否承载所选语义、成员顺序和 Word 结构；`materialized_members`、样式签名和风险提示也不代表“完整”。

## 选择代表单元

1. 从当前正文证据识别学校真正展示的标题深度和对象类型，不因 Registry 存在某个类型而凭空添加。
2. 对每种实际不同的样式至少保留一个代表；同类型同样式的其他章节实例可以在代表结构建立后清理。代表结构提交前，不得删除尚未纳入结构的唯一对象类型。
3. 成员按文档物理顺序提交，但不要求相邻。不要把夹在中间的写作说明或冗余样例错误映射为成员。
4. `document_order`、重复样式和 `structural_risks` 是物理事实。若跨度中出现相似章标题，由你根据标题文字、目录和局部关系判断是否跨章；Tool 不再据样式直接阻断。
5. 首次提交前先用当前局部证据及一次有目标的搜索确认普通中间章是否另有通用章标题。若模板同时存在固定首章/末章和 `第X章（正文标题）` 一类通用中间章，优先以后者及其后续成员建立普通 `body.chapters`；不要从固定地标下截取 H2/H3/正文后就提前提交一个缺 H1 的结构。
6. 后续发现更能代表当前学校的块时，再次物化会替换旧结构。替换前确认新块没有丢失已证明的独特对象能力；若无法同时重新定位既有独特成员，先保留新证据，不得删除它或用不完整结构覆盖旧结构。

通用中间章是一个需要先收集再修改的局部单元。看到其 H1 后，先向后定位同一章实际展示的
H2/H3/正文等成员；在全部引用就绪前，不对这些成员执行独立 `materialize_slot` 或删除。一次
`materialize_structure` 应直接产生唯一 `body.chapters`。固定首章、固定末章或其他具名地标的
标题不能跨章拼进这个结构；它们只保留地标及各自需要的内容接口。

更晚的通用中间章地标一出现，固定首章/末章的延续作用域立即结束。固定章节中已物化的独立
`body.paragraph` 不能抵扣通用章的正文责任，也不能成为删除通用章样例的理由。Registry 已声明
`body.heading.*` 的父类型为 `body.chapters`，因此这些标题只能作为 `materialize_structure` 成员
物化，不能先建立独立槽。当前工作项只提供 H1/H2 等部分成员时，先建立部分结构是合法的；后续
发现 H3、正文或其他本校真实成员时再扩展同一个结构。这个父子约束不等于要求固定标题深度。

把“已见正文类型”作为当前任务内的短账本。每次遇到 `body-structure` 区域，都要把当前对象的
编号形态、视觉层级、段落样式和邻接说明与 checkpoint 中已经物化的 `body.*` 成员比较：

- `第X章（正文标题）` 是普通章标题证据。若它下面依次展示 `1 材料与方法` 与 `1.1 材料`，
  三者的相对层级分别是 `body.heading.level1`、`body.heading.level2`、
  `body.heading.level3`；即使原模板把后两者设成同一个 Word 样式，也不能合并为同一语义类型。
  看到这组编号后，必须把 H1/H2/H3 记入短账本并在同一个普通章块内完成结构，不能在 H2
  创建后把仍未归属结构的 `1.1` 当成冗余样例删除；
- 当前说明明确写出后面还会展示一级节、二级节、正文、图表或公式时，不要把刚看到的 H1 +
  正文误当成最终完整结构。可以先提交部分结构继续导航，但后续每发现一种实际成员，必须先
  扩展唯一 `body.chapters`，再删除同类冗余样例；
- `checkpoint_summary.materialized_fields` 只说明已经物化了什么，不证明结构完整。若短账本里有
  当前学校已见、但 checkpoint 尚未包含的正文类型，不能进入目录收尾或发布。
- `checkpoint_summary.materialized_structure_members.body.chapters` 是当前结构实际成员事实表。当前
  crop 展示的类型不在该表中时，它是新增能力，绝不是冗余样例。只需提交包含新增成员的
  `materialize_structure`；Tool 会自动携带现有结构的全部成员，不要求 Agent 重新定位和重报旧成员。
- 固定首章/末章的后续 crop 还必须读取
  `checkpoint_summary.materialized_field_locations.body.paragraph`；只有
  `nearest_preceding_heading.text` 与当前固定章节标题一致的 location 才能证明该章已有正文接口。
  全局 `body.paragraph` 数量不能表达章节归属。

扩展已有结构时，只把当前新发现的标题/正文成员提交给同一个 `body.chapters`。Tool 会按物理顺序
自动携带并复用已有成员、替换旧 wrapper，且仍只保留唯一结构。不要因为旧引用失效就删除新层级，
也不要重新建立第二套独立 slot。

一旦搜索已确认存在通用中间章，处理更早出现的固定首章样例时可以保留固定标题和一个正文填写接口，但应清理其中只用于演示层级的 H2/H3 等标题样例。不得为了立即处理当前区域，先把这些 `body.heading.level*` 做成独立 `materialize_slot`；标题能力应延后到通用中间章，并在一次 `materialize_structure` 中归属 `body.chapters`。

物理分页或区域上限可能把同一固定章节拆成多个工作项。只要当前工作项的
`preceding_landmarks` 最近仍指向该固定首章/末章，且当前 crop 没有出现更晚的通用中间章地标，
作用域就没有结束：孤立的 H2/H3/正文占位样例仍是这个固定章节的演示残余。应清理多余样例，
不得仅凭 `××` 占位文本、`标题2`/`标题3` 样式或 Registry 召回结果把它称为通用中间章成员。
若 checkpoint 的 scoped location 最近标题与这个固定章节一致，它才证明前导 crop 已建立唯一章节
正文接口；后续孤立正文样例全部删除，不得重复物化。仅有全局 `body.paragraph >= 1` 不足以作此判断。
此例外不适用于摘要页、封面或另一个逻辑章节的位置。

## 固定章节地标

首章文献综述、末章结论与展望等具名章节，若由当前模板和目录共同证明为固定地标，应保留它们的标题与页面位置。它们不等于可重复的普通中间章节，也不应被拿来机械满足某个固定 H1/H2/H3 清单。

保留地标不等于保留其写作说明和样文。像 `第一章 文献综述（章标题……）` 这样的标题应保留
`第一章 文献综述`，只移除尾部格式注释；标题本身不得物化为独立 `body.heading.level1`。
若该章仍需要学生内容，应选择标题下一个真实正文样式的样例物化为独立 `body.paragraph` 接口，
再删除其余说明、示例正文以及只用于演示层级的蓝色/彩色小标题。当前 crop 中每个可见兄弟对象
都要在同一决定中被明确保留、清理或物化，不能因为正文接口已经建立就漏掉彩色示例小标题。

每个新出现的固定首章或末章都要在自己的起始 crop 建立一个正文接口；来自其他章节的全局
`body.paragraph` 计数不能满足这个新章节。只有该固定章节自己的正文接口已经建立，后续同作用域
样例才是可删除的冗余演示。

固定章节标题与其第一段正文样例在同一当前 crop 中出现时，必须在这个决定中物化该样例。不能用
全局 `body.paragraph` 数量，也不能凭空声称“前导 crop 已经建立”而删除它；只有在当前对象证据中
能看到位于这个确切固定章节地标下的 `body.paragraph` 槽，才证明本章接口已经存在。

标题含暂定章号（例如“第X章 结论与展望”）时，固定名称仍然是地标。没有只覆盖动态章号的精确 Registry 字段和局部对象边界时，保留整段，不得用通用 `body.heading.level*` 槽替换整段。

`第X章（正文标题）`、`第X章 XXX` 等没有固定章节名称的标题不是地标；其中 `X` 或 `XXX` 正是学生内容入口。当前模板用它展示普通章标题样式时，应把整段物化为 `body.heading.level1`，并与该普通章后实际出现的标题和正文成员共同纳入代表结构。

## 提交与复核

- 外层通常为 `body.chapters`；成员只提交对象引用、Agent 判断的 `body.*` 类型和必要有效格式。
- 当前证据已经显示两个或更多正文成员类型共同构成可重复单元时，使用一次 `materialize_structure`；不要把标题与正文成员分别提交为互不相关的 `materialize_slot`。
- 当前学校已证明通用中间章及多个正文成员类型时，最终所有 `body.heading.level*` 槽都必须列在唯一的 `body.chapters` 结构成员中；不能同时遗留固定首章/末章里的独立标题槽。固定地标下允许独立存在的是该地标自己的正文内容接口，而不是另一套标题层级能力。
- 收尾时若 `checkpoint_summary.materialized_structures` 为空，但短账本已经确认通用中间章及多个正文成员，任务尚未完成；若 `materialized_fields` 中出现独立的 `body.heading.level*`，先把同一普通章的成员提升进唯一结构并清理跨章重复，不进入目录或最终视觉检查。
- `materialize_structure.object_ref` 必须引用其中一个成员，`members` 按物理顺序列出；固定章节地标下的单个内容接口不等同于这个可重复结构。
- 物理顺序和语义重复顺序必须同时成立。若 Tool 返回 `body_structure_not_in_document_order`，不得只把跨章对象数组重新排序后重试；应重新定位一个从通用章标题向后展开的同一普通章节块，再按其真实前向顺序提交。
- 代表对象的字体、字号、缩进、间距与容器应保留。
- 分节边界不应被无意吸入重复结构；Tool 返回风险或边界事实时结合页面关系判断。
- 修改后检查成员是否仍按预期显示，图表公式没有被压成字符串，重复样例清理没有破坏分页和目录依赖。
