# 正文代表结构

## 何时读

只在当前区域出现多个重复章节，或一个章节内出现各级标题、正文、列表、引文、图表、公式等不同
样式，需要提取正文能力时读。不要在封面、摘要或单个普通槽任务中加载。

## 核心模型

正文是“可重复章节结构”，不是所有样例章节的集合，也不是一个无结构的大文本槽：

```text
body.chapters（可重复）
└── 当前学校的一个代表章节
    ├── body.heading.level1
    ├── body.paragraph
    ├── body.heading.level2
    ├── body.paragraph
    ├── body.heading.level3
    ├── body.paragraph
    └── 当前章节确实出现的其他独特对象类型
```

代码内置的是语义对象类型体系；Registry 查询当前对象时会返回相应类型事实。你根据图片、文字、
大纲层级、样式和邻接关系，把当前 Word 对象映射成其中一种类型。Tool 不替你判断语义，只验证目标
是不是能承载该类型，并提取该学校对象的真实样式。

## 选择代表单元

1. 不要在第一次只看到 H2/H3 和一个正文段落时立刻建立结构。继续使用 `next` 查看紧邻的正文区域，
   找到一个能覆盖当前学校常用正文层级和对象类型的连续章节。
2. 保留每种实际不同的对象样式至少一个：例如 H1、H1 后正文、H2、H2 后正文、H3、H3 后正文。
3. 同类型、同样式的其他章节是内容实例，不要全部留下；代表单元完成后批量删除重复样例。
4. 若图、表、公式、长引文或横向分节有独特学校样式，只在当前代表区域确实存在时纳入；不要为了
   Registry 中存在某类型而凭空添加。
5. 成员必须按文档顺序连续提交。若中间对象属于代表章节，也要纳入；若不属于，重新选择更准确的
   边界。
6. “各章标题为三号黑体”“正文首行缩进 2 字符”“图表应有中英文标题”等说明句是帮助你识别
   后续样例对象的知识，不是学生正文。即使它们与样例相邻或使用红蓝色，也不要把说明句映射成
   `body.paragraph`；应删除说明对象，并从真正展示该样式的章节骨架中提取成员。
7. 若 checkpoint 已有 `body.chapters`，但当前连续章节覆盖了更多真实层级或对象类型，可以再次调用
   `materialize_structure`。Tool 会原子删除旧代表结构并用当前成员替换；是否更好由你判断。
8. 每次准备删除新的正文标题、图表、公式或其他独特样例前，对照
   `checkpoint_summary.materialized_fields`。若对应语义类型尚不存在，它不是可直接丢弃的重复项；保留
   该对象，并继续到包含它的完整连续章节后替换代表结构。

## 一次直接物化

使用一次 `materialize_structure`：

- 外层 `field_id` 为 `body.chapters`；
- `members` 中每个对象只提交其 `object_ref` 和判断好的 `body.*` 语义 `field_id`；
- 颜色只表示样例/说明时，可在相应成员上加 `clear_direct_format: ["color"]`；
- Tool 建立外层可重复结构和内部成员槽，保留原段落样式、字体、字号、缩进、间距、分页以及对象容器；
- 同一 checkpoint 已有 `body.chapters` 时，本次操作替换旧代表结构，不会并存两份；
- 可见占位只用 `【】` 区分，不增加灰色占位协议。

不写 YAML，不生成中间 projection，不逐个调用 compiler，也不把 Registry 中全部正文类型列成待办。

## 修改后看什么

- 只留下一个结构完整的代表章节，而不是多个内容重复章节；
- H1/H2/H3 与各自正文都仍可见且样式有区别；
- 示例文字已经变成括号占位，红蓝说明色已按你的明确决定处理；
- 图表公式等复合对象没有被压成字符串；
- 删除其他章节后，没有破坏分节、分页、书签或目录依赖。
