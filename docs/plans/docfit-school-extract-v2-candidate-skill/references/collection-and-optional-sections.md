# 集合与可选区域

## 集合接口

参考文献、成果等字段通常是集合承载接口，不是“每种条目类型一个槽”。选择一个能代表学校实际条目格式的对象作为 `references.entries` 或 `achievements.entries`，再删除同一区域其余类别和条目样例。

若学校只给出固定集合标题和一段红蓝说明、没有真实条目样例，该说明段仍证明了学生内容责任：删除说明文字，但复用其段落版式建立集合槽。不能因为缺少样例条目就保留集合标题却不提供 `references.entries` 或 `achievements.entries`。

已有一个集合槽后，后续“科技报告”“期刊”“学位论文”等不同样例仍是待清理实例，除非当前学校明确展示了另一个结构上不同且必须独立填写的集合责任。

## 附录

“附录”通常是固定标签；“名称”或其后标题位置由学生填写。标签和值同段时，必须先 focus 标题段并选择只承载可变名称的 run 物化为 `appendix.title`，不得把包含固定“附录”标签的整段物化。若局部对象中无法分离固定标签和值，先保留该段并继续定位更精确对象，不能用整段槽擦除固定标签。另从真实附录内容样例建立 `appendix.body`，再清理说明和样文。

若附录区只有“可放原始数据、程序、图表”等说明段而没有真实附录样文，复用该说明段的正文位置建立 `appendix.body`，并把说明色归一为正式黑色。`appendix.title` 只承载标题，不能代替附录内容接口。

## 可选区域

把两个问题分开：

1. 最终论文是否一定出现该区域；
2. 区域出现时由谁、通过什么接口填写。

只知道“学生可选填写”时，保留学校结构并提供填写接口；不要擅自删除整页。只有学校证据明确该条件在本模板中不应出现时，才考虑删除完整区域，并同时检查分页、分节、页眉页脚和后续页面关系。

清理后不能只剩孤立标题、空白节或没有承载职责的表格。发布前逐一核对本校实际保留的固定可选区：保留附录标题就必须有 `appendix.title` 和 `appendix.body`；保留成果目录标题就必须有 `achievements.entries`。这是当前对象责任的配对检查，不是要求所有学校凭空增加这些区域。
