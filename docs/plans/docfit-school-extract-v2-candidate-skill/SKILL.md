# 学校模板整理

目标是得到一份干净、可填写、保留学校固定内容与版式责任的 Word 模板。

应用负责选择当前工作项、推进流程、限制重试、组织最终逐页检查和发布。你只处理当前收到的
角色任务，不自行遍历文档，不判断整项任务是否结束，也不管理版本、游标、路径或中间产物。

## 角色边界

你只会处于以下一种角色：

- **局部语义判断**：查看当前对象、父对象、必要邻接对象和修改后的局部图片，决定保留、清理、
  物化填写接口或修正格式。此时禁止主动逐页巡检。
- **最终视觉检查**：查看应用给出的原生全页 PNG，只判断渲染缺陷并逐页给出明确结论。此时不
  重新做模板语义提取。

局部图用于回答“这个对象是什么、应该怎样处理”；全页图用于回答“全部内容完成后的 Word 是否
渲染正常”。两者证据目的不同，不得相互替代。

## 局部语义判断

优先保留学校身份和制度责任：校名、固定封面标签、声明原文、学校表格、页眉页脚、节设置、
目录机制、固定区域标题和样式骨架。

优先清理会污染学生成稿的内容：

- 操作说明、编写提示、格式讲解和括号指导文字；
- 示例题目、摘要、关键词、章节、图表、公式和参考文献；
- 只用于展示格式的目录缓存样例、多余占位词和学生实例；
- 清理后没有职责的孤立标题、空容器或异常空白。

一个对象看起来像标题，不代表它是填写槽。先判断它是固定标签、结构标题、学生值、示例还是
生成内容。标签与值混在同段时选择最小可编辑对象；不要按位置、空白或 Word 样式名猜语义。

### 填写责任

每个需要学生填写的视觉位置，清理后都必须保留固定文字或真实填写/生成接口：

- 摘要页先逐项落实当前可见的论文题目、固定摘要标题、摘要正文和关键词，再删除说明或样例；
- 同一字段在封面已有填写位置，不代表摘要页等其他视觉位置可以被删除；
- 保留固定“致谢”标题时，必须保留 `acknowledgement.body` 内容接口；
- 保留附录、成果、参考文献等集合标题时，必须有与本校实际结构配对的内容接口；
- 固定“文献综述”“结论与展望”等具名地标不是普通学生章标题，不应为了统一而抹掉。

字段 ID 只能从当前工作项提供的 Registry 候选中选择。候选不足时请求当前对象所需的字段上下文；
不得根据命名习惯创造字段，也不得把 Registry 当成整篇任务清单。

### 正文结构

学校模板已经展示通用中间章及多个可重复成员时，应把实际出现的标题、正文、列表、图表或公式
归入一个 `body.chapters` 结构，而不是建立互不相关的独立槽。`第X章（正文标题）` 是通用章标题
的直接证据，不得先遗漏它建立结构，再把它当说明删除。

只纳入当前学校实际证明存在的成员，不为了满足示例凭空补 H1/H2/H3。固定首章、末章或具名章节
中的样例不能拼成普通中间章结构。更完整的判断规则见
[正文代表结构](references/body-structure.md)。

### 修改后确认

应用执行修改后，实际查看返回的局部图片和机械回执，确认：

- 应保留的固定标签、容器、边框、分页和样式责任仍在；
- 说明或样例确实消失，且没有误删对应的填写位置；
- 新填写接口位于正确视觉位置，没有不必要的格式覆盖；
- 复合对象、书签、字段、表格、图片和节边界没有被破坏。

局部结果不正确时要求重做当前决定，不要接受后寄希望于最终逐页检查补救。

## 按需知识

只在当前局部问题命中时读取对应短卡；不要预先读取全部参考，也不要把卡片案例当作所有学校的
固定清单：

| 当前问题 | 读取 |
|---|---|
| 颜色、下划线、主题色、字符样式或有效格式来源 | [有效样式](references/effective-style.md) |
| 摘要/章节另起页、删除后空白页或重复分页 | [逻辑页起点](references/logical-page-starts.md) |
| 正文标题、段落、列表、图表、公式等可复用体系 | [正文代表结构](references/body-structure.md) |
| 目录、点引导线、页码、题注、字段缓存或交叉引用 | [生成内容](references/generated-content.md) |
| 参考文献、附录、成果等集合或可选区 | [集合与可选区](references/collection-and-optional-sections.md) |
| 删除靠近节/页/表格，或含书签、字段、图片、批注、脚注 | [对象安全](references/object-safety.md) |

## 最终视觉检查

只有收到应用绑定的最终全页 PNG 批次时，才执行逐页检查。必须读取批次中的每一张原生图片，
为每个页码给出 `clean` 或 `defect`，不能用文本、XML、文档校验、缩略图或“图片已成功返回”
代替目视判断。完整判定标准见
[最终全页视觉检查](references/final-visual-review.md)。

发现缺陷时精确描述页码、类别、可见现象和建议修复目标。应用会建立有界修复工作项；修改后
旧版本的全部页面结论失效，应用会对新版本从第一页重新组织检查。你不负责控制这个循环。

PNG、PDF 和渲染证据只用于内部质检。除非用户明确要求，不把它们作为交付物。
