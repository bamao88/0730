# DocFit 本地运行观测界面使用指南

> 状态：面向本地开发者和产品人员的使用说明，非架构规范
> 日期：2026-08-04
> 目的：说明怎样启动本地观测网站，以及人应该怎样逐层阅读一次 DocFit 运行。

## 1. 这个网站用来做什么

DocFit 本地运行观测界面把一次 `docfit convert` 中已经发生的 Agent、Tool 和 Subagent
活动整理成可以逐层阅读的运行记录。它适合回答以下问题：

1. 这次转换最终完成了、需要补充信息，还是失败了；
2. 主 Agent 按什么顺序调用了哪些 Tool；
3. 哪次 Tool 调用最慢，输入和输出留下了哪些脱敏字段；
4. 什么时候启动了 Subagent，Subagent 调用了什么；
5. 出现问题时，应该拿哪个 `run_id`、`tool_use_id`、文档 hash 或证据引用继续调查。

它只负责观察和定位，不会启动转换、控制 Agent、修改 DOCX，也不会在观测数据库里保存
论文正文或完整页面图片。

## 2. 最快启动方式

在 DocFit 仓库根目录打开终端。如果是第一次准备环境，先运行：

```bash
uv sync --frozen
```

启动观测网站：

```bash
uv run docfit observe
```

终端会打印一条实际地址，例如：

```text
DocFit observer: http://127.0.0.1:62145/
```

把终端本次打印的完整地址复制到浏览器即可。页面现在不需要登录码，也没有登录页面。
不要关闭这个终端；终端中的进程停止后，网页也会停止服务。需要停止时按 `Ctrl+C`。

### IP 地址和端口是否固定

| 部分 | 是否固定 | 含义 |
|---|---|---|
| `127.0.0.1` | 固定 | 永远表示当前这台电脑，只能从本机访问 |
| 端口，例如 `62145` | 默认不固定 | 不传 `--port` 时，系统每次选择一个当前可用端口 |
| 完整网址 | 默认不固定 | IP 不变，但端口可能在下一次启动时改变 |

因此，当前浏览器中的 `http://127.0.0.1:62145/` 只在这次 observer 进程仍运行时有效。
下一次启动要以终端新打印的地址为准。

如果希望每次都使用相同网址，可以指定一个固定端口：

```bash
uv run docfit observe --port 43123
```

此时网址固定为：

```text
http://127.0.0.1:43123/
```

如果 `43123` 已被其他程序占用，observer 会以 `observer_startup_failed` 退出。可以先结束
占用该端口的程序，或者换一个端口。端口可使用 `0` 到 `65535`；`0` 表示让系统自动选择，
不适合作为浏览器书签中的固定端口。

网站没有 `--host` 参数，也不会绑定 `0.0.0.0`。同一局域网中的手机或其他电脑不能通过
这个地址访问。不要使用代理或隧道把它转发到局域网或公网。

## 3. 产生一条可以查看的运行记录

observer 网站和转换命令是两个独立进程。网站只读取观测历史，所以它可以在转换之前、
转换期间或转换结束后启动。为了实时查看，建议保留两个终端：

```text
终端 A：uv run docfit observe
终端 B：uv run docfit convert ...
```

在终端 B 运行一次转换：

```bash
uv run docfit convert \
  --input evals/fixtures/smoke/student.docx \
  --school-template evals/fixtures/smoke/school-template.docx \
  --school-requirements evals/fixtures/smoke/school-requirements.pdf \
  --output .tmp/smoke-output
```

`docfit convert` 默认使用 `--observation auto`。即使 observer 网页当时没有启动，转换进程
仍会把隐私安全的观测事件写入本地历史；以后启动网页仍可查看。只有显式传入下面的参数
才会关闭本次逐事件观测：

```bash
--observation off
```

浏览器页面会监听历史变化。出现新事件时通常会自动刷新；连接中断时会退回到定时检查。
如果页面没有及时变化，可以手动刷新一次。

## 4. 人应该按什么顺序看

建议固定按“先结论、再过程、最后证据”的顺序阅读：

```text
运行总览
  → 四个状态维度
  → Transcript / 时间线
  → Agent / Subagent 树
  → Tool 调用与事件详情
  → 本地证据与调试上下文
```

### 第一步：从运行总览找到目标运行

首页的每一行对应一次运行。先看：

- `run_id`：这次运行的唯一标识，后续调查时优先复制它；
- 结果：本次转换的最终状态；
- 观测：这条时间线是否完整；
- 本地证据：网页当前是否已经获得任务目录的临时授权；
- Tool / Subagent：本次记录到了多少调用；
- 最近活动：判断它仍在运行，还是已经停止更新。

不要仅凭“事件数很多”判断运行成功。事件数只说明记录数量，不代表论文质量或最终产物
已经通过验证。

### 第二步：先读详情页顶部的四个独立状态

进入某条运行后，顶部四张状态卡必须分开理解。

#### 运行结果

| 状态 | 人应该怎样理解 |
|---|---|
| `COMPLETED` | App 的最终报告确认转换完成 |
| `NEEDS_INPUT` | 系统需要用户补充信息或处理阻塞条件，本次没有完成交付 |
| `ERROR` | App 或 Tool 以错误结束 |
| `unknown` | 当前没有足够的最终报告事实，不能猜测成功或失败 |

一个 backend 或 Tool 节点显示 `ok`，不代表整次运行就是 `COMPLETED`。反过来，时间线中
出现一次错误，也要继续看后续是否发生了安全重试和最终报告。最终结论以“运行结果”为准。

#### 观测覆盖

| 状态 | 人应该怎样理解 |
|---|---|
| `complete` | 当前要求的事件来源都已记录，没有已知丢弃或冲突 |
| `degraded` | 时间线仍可阅读，但已知有事件缺失、丢弃或采集异常 |
| `unavailable` | 没有足够的逐事件数据重建运行过程 |

`complete` 只表示“日志覆盖完整”，不表示论文格式正确。`degraded` 也不等于转换失败；
观测采集失败不会主动中止转换。

#### 本地证据

| 状态 | 人应该怎样理解 |
|---|---|
| `unmounted` | 历史摘要可看，但当前浏览器会话尚未重新授权任务目录 |
| `available` | 已选择并验证匹配的任务目录，可以打开允许的本地产物 |
| `stale` | 本地文件在验证后发生变化，旧引用不能继续使用 |
| `missing` | 任务目录或目标文件已经不存在 |
| `unauthorized` | 目录不在本次授权范围内，或路径安全检查未通过 |
| `conflict` | 目录中的 ID、hash 或报告事实与这次运行冲突 |

`unmounted` 不表示文件被删除。它表示网站不会持久化本地绝对路径，服务重启或浏览器短期
会话结束后，需要人重新选择目录并让系统验证。

#### SDK transcript

| 状态 | 人应该怎样理解 |
|---|---|
| `active` | 本次 SDK 的临时 transcript 生命周期仍在进行 |
| `cleaned` | 本次运行级临时 transcript 已确认清理 |
| `residual` | 检测到本次运行残留，但网站不读取其内容或路径 |
| `cleanup_failed` | 清理动作失败，需要单独处理本机隐私残留 |
| `unknown` | 没有足够回执判断 transcript 生命周期 |

清除网站的观测历史不会删除 SDK transcript；这两类数据有独立的生命周期。

### 第三步：用 Transcript / 时间线找转折点

时间线按照本次运行的单调时钟排序，适合回答“先发生了什么，后发生了什么”。每条事件
重点看五项：

1. 时间偏移：事件发生在本次运行开始后的什么位置；
2. 来源：`app`、`sdk`、`permission`、`tool` 或 `report`；
3. Actor：主 Agent、某个 Subagent、Tool 或 App；
4. 状态与 `summary_code`：安全的状态摘要和错误码；
5. Tool 名称、`tool_use_id` 和父调用 ID：用于把调用、结果和 Subagent 连起来。

这不是模型的完整对话，也不包含隐藏思维链。原始 prompt、论文正文、Subagent 分析正文和
完整 Tool response 不会复制到观测数据库。

出现问题时，从时间线底部向上找第一个与最终状态相关的 `error`、`needs_input`、权限拒绝
或 coverage 缺口，再进入相应 Tool 或事件卡片查看直接证据。

### 第四步：用 Agent 树确认“谁调用了谁”

Agent / Subagent 树适合查看层级，不适合判断完整先后顺序：

- `Main Agent` 下的 Tool 是主 Agent 直接调用；
- `Agent invocation` 表示一次启动 Subagent 的父调用；
- `Subagent` 节点下面的 Tool 是该 Subagent 内部调用；
- “关系缺口”表示系统没有足够直接 ID 证明某条父子关系。

关系状态的含义：

| 状态 | 含义 |
|---|---|
| `verified` | 直接 ID 或 hash/ref 证据完整且一致 |
| `partial` | 缺少部分关联来源，但已有事实没有矛盾 |
| `broken` | 应有的直接关联桥接缺失，不能建立这条关系 |
| `conflict` | 两个直接来源给出了互相冲突的关联事实 |

网站不会根据时间接近或名称相似强行把两个节点连起来。因此，`partial`、`broken` 和
`conflict` 都应该被当作调查提示，而不是自动补全的事实。

### 第五步：用 Tool 卡片定位慢调用或失败调用

每张 Tool 卡片重点看：

- 调用者是谁；
- Tool 名称与 `tool_use_id`；
- `ok`、`needs_input` 或 `error` 状态；
- 开始、结束和耗时；
- 父调用 ID；
- 脱敏输入/输出字段；
- 文档、对象或渲染证据引用；
- 错误的 `origin / code`。

同一个 `tool_use_id` 是阅读一次 Tool 生命周期的主线。遇到慢调用时比较耗时；遇到失败
时先记录 Tool 名称、`tool_use_id`、错误码和关联状态，再看它之前的调用是否提供了正确
的文档快照或证据引用。

指标后面的来源也要保留：

- `reported`：SDK 或 backend 直接报告；
- `estimated`：根据已记录事实计算的估算值；
- `unknown`：缺少事实，不能按 `0` 理解。

### 第六步：必要时重新挂载本地证据

网页历史只保存索引和脱敏摘要，不保存 `task_ref → 本地绝对路径` 的长期映射。需要打开
`conversion-report.json`、最终 DOCX 或验证结果时：

1. 点击“重新挂载任务证据”或“选择并重新授权任务目录”；
2. 在系统目录选择器中选择这次转换的输出任务目录；
3. 等待网站用 `run_id`、`task_ref`、`session_id` 和文档 hash 验证；
4. 只有状态变成 `available` 后，才使用“打开”按钮。

如果显示 `conflict`、`stale` 或 `missing`，不要选择相似目录反复绕过。先确认是不是选错
任务、文件被替换，或旧任务已经删除。网站不会根据旧日志猜测真实文件位置。

目录选择器和“在系统中打开”属于可选的本地调试适配能力。当前 macOS 本地壳可提供这些
动作；核心转换和云端运行不依赖 Microsoft Word、AppleScript 或图形会话。如果当前平台
没有适配器，页面仍可完整查看历史摘要和脱敏事件。

## 5. 失败时的固定排查顺序

当页面显示 `NEEDS_INPUT` 或 `ERROR` 时，按下面顺序收集信息：

1. 记录 `run_id` 和顶部四个状态；
2. 确认观测覆盖是 `complete`、`degraded` 还是 `unavailable`；
3. 在时间线中找到最后一个与最终状态相关的失败或追问事件；
4. 在 Tool 卡片中记录 Tool 名称、`tool_use_id`、耗时和 `origin / code`；
5. 在 Agent 树中确认它来自主 Agent 还是某个 Subagent；
6. 点击相应事件的“复制调试上下文”；
7. 需要检查真实产物时，再重新挂载并验证任务目录。

复制出的调试上下文只包含允许的 ID、状态、错误码和证据引用，适合粘贴给开发者或调查
Agent。不要只截取一句错误文本；同时保留 `run_id`、`tool_use_id` 和 coverage，才能判断
错误是否来自转换、Provider、Tool 还是观测系统。

## 6. 怎样比较优化前后的两次运行

在运行总览选择“基线运行”和“候选运行”，然后生成可比性摘要。阅读顺序是：

1. 先看可比性状态和条件；
2. 只有输入、版本和验证门等条件一致时，再比较耗时、Token、Tool 次数和错误数；
3. `delta = candidate - baseline`，负值是否更好取决于指标本身；
4. 页面显示 `not_allowed` 时，只能把差异用于定位，不能宣布哪个版本更好；
5. 任一侧为 `unknown` 时，页面不会把它补成 `0`。

调用更少、耗时更短不自动证明最终论文质量更好。性能比较仍要同时检查两次运行的最终
结果、产物 hash 和验证门是否一致。

## 7. 常见问题

### 旧浏览器标签页突然打不开

先看启动 observer 的终端是否仍在运行。服务重启后，默认端口可能改变；关闭旧标签页，
重新复制终端打印的完整地址。若希望书签长期有效，请使用固定 `--port`。

### 页面能打开，但没有新的运行

确认转换命令没有使用 `--observation off`。再确认 observer 与转换命令由同一用户、同一
本地状态环境启动。默认历史数据库位于：

```text
~/.local/state/docfit/observability/observations.sqlite3
```

如果设置了 `XDG_STATE_HOME`，实际根目录会改为该目录下的 `docfit/observability`。不要在
服务运行时手动修改 SQLite 文件。

### 页面显示 `unmounted`

这是历史运行的默认安全状态，不是错误。需要打开本地产物时重新选择正确的任务目录；
只看时间线、Tool、Subagent 和指标时不需要挂载。

### 页面显示 `degraded`

继续查看 `events_dropped`、`missing_sources` 和安全错误码。它表示观测记录不完整，不代表
转换本身必然失败。最终结果仍看“运行结果”和 `conversion-report.json`。

### 固定端口启动失败

通常是端口已被占用，或者本地观测状态目录不可用。换一个端口重试；如果所有端口都失败，
检查终端打印的固定错误码 `observer_startup_failed`，再检查本地状态目录权限和剩余空间。

### 清空历史会不会删除论文或最终 DOCX

不会。“删除观测记录”和“清空观测历史”只删除观测数据库中的脱敏索引行，不删除任务
目录、最终 DOCX、验证产物或 SDK transcript。

## 8. 日常推荐用法

如果你希望网址稳定，日常可以固定使用：

```bash
uv run docfit observe --port 43123
```

然后把下面的网址加入浏览器书签：

```text
http://127.0.0.1:43123/
```

如果你经常同时启动多个 DocFit 工作副本，则使用不带 `--port` 的命令更省心，让系统为
每个进程选择不冲突的端口，并始终以终端当次打印的地址为准。
