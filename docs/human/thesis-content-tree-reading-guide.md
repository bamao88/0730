# 论文内容树与关系视图阅读指南

> 状态：面向人阅读的说明，非架构规范
> 日期：2026-08-04
> 对应母稿：[通用论文领域母稿](../../temp/knowledge-mother-draft/通用论文领域母稿.md)

本文解释为什么完整论文不能只画成一棵包含树，以及应该怎样区分实际有序内容、共享事实、
引用关系、审阅保留对象和模板绑定。

最重要的一条阅读原则是：

> 树只负责表达“拥有、包含和顺序”；事实、引用、证据、判断、审阅锚点和模板去向使用带类型的连接。

## 1. 为什么不能把所有对象都放进一棵树

一棵包含树最适合回答：

- 文档中实际有什么；
- 某个对象位于哪个单元中；
- 同级对象的阅读顺序是什么。

但论文转换还需要回答另外几类问题：

| 类别 | 回答的问题 | 典型例子 | 正确表达方式 |
|---|---|---|---|
| 实际有序内容 | 文档里实际有什么、先读什么后读什么 | 封面、摘要、章节、段落、图、表、公式 | 主阅读顺序树 |
| 共享事实 | 多个位置共同使用的事实是什么 | 论文题名、作者、专业、日期 | 共享事实注册表 |
| 引用关系 | 一个位置指向哪个对象 | `[12]` 指向文献条目；“见式（3-2）”指向公式 | 非包含关系图 |
| 审阅保留对象 | 哪些附加对象及其锚定范围必须保留 | 批注、修订、文本框、未知部件 | 保留对象注册表 |
| 模板绑定 | 原稿内容应该进入目标模板哪里 | 题名填入封面槽位；正文追加到正文容器 | 当前任务绑定表 |

如果把这些关系全都画成 `父节点 → 子节点`，后续 Skill 就无法知道某条边究竟表示
“内容属于这里”“这个位置引用了某个事实”“这项判断由某份证据支持”，还是“准备把内容
填入模板中的某个位置”。

## 2. 实际有序内容：表达“内容在哪里”

真正的论文内容树保存实际占据阅读位置的单元和内容。例如：

```text
正文根 body.main
└─ 第一章 body.section[level=1]
   ├─ 第一段 body.paragraph
   ├─ 第一节 body.section[level=2]
   │  ├─ 正文段落 body.paragraph
   │  ├─ 公式 object.equation
   │  └─ 正文段落 body.paragraph
   └─ 第二节 body.section[level=2]
```

这棵树中的父子关系有固定含义：

- 第一节属于第一章；
- 公式位于第一节中；
- 公式前后分别有哪些内容；
- 第一节与第二节的先后顺序是什么。

一级、二级、三级标题不需要定义为互相平行的三种节点。它们统一使用递归的
`body.section`，再通过 `level=1`、`level=2`、`level=3` 表达层级。章节内的段落、图、表、
公式和直接子章节共同保存在同一个有序 `children[]` 中，不能先按类型分组后再拼接。

## 3. 共享事实：表达“它是什么”

论文题名可能同时出现在外封面、内封面、书脊、中文摘要页和英文摘要页。如果把题名分别
作为这些单元独立拥有的子节点，就会得到多份看似独立的题名：

```text
外封面
└─ 题名：“XXX研究”

内封面
└─ 题名：“XXX研究”

中文摘要
└─ 题名：“XXX研究”
```

这样无法区分“同一个论文题名的多次出现”和“三个不同的题名”。更合理的表达是只保存一份
事实真值，再让各个出现位置引用它：

```text
共享事实注册表 thesis.facts
└─ 论文主标题 fact:title-001
   └─ 值：“XXX研究”

外封面题名位置 ref:title-cover ──引用──→ fact:title-001
内封面题名位置 ref:title-inner ──引用──→ fact:title-001
摘要页题名位置 ref:title-abstract ──引用──→ fact:title-001
```

因此，论文题名事实不属于某一个封面。封面拥有的是一个实际出现位置，这个位置再引用论文
题名事实。这样既能检查多个位置是否一致，也能在它们冲突时保留冲突，而不是悄悄生成多份
互相竞争的真值。

摘要正文、声明正文、献词、正文段落、图和表等局部内容不属于这类共享事实，它们仍由各自
所在的文档单元直接拥有。

## 4. 引用关系：表达“这个标记指向谁”

正文中的引文、公式索引和交叉引用同时具有两种身份：它们在正文中有实际出现位置，同时又
指向另一个对象。

例如，内容树可以表达 `[12]` 出现在某个段落中：

```text
第一章
└─ 正文段落
   └─ 文内引文标记 “[12]”
```

但还需要一条独立的关系说明它指向哪条参考文献：

```text
文内引文 citation-01
── citation_target ──→
参考文献条目 reference-12
```

正文中的“见式（3-2）”同理：

```text
段落中的交叉引用 cross-ref-07
── cross_reference_target ──→
公式 equation-3-2
```

不能把参考文献条目直接放在文内引文下面：

```text
错误示意
文内引文 “[12]”
└─ 参考文献条目
```

同一条参考文献可以被十几个正文位置引用，而树节点通常只有一个直接父节点。强行使用包含
关系，要么会复制十几份文献条目，要么会错误地认为该文献只属于某一个正文段落。

正确分工是：

- 内容树保存引文标记在正文中的出现位置；
- 关系图保存引文标记指向哪条文献；
- 后置内容树保存文献条目在参考文献列表中的实际顺序；
- 同一个文献条目可以被零次、一次或多次引用，未被引用不等于应当自动删除。

脚注也采用同样的方式：脚注标记留在段落的行内顺序中，脚注正文拥有自己的附着内容流，
二者通过 `note_map` 连接。

## 5. 审阅保留对象：表达“什么附加对象必须一同保留”

批注和修订不总能成为某个段落的普通子节点。一条批注可能覆盖一个句子、两个段落、若干
表格单元格，甚至从正文文字跨到公式。

如果简单写成：

```text
段落 A
└─ 批注 1
```

就可能丢失“这条批注实际从段落 A 末尾延伸到段落 B 开头”的信息。更合适的表达是：

```text
保留对象 comment-01
├─ 批注内容
├─ 作者和时间
└─ anchored_range
   ├─ 起点 → paragraph-A / text-offset-25
   └─ 终点 → paragraph-B / text-offset-12
```

内容树继续保存可见正文的阅读顺序，保留对象则通过锚定范围与正文连接。这样 Skill 才知道：

- 批注不是论文正文；
- 它不能被静默删除；
- 它可能跨越多个正文节点；
- 最终保留、接受、拒绝还是交给人工，应由当前任务要求决定。

解析器不能识别的文本框、嵌入对象或自定义部件也不能当作空内容。可见未知对象需要在原阅读
位置留下占位节点，原始载荷则进入保留对象注册表，以便后续检查和无损交付。

## 6. 模板绑定：表达“内容准备放到哪里、怎样放”

学生论文内容树描述原稿当前是什么；目标模板树描述模板允许放什么。它们是两棵不同的树：

```text
学生论文内容树
├─ 外封面
├─ 中文摘要
└─ 正文
   └─ 第一章
```

```text
学校模板树
├─ 封面固定区域
│  ├─ 题名槽位
│  └─ 作者槽位
├─ 摘要容器
└─ 正文容器
```

两棵树之间通过当前任务绑定连接：

```text
论文题名事实
── fill ──→ 模板题名槽位

学生中文摘要实例
── replace_or_fill ──→ 模板摘要容器

学生正文根
── append ──→ 模板正文容器
```

如果把模板节点直接画成学生内容的父节点，就会混淆：

- 学生原稿里的正文原本在哪里；
- 转换后正文应该进入模板哪里。

不同学校的模板结构也不相同，所以模板绑定只属于当前任务。它不能反向改变“正文”“题名”
“公式”或“参考文献”等稳定论文语义，更不能把某一学校的模板结构提升为通用 Knowledge。

## 7. “是什么、在哪里、为何判断、怎么处理”怎样分开

同一个论文对象在转换过程中至少会涉及四类信息：

```text
是什么
└─ semantic_id、事实值、稳定内容身份

在哪里
└─ instance_id、内容树位置、当前文档快照定位器

为何这样判断
└─ evidence_link、来源观察、模板观察、要求声明、用户确认

怎么处理
└─ decision_overlay、处置候选、模板绑定、人工责任
```

以一个疑似二级标题为例：

- **是什么**：它是 `body.section`，推导出的语义层级为 `level=2`；
- **在哪里**：它是第二章下的某个具体章节，在当前 DOCX 中对应一个具体段落范围；
- **为何判断**：原始编号为 `2.3`，来源大纲级别为 2，目录中也是二级，文字与外观提供辅助证据；
- **怎么处理**：保留标题文字，绑定到模板的二级正文结构，按当前任务规则处理编号和目录。

如果把这些都写成该标题的永久子节点：

```text
二级标题
├─ Word 段落位置
├─ 因为它使用“标题 2”样式
├─ 应修改成某种字号字体
└─ 放入模板第二级标题槽位
```

就会产生混淆：

- Word 段落位置会在文档编辑后失效；
- “标题 2”样式只是本次识别证据之一；
- 语义层级是当前证据支持下的判断；
- 模板槽位取决于本次学校模板；
- 字体字号属于样式层；
- 只有章节身份、标题文字和稳定结构关系适合进入稳定语义模型。

## 8. 一个同时包含公式、引文和批注的完整例子

假设第一章某段写着：“根据已有研究[12]，参数关系见式（3-2）。”，后面紧跟陈列公式，
而审阅者对这句话添加了一条跨段批注。

主阅读顺序树只表达实际内容和顺序：

```text
第一章 body.section[level=1]
├─ 正文段落 paragraph-01
│  ├─ 文字：“根据已有研究”
│  ├─ 文内引文标记 citation-01：“[12]”
│  ├─ 文字：“参数关系见”
│  └─ 交叉引用 cross-ref-01：“式（3-2）”
├─ 陈列公式 equation-3-2
└─ 后续段落 paragraph-02
```

非包含关系图表达目标：

```text
citation-01 ──citation_target──→ reference-12
cross-ref-01 ──cross_reference_target──→ equation-3-2
```

保留对象注册表表达批注范围：

```text
comment-01
├─ 起点 → paragraph-01
└─ 终点 → paragraph-02
```

当前任务投影再记录：

```text
snapshot_map
├─ paragraph-01 → 当前源 DOCX 的段落定位器
├─ equation-3-2 → 当前源 DOCX 的公式对象定位器
└─ reference-12 → 当前源 DOCX 的文献条目定位器

evidence_link
└─ 这些语义实例和关系分别由哪些来源观察支持

decision_overlay
└─ 公式、引文、批注和文献条目本次准备保留、修改还是人工确认

binding.map
└─ 各内容实例准备写入目标模板的哪个容器或槽位
```

编辑后，旧 DOCX 定位器可能失效，但 `paragraph-01`、`equation-3-2` 和 `reference-12` 等逻辑
实例身份仍可用于新旧结果对照。Agent 重新检查候选文档，建立新快照映射，然后验证内容、顺序、
公式目标、文献目标和批注状态是否仍然正确。

## 9. 最后怎样读母稿中的“总树”

母稿的 `thesis.model` 大图是一张对象目录图，不代表所有顶层分组都是论文页面上依次出现的
子节点。阅读时应把它理解为几个相互连接的视图：

```text
稳定论文语义模型 thesis.model
├─ 主阅读顺序树 thesis.primary_flow       实际内容和顺序
├─ 附着内容子树 thesis.attached_flow*      脚注、尾注、页眉页脚自身的内部顺序
├─ 共享事实注册表 thesis.facts             题名、作者、日期等唯一事实
├─ 非包含关系图 thesis.relations           引文、交叉引用、事实引用和生成依赖
└─ 审阅与未知保留注册表 thesis.preservation 批注、修订和未知对象

当前任务投影 task.projection
├─ snapshot_map                            当前文件位置
├─ evidence_link                           判断依据
├─ decision_overlay                        当前处理判断
├─ binding.map                             目标模板去向
└─ validation                              修改后的验证记录
```

其中只有 `thesis.primary_flow` 和各个附着内容流是真正按阅读顺序遍历的内容树。其他部分是
注册表、关系图或当前任务投影，虽然为了盘点方便被画在同一张大图里，但不能把它们理解成
论文页面上的普通父子结构。
