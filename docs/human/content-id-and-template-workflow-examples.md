# 模板文字处理示例

> 状态：面向人阅读的说明，非架构规范
> 日期：2026-08-01
> 说明：文件名沿用早期命名；`content_id` 等对象引用现在只视为 DOCX Tool 的内部实现。

本文用两个容易混淆的模板片段说明 Agent、Knowledge 与 Tools 如何分工。规范边界见 01、04、05 文档。

示例优化过程中发现的问题、根因归属、修复位置与验证证据，持续记录在
[《论文转换示例优化问题台账》](./thesis-conversion-example-optimization-log.md)。

## 1. 共用判断模型

模板中的可见文字不能简单分成“保留”或“删除”。Agent 通常区分：

```text
fixed_content       学校要求最终保留的固定文字
conditional_content 根据学生类型或元数据决定是否出现
slot_placeholder    等待学生内容填入的位置
format_instruction  只用于说明字号、字体或行距，最终应清理
```

分工如下：

- Agent 根据通用 Knowledge、页面位置、上下文、当前任务学校材料和实际样式判断角色；
- DOCX Tool 返回可定位的对象或文本片段引用；
- Agent 形成语义操作意图；
- Tool 精确修改工作副本并重新读取；
- 验证 Tool 检查内容、占位符、样式和渲染；
- 已知样本的正确结果固化为 Eval 断言。

如果 Tool 内部使用 `content_id`、`source_ref` 或 `span_ref`，它们只是保证定位安全的实现细节。Agent 可以传回 opaque 引用，但应用壳和 Agent runtime 不需要理解其结构。

## 2. 示例一：固定标题、条件“（设计）”与格式说明

### 2.1 原始模板文字

```text
全日制普通本科生毕业论文（设计）（一号黑体加粗）
```

本例中的业务含义：

```text
全日制普通本科生毕业论文   fixed_content
（设计）                   conditional_content
（一号黑体加粗）           format_instruction
```

### 2.2 Agent 如何判断

Agent 应同时观察：

- 该段位于封面主标题位置；
- 学校说明表明论文类与设计类的标题不同；
- “一号黑体加粗”描述格式，而不是交付文字；
- 模板的实际字体、字号和加粗是否与文字说明一致。

语义结果可以表示为：

```yaml
rule: cover.document_type_heading
fixed_text: 全日制普通本科生毕业论文
conditional_suffix:
  value: （设计）
  when: student_work_type == design
style:
  font: 黑体
  size: 一号
  bold: true
```

如果可见说明与模板实际样式冲突，Agent 不应静默选择。它应展示两份当前任务
证据并向用户确认；确认结论只服务当前任务，不写入长期 Knowledge。

### 2.3 Tool 如何处理

制作学校模板时，Tool：

1. 保留固定标题；
2. 把“（设计）”处理为可按学生类型选择的内容；
3. 删除可见格式说明；
4. 保留并规范化段落样式；
5. 另存并渲染工作副本。

转换学生论文时，Agent 根据学生文档或用户元数据判断：

```text
design → 全日制普通本科生毕业论文（设计）
paper  → 全日制普通本科生毕业论文
不确定 → 询问用户
```

Tool 只执行已经明确的操作，不重新解释学校自然语言。

### 2.4 如何验证

确定性检查：

- 最终 DOCX 能重新打开；
- 格式说明文字已删除；
- 固定标题仍存在；
- design / paper 两种输入产生正确文字；
- 字体、字号和加粗符合当前任务已确认规则。

Eval 断言：

- 两种类型各一个合成 case；
- 固定文字、条件后缀和样式分别断言；
- 页面位置由人工查看或图像差异辅助。

## 3. 示例二：中文题目占位文字与格式说明

### 3.1 原始模板文字

```text
毕业论文（设计）中文题目（小二黑体加粗）
```

本例中的业务含义：

```text
毕业论文（设计）中文题目   slot_placeholder
（小二黑体加粗）           format_instruction
```

这里的“毕业论文（设计）中文题目”整体表示学生中文题目的填写位置，与示例一的固定标题不同。

### 3.2 Agent 如何判断

Agent 应观察：

- 该段处于封面中文题目区域；
- 相邻位置是否存在英文题目；
- 学校说明是否要求在此填写学生题目；
- 这段文字是否明显不是某个学生的真实标题；
- 实际段落样式是否与“小二黑体加粗”一致。

当前任务推导规则可以表示为：

```yaml
slot: cover.title_cn
source: title_cn
fill: replace
style:
  font: 黑体
  size: 小二
  bold: true
```

### 3.3 Tool 如何处理

制作模板时，Tool：

1. 删除格式说明；
2. 将占位文字替换为空锚点或受控标记；
3. 保留原有页面位置和样式；
4. 检查不再残留占位文字。

转换学生论文时，Agent 从源文档识别实际标题，例如：

```text
面向复杂文档的智能格式转换方法研究
```

然后让 Tool：

1. 把标题写入 `cover.title_cn`；
2. 不复制学生原格式；
3. 应用学校标题样式；
4. 渲染封面供 Agent 回看。

如果 Tool 使用对象引用，Agent 只需要把分析结果中的引用传回编辑工具，不需要解析 OOXML 位置。

### 3.4 长标题

真实标题可能比占位文字长。写入后 Agent 应查看：

- 自动换行是否合理；
- 是否挤压英文题目或学生信息；
- 是否出现页面溢出；
- 学校是否允许条件性缩小字号；
- Tool 使用的渲染 provider 是否足以支持分页判断。

Agent 可以调整操作并再次渲染，但不能改写学生题目来适应版面。

### 3.5 如何验证

确定性检查：

- 学生标题文字完整；
- 目标槽位已填；
- 占位文字和格式说明不存在；
- 最终 DOCX 可打开；
- 标题样式符合当前任务已确认规则。

Eval 断言：

- 普通长度与超长标题各一个 case；
- 断言标题内容和关键样式；
- 长标题页面由人工确认换行与遮挡。

## 4. 两个例子的差异

| 维度 | 示例一 | 示例二 |
|---|---|---|
| 原文字 | 全日制普通本科生毕业论文（设计） | 毕业论文（设计）中文题目 |
| 业务角色 | 固定内容 + 条件内容 | 槽位占位文字 |
| 学生数据作用 | 决定是否保留“（设计）” | 提供实际中文题目 |
| 最终处理 | 保留固定部分，按条件生成后缀 | 整体替换为学生标题 |
| 格式说明 | 转成样式后删除 | 转成槽位样式后删除 |

文字外观相似并不代表语义相同。Agent 必须结合页面位置、相邻内容、学校来源和实际样式判断。

## 5. 沉淀位置

经过真实样本和人工确认后：

- 跨多个任务仍成立、且已经去除学校名称和具体数值的概念、识别方法、解释原则
  与处理模式，可以作为产品 Knowledge 候选；
- 学校名称、具体字号、固定文案、条件规则和确认结论只进入当前任务证据或授权
  Eval fixture，不进入长期 Knowledge；
- 精确修改能力进入 `tools/`；
- Agent/Skill 错误进入 `evals/skills/`，完整交付错误进入 `evals/e2e/`；纯逻辑和 Tool 契约错误分别进入 `tests/unit/` 与 `tests/contract/`，真实 SDK、Provider 和 CLI 组合错误进入 `tests/integration/`。

不需要把这些经验编译为新的运行阶段或状态机。
