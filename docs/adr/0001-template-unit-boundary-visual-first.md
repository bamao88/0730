# ADR 0001: 视觉语义判断与统一源对象边界

日期: 2026-08-18；修订: 2026-09-22
状态: accepted decision；实现与验证状态见当前全流程对象身份计划

## 背景

模板提取要先识别封面、目录、正文等功能区，再判断各区内部内容。最初决策让 Agent 提交
页码、区域和可见文字，由 Tool 将视觉锚点解析为 Word 范围。该做法避免让 Agent 计算 Word
索引，却留下另一套定位合同：首次分区和后续源对象判断不使用同一身份。

2026-09-22 用户明确要求第一步到实际写入使用同一对象身份，且禁止过渡兼容。
本修订替代原 ADR 的 visual-anchor-to-locator 决策，保留视觉帮助学校语义判断的职责。

## 决策

1. App 从原始不可变 DOCX 建立完整 canonical source inventory，先于第一次 Agent query。
2. Agent 读取源对象 ID、可读文本、顺序和视觉线索，输出功能区名以及已有源对象上的边界。
3. 边界可以是对象开始/结束，也可以是对象内部切点。内部切点给出精确前后原文，Harness
   检查两段拼接等于对象全文并计算 offsets；不让 Agent 管理 hash、locator 或映射。
4. 功能区范围覆盖完整清单，按源顺序无缺口、无重叠。同一对象跨区时继续使用原 ID 的子范围。
5. 读取、分批、判断、恢复、物化及发布只消费初始清单的投影和共享 span resolver 结果。
   raw Word locator/fragment 是内部执行映射；unit ID 是分组名称，都不能成为另一个选对象入口。
6. 旧文本定位、页码定位、locator 直传和缺初始 inventory binding 的 proof 明确拒绝，无双读和转换。

## 备选方案与取舍

- 按分区重新生成 ID：使分区调整改变对象身份，拒绝。
- 为跨区对象复制新对象或限制边界只能落在段落间：无法满足对象内精确边界，拒绝。
- 保留旧文字搜索作为兜底：重复文字仍可能换对象，且违反唯一合同，拒绝。
- 让 Agent 输出 Word locator 或 offsets：把确定性定位工作转嫁给语义判断层，拒绝。

采用统一清单后，Tool 需展示对 Agent 可读的上下文，不能只给不透明 ID。共享对象由一个语义
批次负责，但该批次必须看到所有相关分区上下文；后续 parts 不能跨已接受的分区切点。

## 验证与后果

验收需要分别证明：稳定 ID 和精确范围的 logic/contract；从初始清单的真实 replay；新 Agent 从
原始 DOCX 开始分区、反馈修订和后续写入；重开实际 Word 核对修改范围及未选中内容。
历史 post-unit 证据不能代替新链路证据。学校语义和版式的全面产品验收不属于此次身份任务。
