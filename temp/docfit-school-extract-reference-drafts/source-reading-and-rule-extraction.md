# 来源阅读与规则提取

> 状态：Temp 草稿。用于未来论文模板提取 Skill 的按需 Reference，尚未进入正式 Skill、Knowledge 或公开 Schema。

## 何时读取

在以下任一情况出现时读取本文件：

- 同一格式或内容要求在模板、说明文档和样例中不一致；
- 需要判断一段内容是学校固定文字、填写提示、样例、生成机制还是纯布局对象；
- 准备删除说明、样例或条件内容；
- 需要决定能否根据常识补全缺失要求；
- 准备把一次学校案例总结成可复用经验。

本文件回答“证据说明了什么”和“什么职责必须继续存在”。它不负责确定物理边界、执行 OOXML 修改，也不保存某所学校的具体格式参数。

## 当前任务应留下什么

读完来源后，Agent 至少应留下四类自然语言结论：

- 哪些是学校明确要求，适用于什么范围；
- 哪些只是模板实现、学生样例或操作教程；
- 哪些职责在清理后仍要保留、填写、生成或人工完成；
- 哪些地方存在冲突、缺证据或需要用户确认。

这些结论随后分别交给单元拆分、模板清理、正文样式、生成内容和验证流程使用。

## 核心原则

先保存事实，再作判断；先识别必须存续的职责，再决定删除、填写或生成操作。

不要把以下三类信息混成一个结论：

1. **来源事实**：某个文件、段落、样式或 Word 渲染实际出现了什么。
2. **当前任务判断**：本次提取认为该事实适用于什么对象、范围和版本。
3. **执行决定**：保留、清空、生成、创建槽位、人工处理或暂不处理。

执行决定可以改变，来源事实不能被改写。后续证据推翻判断时，应保留旧判断的来源和被替代原因。

## 1. 给来源定性

为每个会影响最终模板的来源记录其性质。这里是判断词汇，不要求立即固化为公共字段。

| 来源性质 | 它能证明什么 | 不能直接证明什么 |
|---|---|---|
| 学校正式规范或通知 | 明文规定的适用范围、必选项和格式要求 | Word 中具体如何承载该要求 |
| 学校正式 Word 模板 | 固定结构、可见说明、样例实现、分节和对象关系 | 每个样例值都是规范要求 |
| 模板中的说明文字 | 学校希望用户遵守的操作或格式提示 | 文字本身一定要保留在干净模板中 |
| 模板有效显示实例 | 当前 Word 对象实际生效的格式和布局行为 | 该值一定是学校有意规定而非历史遗留 |
| 命名样式和原始 OOXML | 实现机制、继承链和包结构 | 最终有效显示，也不能仅凭样式名判断语义 |
| 学校认可论文样本 | 现实使用中的可行实现和边界案例 | 可覆盖正式规范的普遍规则 |
| 学生稿 | 本次需要迁移的内容和异常输入 | 目标学校的模板规则 |
| 国家或行业标准 | 适用条款明文覆盖的缺失属性 | 学校已经明确规定的属性可以被覆盖 |
| Word 原生渲染或保存结果 | 目标应用中的分页、字段、换行和包行为 | 这些行为的规范来源 |
| LibreOffice 等辅助渲染 | 批量发现越界、裁切和明显空白页风险 | Word 交付版的最终分页真值 |
| Agent 推断 | 把多项事实组织成待复核结论 | 新的学校事实或新的标准数值 |

### 默认冲突处理顺序

只比较**同一语义角色、同一适用范围、同一模板版本**的主张。范围不同不是冲突。

1. 优先使用当前任务已明确认定的学校正式规范。
2. 再检查学校正式模板中的明确说明。
3. 再检查模板的有效显示实例，包括直接格式和继承结果。
4. 原始样式定义、认可论文和保守推断只作为补充证据。
5. 若用户已规定其他优先级，以用户的当前任务决定为准。
6. 若冲突会改变固定内容、重要槽位、全局样式或最终分页，并且没有明确优先级，保持未决并请求确认。

不要“投票取多数”，也不要把不同来源的属性拼成一个没有出处的整套样式。字体、字号、粗体、对齐、间距、编号等应逐属性判断。

## 2. 区分可见角色与存续职责

一个对象现在看起来是什么，与清理后必须继续提供什么，是两个问题。

### 当前可见角色

- `fixed_content`：学校固定标题、声明、表格标签、品牌或不可替换文字。
- `placeholder`：等待填入真实值的可见占位内容。
- `instruction`：操作、填写或格式说明。
- `example`：为了展示结构或样式而存在的样例。
- `mechanism`：字段、编号、内容控件、书签、页码等活机制。
- `structural_container`：表格、段落、分节、页眉页脚等承载结构。
- `unknown`：现有证据不足以定性。

### 必须存续的职责

- `fixed`：清理后仍必须原样或按授权版本存在。
- `fill`：需要为用户或转换 Agent 留出明确输入位置。
- `generate`：内容需要依据最终论文结构计算，而不是复制当前显示值。

以下不是职责种类：

- “重复”是数量特征；
- “条件出现”是适用条件；
- “人工填写”是处理方式；
- “删除”是执行操作；
- “未决”是证据状态。

一段说明文字可以被删除，但它描述的 `fill` 或 `generate` 职责必须先迁移到新的接口。一个表格既可能是固定结构，也可能同时包含多个填写职责。

## 3. 建立最小证据记录

对会影响模板结构、样式或内容处置的结论，至少能够回答：

- 来源文件、页、段落、对象或稳定引用是什么；
- 来源性质是什么；
- 原始主张或观测事实是什么；
- 适用对象、语言、文档类型和条件是什么；
- 当前判断是什么；
- 这是已确认、候选、冲突还是未决；
- 执行后用什么证据证明职责仍然存在。

不要强迫 Agent 在自然语言判断阶段先填满一个复杂 Schema。开发实现可以把这些内容编译成结构化记录，但 Reference 的重点是避免遗漏。

## 4. 从学校案例提炼经验

### 案例 A：说明文字不能整段当垃圾删除

湖南农业大学模板中的说明文字同时描述目录留白、正文标题位置、参考文献、致谢和附录的排版要求。早期清理删除了说明文字，也同时丢失了顶部空行和间距规则。

正确做法：

1. 把固定要求、条件、间距和生成职责分别提取；
2. 将可确定的布局要求迁移成段落间距或页面起始合同；
3. 将填写或生成职责绑定到新接口；
4. 最后删除纯教程文字。

可泛化经验是“说明先迁移职责再删除”，不是“所有论文标题前固定空两行”。

### 案例 B：候选合同不能自动成为学校 Gold

北京大学 `fill-contract-r02` 根据单篇试转换和人工反馈提出封面题目安全容量、只保留中文题注、匿名模式删除完整条件节等规则。该目录明确标注为 Candidate，尚未完成更大样本和 Human 验收。

正确做法：把这些结论作为当前候选证据使用；只有学校正式材料、扩大验证和人工确认完成后，才能讨论晋升。不能因为案例修复成功就把“10 个加权字符”写进通用 Knowledge。

### 案例 C：第三方模板可以证明行为，不能证明规范权威

北京大学源材料中存在社区工程参考文件。它的字段、样式和可见结构可以用于研究 Word 行为，但如果学校没有正式发布授权，就不能把其中所有值认定为学校规范。

### 案例 D：可选不等于立即删除

南京农业大学的“相关学术成果目录”标注为非必需项。它仍然是学校拥有的逻辑职责。条件未确认时，应保留可见复核入口，不能仅因为学生稿没有这部分就静默删除。

## 5. 禁止的经验提升

以下内容必须留在当前学校或当前任务证据中：

- 某校具体字号、字体、行距、题名容量和题注语言政策；
- 某校恰好有多少个逻辑单元；
- 某个学生样本中出现了几张图、多少条目录项；
- 单篇 Candidate 修复得到的阈值；
- 某个渲染器在某台机器上的坐标或页数。

可以进入通用 Skill 的是识别、冲突处理、迁移和验证方法。

## 6. 未来开发预留

以下是能力位置，不是已批准的 Tool 名称或公共 Schema：

### EVIDENCE-01：证据台账辅助生成

- 从文件清单、段落引用和对象引用生成任务级证据记录；
- 保留来源 hash、版本和证据性质；
- 不自动决定权威性。

### EVIDENCE-02：属性级冲突扫描

- 找出相同语义范围内的字体、字号、间距、条件和顺序冲突；
- 将不同适用范围与真正冲突分开；
- 冲突只报告，不静默选择赢家。

### EVIDENCE-03：说明职责迁移检查

- 检查待删除说明是否仍承载固定、填写或生成职责；
- 没有迁移目标时阻止破坏性删除；
- 支持人工确认“无职责存续”。

开发这些能力前，应先批准独立计划，并保持现有五个公开 Tool 名称不变。
