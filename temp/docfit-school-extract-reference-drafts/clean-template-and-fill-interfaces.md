# 干净模板与可填写接口

> 状态：Temp 草稿。用于未来论文模板提取 Skill 的按需 Reference。这里描述清理判断，不执行学生论文内容填充。

## 何时读取

在以下情况读取本文件：

- 需要把带说明和样例的学校 Word 转成干净模板；
- 准备删除占位文字、样例章节、教程或学生信息；
- 需要为封面、摘要、正文或表单建立可定位填写位；
- 需要决定内容缺失时保留、删除、提示还是失败；
- 清理后模板看起来干净，但 Agent 或用户不知道在哪里填写。

## 核心结论

干净模板不是“样例文字越少越好”，而是：

> 固定结构仍在，学校职责仍在，样例实例已移除，填写和生成接口清晰可用，修改后能够独立验证。

如果删除后只剩空白页面或无意义空表格，却没有可见且唯一的填写入口，这不是合格的干净模板。

## 当前任务应留下什么

- 固定保留区、可填写区、生成区、条件区和人工区；
- 每个待删除说明或样例的职责迁移去向；
- 每个填写位置的可见提示、唯一定位和空内容策略；
- 需要整段、整页或整节处理的条件内容；
- 一次真实填充、更新、保存和重开的验证结果。

## 1. 清理前先分类

对候选对象分别判断：

- **保留固定内容**：学校名称、声明、表单标签、不可替换标题和固定说明。
- **替换为填写接口**：题名、作者、学号、摘要正文、关键词等任务值。
- **保留为生成接口**：目录、图目录、表目录、题注编号和交叉引用。
- **条件处理**：实名页、可选成果页、可选附录等。
- **迁移后删除**：教程、样例、格式说明和演示内容。
- **保留待确认**：证据不足、对象混合或删除风险高的内容。

“删除”只能出现在职责判断之后。固定职责没有替代位置时不删除；说明职责没有迁移时不删除；对象身份未决时不删除。

## 2. 先迁移，再清理

说明文字和样例可能承载：

- 固定用语和标点；
- 填写内容的类型、长度、语言或数量；
- 标题、正文和表单的间距；
- 分页、分节和装订规则；
- 目录、编号或字段更新方式；
- 条件出现规则；
- 重复容器和复合对象的成员顺序。

按以下顺序处理：

1. 标出所有可见角色和结构容器；
2. 识别清理后仍需存在的固定、填写和生成职责；
3. 将规则迁移到槽位、固定区域、生成机制、页面起始合同或人工区域；
4. 建立唯一目标并验证其可解析；
5. 只删除已完成迁移的文字或实例；
6. 比较修改前后，确认受保护结构没有连带变化。

## 3. 可填写接口的最低要求

每个填写接口同时服务用户和 Agent：

- **可见**：用户打开模板能理解这里需要什么；
- **唯一**：Agent 能解析到一个且仅一个目标；
- **有边界**：填入内容不会吞掉邻近固定文字；
- **有内容类型**：标量、段落流或复合内容处理方式明确；
- **有数量规则**：是否可空、是否重复、上限是否存在；
- **有空内容策略**：缺失时保留提示、人工复核、删除整块或失败；
- **有布局承载**：表格、段落、下划线、分节等容器不因清空文字而丢失；
- **可复验**：填写、更新字段、保存、重开后目标仍稳定。

不要仅依赖灰色占位文本、页面坐标或第一次出现的相同短语。优先使用当前 Tool 能稳定定位的内容控件、书签、结构边界或唯一对象引用。

## 4. 按内容形态建立接口

### 标量

用于题名、作者、学号、日期等单个有界值。保留固定前后缀、表格格线和下划线职责，只替换值区域。

### 段落流

用于摘要、正文、致谢、参考文献等可变长度内容。需要明确开始、结束、允许的段落角色和退出条件，不能只留一个单行占位符。

### 复合内容

用于图、表、公式、双语题注或成组表单。接口需要表达内部成员和顺序，不能将整个对象压成一个字符串槽位。

## 5. 删除模式与容器保护

根据物理结构选择最小安全修改：

- 只清空文字，保留段落和样式；
- 删除混合段落中的精确片段；
- 清空表格单元格，保留网格、合并和行高；
- 删除整个无职责容器；
- 删除有稳定首尾锚点的连续块；
- 去掉内容控件外壳但保留内部内容。

不要因为文本相同就批量删除所有命中。先比较上下文、有效格式、字段、对象和相邻结构。

## 6. 空内容和条件内容

把“是否出现”和“出现后由谁填写”分开判断。

### 必填内容缺失

保留学校结构和可见待补接口，在严格交付中报告或失败。不要伪造姓名、日期、签字或学校事实。

### 可选内容缺失

在草稿或复核阶段保留可见提示，除非学校证据明确要求缺失时整块省略。

### 条件内容未确认

记录条件并进入复核。不要把“学生稿没出现”当成条件为假。

### 条件明确为不出现

判断缺席策略覆盖的最小完整结构：仅清空值、删除内容容器、删除整页或删除整个条件分节。处理后重新检查分页、页眉页脚和后续奇偶页设置。

### 人工签字或盖章区域

保留学校表单壳和人工职责，不自动生成未知签名或审批意见。

## 7. 真实案例

### 案例 A：第一版干净模板没有真正的填写接口

南京农业大学和北京大学早期清理版本删除了样例，但仍依赖灰色文字和视觉位置猜测，无法保证每个填写位置唯一。后续版本建立唯一内容控件标签，并固定正文标题的大纲级别，才形成可复用接口。

可泛化经验：清理验收必须包含“真实填写一次”和“重复解析仍唯一”，不能只扫描是否还存在样例文字。

### 案例 B：封面下划线是一组固定行容器

北京大学候选 r02 中，封面题名位由三条固定下划线和表格行共同构成。不能把三行合成一个自动换行单元格，也不能为塞入长题目擅自缩小字号。

该案例的通用经验是“封面显示线的结构与容量必须作为填写接口的一部分验证”；具体 10 个加权字符阈值仍是 Candidate 任务证据。

### 案例 C：说明文字删除导致页面顶部节奏丢失

湖南农业大学模板的说明段同时承担正文标题、目录和后置内容的留白解释。直接删除后，模板虽然文字更干净，但页面顶部位置错误。应把可确定的空白迁移为段前距或页面起始合同，再删除说明。

### 案例 D：条件页只删文字产生空白页

北京大学匿名模式案例中，实名专家名单属于完整条件节。只删除可见内容而保留分节边界，会在封面后留下空白页。缺席策略必须明确是否删除整个条件节以及如何处理后续 `oddPage`。

### 案例 E：表格中的空单元格仍然有职责

任务书、开题、答辩和成绩表里的空白格可能是学校预留的手填区域。不能因为无文本就删除单元格、压缩行高或把表格当作空内容。

## 8. 清理后的验收

至少验证：

- 固定学校文字、品牌、声明和表格结构没有无授权变化；
- 每个填写职责都有唯一目标；
- 每个生成职责仍保留活机制或明确生成入口；
- 教程、样例和旧学生信息没有残留；
- 内容控件、书签或边界没有重复；
- 填写标量不会覆盖固定前后缀；
- 填写长段落不会越过退出边界；
- 条件缺席不会留下伪空白页；
- 填写、字段更新和 Word 保存后模板仍可打开且结构稳定。

## 9. 未来开发预留

### CLEAN-01：候选内容分类视图

- 汇总文本、容器、字段、对象和周边上下文；
- 允许 Agent 标注保留、迁移、删除、条件或未决；
- 不根据关键词自动执行删除。

### CLEAN-02：职责迁移门

- 对删除操作检查所有存续职责是否已有目标；
- 自动槽位必须唯一、稳定并绑定当前快照；
- 未决区域和固定内容默认拒绝破坏性修改。

### CLEAN-03：填写接口物化

- 支持标量、段落流和复合内容的稳定承载；
- 保留表格、段落、样式和布局关系；
- 暂不承诺新的公共 API 或 Slot Schema。

### CLEAN-04：填充往返验证

- 对代表性短值、长值、空值和重复值做填充测试；
- 保存并重开后检查目标唯一性、溢出和固定内容；
- 将失败定位到具体接口和受影响页面。

开发工作另行规划。本草稿只预留职责与验收条件。
