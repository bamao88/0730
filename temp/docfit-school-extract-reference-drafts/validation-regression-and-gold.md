# 验证、回归与 Gold 固化

> 状态：Temp 草稿。用于未来论文模板提取 Skill 的按需 Reference。Temp 中的人工 Gold 和 Candidate 状态不得被本文件自动改变。

## 何时读取

在以下情况读取本文件：

- 准备声明模板提取完成；
- 修改了分页、分节、固定表格、字段、样式或复合对象；
- 包结构通过但 Word 表现仍有疑问；
- 需要区分 Candidate、已验证候选和 Gold；
- 新实现输出与现有 Gold 不一致；
- 需要决定回归范围。

## 核心结论

“DOCX 能打开”“XML 合法”“截图相似”和“Word 中可反复填写、更新、保存”是不同层次的证明。任何一层通过都不能替代其他必要层。

验证证据必须绑定同一个候选 hash。不能用修改前的截图、另一渲染器的页数或另一份 Word 保存包证明当前文件正确。

## 当前任务应留下什么

- 结构、职责、填写行为、Word 视觉和包清洁五层结果；
- 每项修改对应的影响面和回归范围；
- 精确保持、授权语义保持、样式符合和行为符合的独立结论；
- 所有阻断项、人工确认和负向 fixture 结果；
- 当前产物为什么只能是 Candidate、已验证候选或可以进入 Gold。

## 1. 五层验证

### 1.1 结构完整性

检查：

- ZIP 和 OOXML 基本合法；
- 段落、表格、分节和包部件没有意外丢失；
- relationships、书签、脚注、批注和媒体可达；
- 单元首尾锚点和源块覆盖正确；
- 没有孤立字段、重复 Slot 或损坏引用。

结构通过只能证明文档机器结构基本一致，不能证明视觉和 Word 行为正确。

### 1.2 语义职责完整性

检查：

- 学校固定内容保留；
- 样例和教程按授权清除；
- 填写、生成、条件和人工职责仍有入口；
- 必填、可选和条件内容的状态正确；
- 未决内容没有被伪造或静默删除；
- 学生正文和授权规范化后的内容都可追溯。

### 1.3 模板行为

使用代表性输入验证：

- 标量、长值和空值能否填写；
- 段落流是否越过边界；
- 重复内容是否能正确扩展；
- 目录和引用能否更新；
- 条件页缺席是否正确；
- 保存并重开后接口是否仍唯一。

### 1.4 canonical renderer 视觉验证

最终交付面通常以 Microsoft Word 为准；用户明确指定 WPS 时以 WPS 为准。检查：

- 总页数和单元页数；
- 首锚点位置；
- 意外空白页；
- 标题换行、目录制表位和页码；
- 页面几何、页眉页脚和装订规则；
- 固定学校表格、封面、图表公式和共享页面区域；
- 裁切、遮挡、越界和异常留白。

LibreOffice 用于全页风险扫描，不能覆盖 canonical renderer 的冲突结论。

### 1.5 包清洁与交付一致性

检查：

- 不残留学生隐私、旧作者、自定义数据或未使用媒体；
- 清理过程没有破坏 Word 同次保存形成的跨部件一致性；
- 最终文件无恢复提示；
- 交付 hash、报告和截图指向同一个文件；
- 来源文件保持只读，最终重新检查来源 hash。

## 2. 区分不同的“保真通过”

不要把所有检查压成一个 PASS。

- **字节或逐字保持**：适用于未经授权不得改变的内容。
- **授权语义保持**：允许移除编号前缀、规范少量空格或迁移字段，但正文语义不丢失。
- **结构保持**：对象、顺序、关系和边界完整。
- **样式符合**：最终有效格式满足当前学校合同。
- **行为符合**：填写、更新、保存和重开仍正确。
- **视觉符合**：canonical renderer 中页面表现可接受。

如果授权转换导致逐字比较失败，应保留该 FAIL，同时新增“授权语义保持 PASS”。不能把严格检查改写成 PASS 来美化报告。

## 3. 修改影响面决定回归范围

| 修改内容 | 最小回归范围 |
|---|---|
| 普通文字清空 | 当前对象、相邻段落和完整页面 |
| 段落或容器删除 | 当前页、前后页、边界和固定邻居 |
| 表格或复合对象 | 全部成员、关系、跨页位置和相邻页面 |
| 基础样式或主题 | 所有使用者、正文能力样本、目录和固定表单 |
| 标题与编号 | 全文标题树、目录、页码、题注章节号和交叉引用 |
| 分节或分页 | 所有受影响节、页眉页脚、页码和空白页 |
| 字段缓存或 Word 保存包 | 完整包、所有目标字段、重开行为和隐私清理 |
| Slot 或条件策略 | 所有相关填写场景、空值和长值案例 |

不能只回归“这次准备修的目标”。南京农业大学修改目录自引用时同时影响标题格式，早期回归范围太窄，未能发现新增问题。

## 4. 负向回归比普通成功样例更重要

至少保存能够证明验证器会失败的负例：

- 湖南封面与诚信声明少一个或多一个顶部空段；
- 湖南任务书表格包装段形成伪空白末页；
- 北京大学独立单元残留 `oddPage`；
- PKU 短 H2 的目录点引导符错误；
- 命名样式正确但直接格式覆盖；
- 删除说明后没有留下填写接口；
- 条件页只删内容、未删分节；
- 书签起止 ID 不一致；
- 源顶层块缺失或重复；
- XML 合法但 Word 打开需要恢复。

负例要绑定预期失败原因。只保存“某次失败文件”而没有可复现判定条件，无法形成稳定回归。

## 5. Candidate、Verified 与 Gold

### Candidate

由程序或人工判断生成，证据可能只覆盖一个样本。Candidate 可以用于继续验证，但不能覆盖 Gold。

### 已验证候选

通过约定的结构、行为和 Word 视觉检查，但还可能缺少更大样本、外部人工确认或正式来源。

### Gold

只在项目已批准的范围内，由官方来源、人工确认和 canonical renderer 证据共同形成。至少绑定：

- 源文件和 SHA-256；
- 单元 manifest 或等价真值；
- Word 页数和页面证据；
- 自动验证结果；
- 人工确认范围；
- 版本和变更理由。

新实现输出不同不是更新 Gold 的理由。先把差异当作失败调查；只有新版官方模板、Word 原生证据证明旧 Gold 错误，或用户明确确认新定义时才修改 Gold。

## 6. 真实案例

### 案例 A：源块覆盖门发现 37 个顶层块丢失

一次模板处理局部单元都能打开，但全局审计发现 37 个源顶层块没有分配。经验：局部成功不能替代全局覆盖；同时还要检查边界所有权，防止块虽然被分配却归给错误单元。

### 案例 B：Word 包损坏绕过 ZIP/XML 检查

南京农业大学 student-003 的一个修复稿通过 ZIP、XML、目录样式和链接检查，但 Word 打开提示恢复。根因是从 Word 保存件零散移植字段缓存，造成跨部件状态不一致。

### 案例 C：目录静态截图通过，真实更新失败

北京大学短 H2 在静态缓存中看起来正常，Word 更新整个目录后点引导符异常。最终门必须包含目标应用更新和保存，不是只比较旧缓存截图。

### 案例 D：严格内容检查 FAIL 与语义保持 PASS 同时成立

北京大学试转换因授权编号规范化无法通过逐字严格比较，但语义规范化检查通过。报告保留两个结论，没有把严格 FAIL 改写为 PASS。

### 案例 E：Candidate 不能覆盖 Gold

北京大学 r02 根据人工成品反馈改变匿名条件页和 `oddPage` 处理，但 README 明确不直接修改旧 Gold。需要补足正式证据和验收后再讨论晋升。

## 7. 冻结前清单

冻结前确认：

- 所有来源和最终候选 hash 已记录；
- 所有必需职责已解析，未决项得到明确处置；
- 源块全部且仅分配一次；
- 填写和生成接口已做代表性往返测试；
- 字段、关系和对象闭包通过；
- canonical renderer 全部权威页面已检查；
- 所有意外差异有授权操作或阻断结论；
- 负向回归确实能被拒绝；
- 文档能在 Word 中无恢复提示打开；
- 隐私和包清洁检查通过；
- 当前证据足以支持 Candidate、已验证候选或 Gold 中的相应状态。

## 8. 未来开发预留

### VALIDATE-01：统一候选证据索引

- 将结构、语义、行为、渲染和包清洁结果绑定同一 hash；
- 防止混用旧截图、旧报告或其他渲染器结果；
- 保留机器阻断与 Agent 判断的区别。

### VALIDATE-02：影响面驱动回归选择

- 根据修改对象选择当前页、相邻页、相关节或全篇范围；
- 基础样式、编号、分节和字段包修改自动扩大回归范围；
- 选择结果可解释、可人工扩展。

### VALIDATE-03：负例夹具

- 将分页、目录、直接格式、条件节、关系和包损坏案例转成脱敏 fixture；
- 每个 fixture 有唯一预期失败原因；
- 不能把 Temp 中未经授权的真实学生内容直接产品化。

### VALIDATE-04：冻结门

- 独立重开候选和来源；
- 重验 hash、证据覆盖、机器阻断和人工审阅；
- 失败时不发布部分产物，也不自动刷新 Gold。

这些能力涉及正式验证和 Gold 范围时，需要新的用户批准计划。当前 M3 Eval、真实样本资格验证和外部人工复核仍不应被声称已经完成。
