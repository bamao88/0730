## 何时读取

只要任务涉及正文示例、章节样式、标题层级、图表公式、参考文献正文、缺失样式或国家标准补全，就读取本文件。

正文不能套用“复制一个单元、删除样例、留下几个字段”的简单逻辑。它是一个覆盖整篇论文内容表达能力的样式与结构系统。

## 核心结论

正文模板保存的不是五个示例章节，而是一套可反复应用于任意章节的能力：

- 不按“第一章、第二章、第三章”分别建立模板；
- 以语义角色和结构能力识别样式；
- 用一套最小但足够的代表性正文验证全部能力；
- 学校已定义的要求优先保留；
- 学校没有定义的属性保持缺失，等待确定性、可追溯的标准补全；
- Agent 识别角色、范围、冲突和缺口，不直接从记忆生成具体国家标准数值。

## 当前任务应留下什么

- 正文需要覆盖的标题、段落、字符、编号、对象和特殊分节能力；
- 每个能力由源模板哪个实例证明；
- 每个样式属性是已观察、缺失、冲突还是未决；
- 哪些重复章节可以删除，哪些独有能力必须留下；
- 哪些缺失属性未来需要确定性标准能力补全；
- 一套代表性正文的全局回归结果。

## 1. 正文与逻辑单元的关系

逻辑单元回答“这一段源模板能否安全独立处理”；正文能力回答“未来任意论文正文需要哪些可复用表达能力”。两者不能混为一谈。

- 一个 `body` 单元可以跨很多页、章节和分节；
- 一个源 `paper-body` 单元也可能物理上包含摘要、正文和后置示例；
- 正文内部的章起页、横向页和公式段落可以形成结构边界，但通常仍属于同一个正文职责；
- 只有独立学校表单、不同所有权或稳定处理边界才值得拆成新的交付单元。

因此，正文样式提取可以在一个较大的源单元内部完成，不要求先把每个语义角色拆成独立 DOCX。

## 2. 建立正文能力清单

不要假设所有学校都提供完整示例。先按当前材料观察下列角色是否存在、是否明确、是否冲突。

### 2.1 页面和分节能力

- 正文页尺寸、页边距、装订线；
- 页眉页脚、页码体系及首页差异；
- 章是否另页开始；
- 横向大表或特殊页面的分节；
- 分栏、连续分节和节间继承；
- 孤行控制、与下段同页、段中不分页。

### 2.2 段落角色

- 一级至五级标题；
- 无编号标题，例如结论、参考文献标题或附录内部标题；
- 普通正文；
- 首段、续段或特殊缩进正文；
- 块引用；
- 列表项；
- 图题、表题、公式编号；
- 图表注释、来源说明；
- 参考文献条目；
- 脚注和尾注正文。

不要因为学校只展示到三级标题，就自动断言四级、五级标题不存在。检查说明文字、样式库和样例章节；仍无证据时，把角色标为缺失或未决。

### 2.3 字符角色

- 中文正文；
- 西文、数字和变量；
- 强调、加粗、斜体；
- 上标、下标；
- 行内引用；
- 超链接和交叉引用显示文字；
- 术语、变量、单位和符号的直立或斜体要求。

字符样式清理与正文内容改写是两件事。清除异常 `w:spacing`、缩放和位置可以属于格式归一化；为英文科学名称补空格属于内容修改，必须有白名单、计数和独立保真检查。

### 2.4 编号与导航能力

- 多级标题编号；
- 章内编号重置；
- 列表编号；
- 图、表、公式编号；
- 标题大纲级别；
- 目录、图目录、表目录的入口；
- 书签和交叉引用目标。

标题文本与编号前缀必须分离。学生稿中的“第一章”或“1.2.3”是输入表现，不能直接当作目标模板编号机制。

### 2.5 复合正文对象

- 图片及其中英文题注；
- 表题、表格、英文表题、注释和来源；
- OMML 公式、编号和对齐结构；
- 浮动文本框、形状和锚点；
- 引文、参考文献条目和内部目标；
- 脚注标记与脚注正文。

正文样式体系必须覆盖对象成员之间的顺序和附着关系，不能只记录“题注字体”或“表格样式”。

## 3. 选择代表性正文，而不是复制所有章节

### 选择原则

保留能够覆盖不同能力的最小样本：

- 至少一个章、节、小节层级链；
- 只有材料确实支持时才加入 H4/H5；
- 普通正文、列表、强调和引文；
- 一组图片和题注；
- 一组表格和题注；
- 一个可编辑公式；
- 一个脚注或交叉引用；
- 一个真正改变页面几何的特殊分节。

删除只重复相同能力的第二章、第三章等样例，但保留其曾证明的独有能力。删除前先做能力差异比较，不能只比较章节标题。

### 代表性正文的目标

它用于验证未来样式和机制是否可复用，不是供学生照抄的论文内容。清理后应把示例文本替换为明确、最小的能力测试内容或槽位，不保留学校无关的完整论文叙述。

## 4. 按属性观察实际样式

对每个语义角色分别收集：

- 命名样式和 `basedOn` 链；
- 文档默认值和主题；
- 段落直接格式；
- Run 直接格式；
- 编号和列表属性；
- 表格、单元格和分节属性；
- 最终有效字体、字号、粗体、斜体、对齐、缩进、段前段后、行距、分页控制；
- 该属性的来源、范围和置信状态。

样式名只帮助检索。名为“标题”的样式不一定对应论文标题；名为“正文”的段落也可能被直接格式覆盖。

### 属性状态

对每个角色的每个属性区分：

- `observed`：模板存在有效值；
- `missing`：当前学校材料没有给出；
- `conflict`：同范围的正式要求与模板有效显示不一致；
- `unresolved`：对象范围或适用条件不清楚。

不要把整个样式标成“存在”后忽略局部缺失。例如 H2 可能已定义字体和字号，但没有明确段前距或章起页关系。

## 5. 正文样式解析顺序

### 第一层：当前任务事实

保留学校说明、用户确认和模板观测。冲突时不静默覆盖，逐属性暴露给 Agent。

### 第二层：模板有效实现

学校说明没有写明但正式模板有稳定可见实例时，可以把有效实现作为当前任务证据，同时记录它是“模板观测”而不是“规范明文”。

### 第三层：确定性标准补全

只有以下条件同时满足时，未来程序才可补全缺失属性：

- 已选择明确的国家级标准标识和版本；
- 有适用性证据证明该标准覆盖当前论文类型和属性；
- 对应条款有明文值；
- 当前学校和用户要求没有冲突。

标准无明文、不适用或存在冲突时保持未决。不得用“常见论文一般这样”生成默认值。

国家标准规则应作为 Tool/adapter 内部版本化数据维护，不进入 Agent 可直接照抄的经验表，不形成学校 profile，也不新增第六个公共 Tool。

## 6. 整体样式系统一致性

正文样式不能逐个孤立写入。每次形成候选样式体系时检查：

- H1–H5 的继承关系没有意外把粗体、缩进或语言字体传给下级；
- 正文和题注不会继承标题的分页控制；
- 中西文字体、主题字体和直接字体覆盖一致；
- 标题编号、大纲级别和目录层级一致；
- 章起页关系独立于标题视觉样式；
- 固定行距不会裁切公式、上标或复杂对象；
- 表格样式不被表级、行级或单元格直接边框覆盖；
- 参考文献悬挂缩进与正文引用目标一致；
- 横向节恢复到后续正常页面几何；
- 修改公共基础样式后的影响面得到全局回归。

“某一段看起来正确”不能证明整个正文样式体系正确。需要用代表性正文同时覆盖继承、编号、对象和分页。

## 7. 真实案例

### 案例 A：北京大学五章合并为一套正文能力

原模板提供多个示例章节。复盘发现它们重复展示相同能力，因此合并成一套代表性正文，覆盖 H1–H5、正文、列表、强调、引文、图、表、公式、字段和交叉引用。只有横向页面因为真实改变页面几何而保留为独立能力样本。

经验：按能力差异去重，而不是按章节名称保留。

### 案例 B：南京农业大学动态第三章没有另页开始

标题段落的字体、字号和间距都正确，但动态插入的第三章没有从新页开始。原因是只迁移了标题视觉样式，没有迁移章级页面关系。

经验：标题样式和结构关系分开观察；章起页可能由 `pageBreakBefore`、分节或装配规则承担。

### 案例 C：小标题后的正文被错误换页

学生稿的偶然分页被复制到目标模板，小标题后的正文被拆开或继承了错误对齐。正文流应跟随所属标题连续排版，只在学校确认的章级或特殊结构边界分页。

### 案例 D：样式名正确但直接格式仍错误

早期模板把段落设置为目标样式，但旧 Run 的直接字体、粗体、字符间距和缩放仍覆盖样式。必须计算最终有效值并清理非语义覆盖，不能把 `style_id` 匹配当作验收。

### 案例 E：固定正文行距裁切 OMML 公式

南京农业大学 student-002 中，固定 20 磅行框无条件作用于公式段，导致分数线和上下标被裁切。最终保留 OMML，可编辑公式段使用不会裁切的行高策略，公式前后正文仍保持学校节奏。

经验：正文基准行距不能无条件覆盖含高对象的段落。

### 案例 F：参考文献不是普通正文列表

参考文献既有条目段落样式，也有连续编号、悬挂缩进、稳定书签和正文引文链接。只把段落套成普通正文会破坏多行对齐和引用闭包。

### 案例 G：湖南农业大学 `paper-body` 不妨碍内部样式识别

Gold 因缺少可靠物理边界，把题名、摘要、正文、参考文献、致谢和附录示例合并为一个 `paper-body`。样式提取仍可在该源范围内识别不同语义角色；不能反过来为了样式分类强行切出不稳定的 Word 单元。

## 8. 正文候选验收

至少准备以下测试内容：

- 短、中、长 H1/H2/H3；材料支持时加入 H4/H5；
- 两个连续章节，验证编号和章起页；
- 多段正文和列表；
- 中西文混排、强调、上标和下标；
- 图片、表格、公式及其题注；
- 参考文献条目、正文引文和内部跳转；
- 横向节后恢复正常页面；
- 空值、长值和重复内容。

检查：

- 所有角色都有明确的学校观测、标准解析或未决状态；
- 没有用经验默认值填满缺口；
- 每个章节复用同一套样式机制；
- 标题编号、目录层级和交叉引用一致；
- Word 中无裁切、异常分页和继承污染；
- 删除重复示例后没有丢失独有能力。

## 9. 未来开发预留

下面是正文专项开发的能力分解，不承诺具体文件格式、函数名或公共 Tool API。

### BODY-01：正文语义角色与能力覆盖报告

- 从样例章节、说明文字和样式库列出可观测角色；
- 报告 H1–H5、正文、列表、图表公式、引用和特殊分节的覆盖状态；
- 标出重复能力和仅出现一次的独有能力；
- 不自动删除章节。

### BODY-02：有效样式解析

- 解析 `docDefaults → 主题/样式继承 → 段落直接格式 → Run 直接格式`；
- 对字体、字号、粗体、对齐、缩进、间距、行距和分页控制逐属性报告；
- 识别表格、编号和分节层的覆盖；
- 输出事实和冲突，不决定语义角色。

### BODY-03：样式角色绑定与缺口清单

- 由 Agent 将源对象绑定到正文语义角色；
- 生成属性级 `observed/missing/conflict/unresolved` 清单；
- 保留来源 hash、对象引用和适用范围；
- 不把样式相似度当作语义身份。

### BODY-04：国家标准确定性补全

- 仅使用批准的标准标识、版本、条款和适用性输入；
- 输出属性级来源和规则集 digest；
- 无明文或有冲突时保持未决；
- 作为现有 Tool/adapter 的内部能力，不向 Agent 暴露可直接套用的国家标准数值表。

### BODY-05：代表性正文编排

- 根据已确认能力选择最小样本；
- 合并重复章节，保留独有对象和特殊分节；
- 为正文、标题、图表公式等建立可填写或生成接口；
- 修改前后保持源内容和对象关系可追溯。

### BODY-06：整体样式回归

- 用能力矩阵生成或选取测试段落；
- 检查样式继承、编号、目录入口、分页、公式裁切和表格边框；
- 在 canonical renderer 中验证全局影响面；
- 将失败定位到角色、属性、来源和页面。

开发前需要单独批准计划，并确认标准授权、版本维护、适用性输入、冲突语义和契约测试。当前代码不应被描述为已经具备这些能力。
