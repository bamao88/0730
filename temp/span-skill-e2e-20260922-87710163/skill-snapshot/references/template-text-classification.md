# 模板文字分类

## 用途

帮助 Agent 判断模板文字在当前学校材料中的业务责任，尤其区分固定内容、条件固定内容、
学生填写位置、说明/格式指导和生成内容。结论用于决定保留、清理、绑定接口或继续读取上下文。

## 触发条件

- 固定文字、说明、示例值或填写位置难以区分。
- 同一段落同时包含标签、空白、示例值或格式说明。
- 颜色、括号、下划线、空白或样式名看起来像提示，但无法单独证明其身份。
- 删除说明或样例前，需要确认该责任已经有安全承载位置。

## 核心判断规则

先问“填写后，这里应该显示什么，哪些文字仍须保留”，再判断当前原文各部分承担什么责任。
颜色、括号、位置、空白或 Word 样式名只是线索，不能单独决定结论。

### 五类责任

| 类别 | 含义 | 通常处理 |
| --- | --- | --- |
| 固定内容 | 校名、制度原文、固定标签、区域标题、表格骨架 | 保留文字与版式 |
| 条件固定内容 | 仅对某院系、语言、学位或条件成立 | 保留条件和依据；不自行裁决未知条件 |
| 学生填写位置 | 需要真实学生值替换的空白、提示或示例所在位置 | 选择对应的 Registry 字段 |
| 说明/格式指导 | 约束其它内容或说明模板用法的文字 | 保留有效要求，再清理说明文字 |
| 生成内容 | TOC 缓存、自动编号、题注或交叉引用结果 | 保留生成机制，按来源对象刷新 |

无法证明时先标记未知并取证，而不是把“不确定”统一变成保留或删除。

### 输出 role 词表

按输入原文的可见顺序划分 parts。`role` 回答“这个片段承担什么责任”；需要填写、正文或生成字段的
片段才选择 `field_id`。原文关联由当前输出格式提供。

| role | 含义 | 后续依赖 |
| --- | --- | --- |
| fixed_label | 学校固定标题、标签、正文、表格骨架或制度文字 | 不写字段；样式随固定内容保留 |
| fill_slot | 学生可变值的填写位置，含已有内容控件、下划线、空白、待替换提示或示例值 | 只能选择 `usage_affordance.allowed_part_roles` 含 `fill_slot` 的字段 |
| cleanup | 模板作者说明、删除提示、示例写作文本或不应进入干净模板的缓存文字 | 删除前确认规则或填写责任已有其它 part 承载 |
| style_only | 字体、字号、缩进、日期格式、目录层级等样式/格式义务 | 不写字段；说明它约束的内容，保留要求与保留说明文字分开判断 |
| manual_region | 签名、盖章、教师评语、审批表等人工填写区 | 默认不写学生字段 |
| body_structure | 正文标题、段落、图表公式列表等正文代表成员 | 只能选择 `usage_affordance.allowed_part_roles` 含 `body_structure` 的字段 |
| generated_content | 目录、编号、题注、交叉引用或域结果 | 只能选择 `usage_affordance.allowed_part_roles` 含 `generated_content` 的字段 |

`field_id` 只属于需要 Registry 字段的 ordered part。固定标签、清理、人工区、样式说明或普通布局片段
不因为文字像字段名就绑定字段；需要字段但词表没有安全项或该字段不允许当前 role 时返回 `needs_input`
或改用正确 role。

### 同块混合责任

part 是原文中责任和处理方式一致的连续片段。相邻文字即使没有空格，也可以在责任变化处拆分；
同段、同单元格或同 run 不影响语义边界。每个 `text` 取自输入原文，所有片段按顺序拼回该段原文。
这是对原文的一次分类；填写后的显示文字由宿主生成。

先在上下文中找出一个完整值的真实位置，再用该字段的一个正常值想象替换：固定标签和正式内容应
仍然存在，相邻的独立值应各归其位，同一个填写位置不应出现两份相同的值。若效果不对，先修正
原文范围或责任判断，再选字段；“这一行与某字段有关”不足以把整行作为填写位置。

固定标签旁已有独立值位置时，标签保持 `fixed_label`，字段只绑定值位置。标签分隔符不进入填写
片段，可随相邻固定文字表达，无需把每个标点单独拆开。同样的文字也可能是待替换提示：若它独占
最终值的位置且另无填写区，就按填写责任判断，不能因为看起来像字段名而固定保留。

提示或示例是否承担填写责任，取决于它在页面上的用途，不取决于它是否像字段名称、是否含空白。
已有可替换文字时，该文字就可能是填写位置；相邻留白也可能只是间距。实际姓名、职称等示例属于
值的内容，字体、字号、居中等说明属于格式义务；字段对应承担该值的文字，值间的间隔按布局关系判断。

格式说明先按以下顺序判断，不因带括号就删除，也不因邻近值就并入值：

1. 值的前面、后面或旁边有独立说明时，说明单独分类并说明约束对象。已有完整值位置，不能再给
   说明建立同一字段接口；尾随说明也不因与占位紧挨着而吞入填写范围。
2. 只有同时满足以下条件时，才把夹入说明的连续范围作为一个字段接口：前后占位共同承载同一个
   完整值；说明位于该值的占位内部且只约束这个值；范围内没有必须保留的标签、正式内容或另一个
   独立值。此时把前后占位拆成两个接口会重复填写同一个值，整体选择适用的 `fill_slot` 或
   `body_structure`，并在 `reason` 记录内联说明义务。
3. 若说明两侧本来就是不同字段，或两个各自完整的填写位置，按各自责任分别判断；不能为了减少
   part 数量合并。证据不足以分辨时补相邻上下文或页面线索，不套用内联说明例外。

同一填写区的续行留白可能只是为一个完整值预留空间，只在真实值位置建立一个接口，其余留白保留
布局责任。另一个独立位置确实需要再次显示同一完整值时才属于镜像。字段含义、复合值和镜像的
选择见 [Registry 与接口绑定](registry-interface-binding.md)。

“空一行”“空三行”等版面指令描述的是应保留的垂直间距，文字本身按 `style_only` 判断，不作为
`fixed_label` 留在最终正文。模板若明确声明 `□` 等符号只代表字宽、缩进或空格，应把这些符号与
相邻正式标题或标签拆开为 `style_only`；符号承载的布局义务保留，符号字面不进入最终内容。
跨页或真实镜像位置仍分别判断。“填写全称”等内容形式要求
也需保留其含义；“某某学院”“研究员”等示例是否可变，依据其填写责任判断。正式名称本身的括号
仍与名称一同保留。说明中的有效要求与说明文字是否显示分开判断。

### 成对示例：上下文、原文 parts 与填写效果

以下字段名称只说明责任，实际 `field_id` 必须来自当前词表，且词表允许相应角色。每行的原文片段
按顺序拼回输入原文，每字恰好出现一次。假想填写值仅用于检查效果，绝不进入输出的 `parts[].text`。

**固定标签与独占题名提示。** 文字是否像字段名不能决定它的处理方式。

| 上下文与输入原文 | 按原文顺序的 parts | 假想填写效果 |
| --- | --- | --- |
| 表格一行含固定标签和独立填写线：`论文题目：________` | `论文题目：` → `fixed_label`；`________` → `fill_slot`（论文题目） | 填入“城市雨水利用研究”后显示 `论文题目：城市雨水利用研究`，标签保留。 |
| 封面中央的题名位置，另无填写区：`论文题目（小二黑体）` | `论文题目` → `fill_slot`（论文题目）；`（小二黑体）` → `style_only`（题名字体要求） | 该位置只显示 `城市雨水利用研究`，用小二黑体排版；不保留题名提示。 |

**尾随格式说明与占位内部说明。** 先确认哪里承载一个完整值，再判断说明是否位于其内部。

| 上下文与输入原文 | 按原文顺序的 parts | 假想填写效果 |
| --- | --- | --- |
| 一个题名填写位置，说明位于完整填写线末尾：`题目：________（小二黑体）` | `题目：` → `fixed_label`；`________` → `fill_slot`（论文题目）；`（小二黑体）` → `style_only`（题名字体要求） | 显示 `题目：城市雨水利用研究`，题名使用小二黑体；说明无需进入填写范围。 |
| 页面证据确认两段线共同组成一个题名位置，说明插在占位中间：`题目：____（小二黑体）____` | `题目：` → `fixed_label`；`____（小二黑体）____` → `fill_slot`（论文题目）；在 `reason` 说明题名使用小二黑体 | 同样只显示 `题目：城市雨水利用研究`；不能把左右两段线各绑定一次，变成两份题名。 |

**两个独立值与一个复合值。** 相邻关系不能代替词表中的内容含义。

| 上下文与输入原文 | 按原文顺序的 parts | 假想填写效果 |
| --- | --- | --- |
| 姓名与职称分别填写，词表分别提供两字段：`指导教师：某某副教授` | `指导教师：` → `fixed_label`；`某某` → `fill_slot`（导师姓名）；`副教授` → `fill_slot`（导师职称） | 姓名为“陈宁”、职称为“教授”时显示 `指导教师：陈宁教授`；没有空格也可按独立值拆分。 |
| 学校要求合写一个年级专业班级值，词表提供对应复合字段：`年级专业班级：20××级××专业×班` | `年级专业班级：` → `fixed_label`；`20××级××专业×班` → `fill_slot`（年级专业班级） | 复合值为“2026级环境科学专业2班”时显示 `年级专业班级：2026级环境科学专业2班`；值内部的“级、专业、班”随整个骨架替换。 |

这些示例说明判断方法，不是见到相同文字就套用的答案。若输入已经将标签和值分成不同条目，分别
判断各自原文，不把相邻条目的文字抄入当前 part。

### 人工表单与使用说明

固定声明或制度文字可整体保留。声明正文、作者签名和年月日骨架同属人工签署责任时，相应范围按
`manual_region` 整体判断，不拆成一组失去人工填写能力的固定文字。

任务书、开题报告、评阅、答辩、成绩及审批表需区分学生基础信息与记录、签名、盖章、评语等人工
责任。不能因为整页或整表属于人工表单，就忽略相邻标签和独立值位置证明的学生字段；“记录、
签名栏手工填写”等要求只约束明确点名的区域。当前词表有语义匹配字段时，学生基础信息位置按
`fill_slot` 判断；材料明确将整表或该位置交给人工填写时，才保持相应人工责任。

论文或文档提交时间只承担提交时间。评阅、签署或审批日期不得绑定提交时间字段，没有专用字段时
保持人工责任。变更原因、审批意见、现场记录或签署内容没有语义匹配的专用字段时，也保留人工
责任，不借用题目、专业、正文等近似字段；表单容器不是正文代表结构。

未预选的复选或单选选项是等待使用者选择的表单能力，按 `manual_region` 保留；不得因当前没有
勾选就判为 `cleanup`。复选框符号若承担真实选择功能，也不适用表示间距的符号清理规则。

下载来源或填写方式属于模板使用说明。说明所指的人工责任已经由对应 parts 承载后，说明文字通常
按 `cleanup` 判断；只有学校材料明确要求读者在最终表单中看到这些说明时才保留。不能清理说明的
同时丢掉它要求保留的签名、勾选或人工填写能力。

### 判断顺序

1. 查看当前范围的原文、相邻语义块、文档顺序和必要的页面线索，理解此处最终用途。
2. 确认填写后仍须显示的正式文字、每个完整值的位置和说明的作用对象；必要时比较模板其他区域。
3. 查看 `field_id_vocabulary` 中每个字段的 `label`、`meaning`、`content_type` 和 `cardinality`。词法匹配是候选，不是结论。
4. 检查要求文件是否明确该文字的身份或适用条件。
5. 页面布局参与语义时查看原生页面或局部图像。
6. 用正常值想象替换已选择的范围，复核标签、独立值、说明义务和接口数量，再给出原文分类与判断依据。

### 清理前闭合责任

删除说明或样例前，明确它证明的学生内容责任将由哪个保留对象承载。若删除后只剩固定标题、空容器
或无法填写的页面，说明责任尚未闭合。优先在真实样例对象上建立接口；没有样例时，才复用说明
所在的合适版式位置。

## 反例

- 看到彩色或括号就清理：正式名称中的括号仍是名称，颜色也可能只是正式内容的样式。
- 把 `20 年 月 日` 按“年、月、日”拆成多个日期接口，或因缺少纯空白而整体固定：它可能是一个
  完整提交日期的值骨架，应结合用途判断。
- 在说明段和真实样例段各建一个相同字段接口：两段若只描述一次填写责任，接口应落在真实内容版式。
- 把内容控件可见的 `【字段名】` 当残留样文清理：它是既有填写界面，仍承担填写责任。

## 不负责事项

- 不定义工具参数、编辑动作或运行时完整性协议。
- 不替代 Field Registry 的字段含义，也不新增 Registry 字段。
- 不记录某所学校样本的最终结论；每次结论都必须回到当前材料判断依据。
