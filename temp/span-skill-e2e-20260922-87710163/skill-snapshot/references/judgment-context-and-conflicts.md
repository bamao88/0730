# 判断依据、对象安全与冲突

## 用途

帮助 Agent 判断当前可读上下文是否足以支持学校语义结论，并在模板、要求、布局结果或 Registry
含义冲突时选择继续读取上下文，或以 `needs_input` 说明会改变当前结论的缺口。

## 触发条件

- 学校模板、要求文件、截图或用户说明彼此不一致。
- 同一对象可能有多种语义解释，且不同选择会改变最终 Word。
- 样式事实、对象边界或布局影响无法只靠结构文本确认。
- 运行环境给出机械反馈后，需要回到语义上下文重新闭合判断。

## 核心判断规则

### 依据层级

只依据当前任务的学校模板、书面要求、官方示例和用户确认。Knowledge 和本 Skill 只提供方法，
不能提供某所学校的具体规则。

一项学校结论只有在适用对象/条件明确、必要布局关系已查看且同范围冲突已处理时才算确认。
模板与书面要求不一致时同时保留两类依据；只有材料明确优先级或用户裁决时才消解冲突。

### 最小问题原则

先比较相邻文本和模板其他相关位置，读取当前学校要求、必要的页面线索和输入词表中的字段含义。
只补充会影响当前判断的证据；post-unit 语义判断不委派。仍无法判断且两种选择会产生不同最终文档时，
返回 `needs_input`，说明冲突的依据、会改变结果的选择和缺失上下文，由宿主衔接后续补充。

### 有效样式

可见格式可能来自默认值、段落/字符样式链、主题和直接格式。判断正式/说明色由 Agent 负责；执行时
给出期望有效结果，不要指挥工具删除某一层 OOXML。后续物化是否成功由宿主复核，不做无语义的
全文颜色清洗。

### 结构边界

从可见文本、相邻内容和布局关系确定语义范围：哪些文字要保留，哪些是待替换的值，哪些是说明，
以及应保留什么分页、留白或表单责任。范围内责任不同时按原文拆分 parts，不需要选择底层编辑对象。
宿主负责关联文档结构、保护编辑边界和执行修改；收到反馈后，只复核受影响文本及上下文是否符合
已表达的语义意图。

若一段内容被整体判为清理，其中却有应保留的标签、填写位置或有效格式要求，先修正语义范围，
分别表达应清理的文字和仍需承载的责任。语义已经一致但宿主无法安全执行时，由宿主处理执行问题，
不要为了消除执行冲突而改掉有证据的语义判断。分页缓存只是历史缓存，不能单独证明逻辑分页。

## 反例

- 模板正文和学校要求冲突时，只选择更容易编辑的一方。
- 因为缩略图看起来正常，就跳过会影响样式或对象边界的局部上下文。
- 对一个会改变最终文件的问题仍然猜测完成，而不是用 `needs_input` 说明最小证据缺口。
- 收到机械失败后，把 failure code 当成学校语义结论。

## 不负责事项

- 不定义 Harness 覆盖协议、工具参数或发布门禁。
- 不保存具体学校的 Gold 结论。
- 不替代对象/布局安全专题 Reference；遇到复杂边界时应读取对应文件。
