# Registry 与接口绑定

## 用途

帮助 Agent 把学校模板中的填写责任绑定到当前 unit packet 里已经提供的 `field_id_vocabulary` 字段，
并在无法绑定时判断是否需要 `needs_input`。它约束语义选择，不定义 Registry 格式本身。

## 触发条件

- 标签、空白、示例值或内容控件需要确定对应哪个 Registry field。
- 同一字段在多个视觉位置出现，或一个视觉位置包含多个学生责任。
- Registry 词法命中但含义不完全匹配。
- 学校材料证明了填写责任，但 Registry 没有可安全承载的字段。

## 核心判断规则

原文分段的主规则见 [模板文字分类](template-text-classification.md#同块混合责任)，其中包含标签与
题名提示、尾随说明与内部说明、独立值与复合值的成对示例。本专题在已经理解的填写责任上选择
字段；不因某字段存在而扩大原文范围，也不以字段匹配代替分段判断。

- 先判断学校责任，再从 `field_id_vocabulary.allowed_field_ids` 中选择字段；字段名、label 或词法相似只是候选。
- 只有 `parts[].role=fill_slot`、`body_structure` 或 `generated_content` 且确实需要可执行字段时才写 `field_id`；
  字段还必须在 `usage_affordance.allowed_part_roles` 中允许当前 role。固定标签、清理、人工区、
  样式说明和普通布局不需要字段绑定。
- 字段须匹配片段承担的内容含义、content_type、cardinality 和允许角色。当前视觉位置用于理解片段的
  责任，不能仅凭页面名称决定字段匹配；实际适用条件仍以学校材料和字段定义为准。
- 固定标签不绑定学生字段；只在可变值或真实填写承载位置上建立接口。
- 学生基础信息出现在人工表单中也可能有匹配字段；先按
  [人工表单与使用说明](template-text-classification.md#人工表单与使用说明) 确定当前具体位置的责任，
  再选择字段。表单名称既不证明整表都可自动填写，也不证明所有位置只能由人工处理。
- 表单中没有匹配字段的行政或现场信息继续保持人工责任或返回 `needs_input`：地点不能绑定研究方向，
  记录人不能绑定学生或导师姓名。用正常字段值替换后若标签与值读起来不是同一内容，字段就不匹配。
- 论文或文档提交时间字段只承担提交时间；评阅、签署或审批日期不得绑定该提交时间字段，没有
  专用字段时保持人工责任。它们发生在不同事件中，不能因为都含“日期”而复用同一个值。
- 字段 label 不必与模板逐字相同；模板写学院、词表写院系或培养单位时，应结合 meaning 判断为同一组织单位责任。
  学院、院系或培养单位的同义变化不能被当作字段不存在。
- 独立值与复合值由内容含义和词表共同决定。姓名与职称需要不同字段时分别绑定，即使原文紧挨着；
  学校要求一个完整复合值，且当前词表提供覆盖其全部内容的复合字段时，整个复合值骨架只建立一个
  接口。复合字段覆盖年级、专业和班级时，不能只把年份片段绑定复合字段，再把专业或班级的占位
  保留成固定文字；也不能把原本独立的责任强行合并来迁就复合字段。
- 同一行的标签和值位置分别判断；一个位置没有匹配字段，不能吞掉同一行另一个已有匹配字段的填写责任。
- `cardinality` 描述字段承载一个值还是一个集合，不根据样例行数推断。集合字段承载整组内容，
  代表条目与其余格式样例的选择见 [集合与可选区](collections-and-optional-sections.md)。
- 变更原因、审批意见或签署内容没有语义匹配的专用字段时保持人工责任；不得借用题目、专业或正文对象字段。
  表单容器不是正文代表结构，不能因为底层是表格就绑定正文表格字段。
- 同一字段只在多个位置承载同一完整值时才是镜像；不同时间状态或不同预期值不是真实镜像，不能复用
  一个单值字段来表达变更前后、申请值与审批值等不同责任。
- 一个视觉位置包含多个字段责任时，各自选择语义匹配字段。底层能否安全写入由宿主处理；只有责任
  本身不明确且会改变字段选择时，才补上下文或返回 `needs_input`。
- 同一 Registry field 可以在多个学校要求的真实位置出现；一个位置已绑定不自动抵扣另一个位置。
- 同一个值的续行留白只延长填写空间，不增加字段责任；它与另一个独立位置再次显示同一完整值的
  镜像不同。先按 [模板文字分类](template-text-classification.md#同块混合责任) 确认实际位置，
  不能为保留行宽、预留换行空间而重复绑定或借用其他字段。
- 学校材料已证明填写责任而词表没有合适字段时，保留该责任，以 `needs_input` 说明内容与字段缺口。
  字段无法绑定不证明原文是固定文字或可清理说明；不能为适配词表而反向改变角色，也不能复用近似字段。
- 准备写“没有可安全字段”前，必须检查当前 unit packet 的 `field_id_vocabulary`；不要用记忆、
  旧样例或词法猜测判断字段存在。
- 当前输入词表中的正文容器和正文成员字段只用于正文代表结构的 `body_structure` parts。它们不是附录、
  参考文献、致谢、摘要或普通说明段落的通用填空字段；这些区域没有安全输入词表字段时，
  返回非执行判断或 `needs_input`，不要用正文段落类字段凑数。

### 字段判断顺序

1. 结合功能区、相邻文本和学校要求，按文字分类专题确认哪些原文片段承担填写责任。
2. 按每个片段的内容含义选择输入词表中的字段，并确认内容类型、数量和允许角色匹配。关键词、
   参考文献、致谢、附录等集合或段落同样需要语义匹配；没有合适字段时说明缺口。
3. 将姓名、职称等不同值的责任分别表达；学校要求一个复合值且词表有对应复合字段时，保留一个接口。
4. 用所选字段的一个正常完整值检查填写效果：固定标签仍成立，字段含义与预期内容一致；需要
   调整原文范围时回到文字分类专题，格式说明的责任仍需保留。

## 反例

- 把声明页手签日期复用为封面提交日期，只因为两者都含“日期”。
- 只因开题报告或任务书表格里出现“学生姓名/学号/毕业论文题目”标签就绑定字段，未确认相邻独立值位置；
  或反过来只因它是表单，就忽略材料已经证明的学生基础信息填写位置。
- 把导师姓名和职称合并成一个字段，因为它们在同一段落里相邻。
- 看到“学院”二字就绑定 department，忽略该处其实是固定校名或表格栏标题。
- Registry 支持 many，就为每个样例类别建立一个独立字段，而不是保留集合接口。
- 把标签行后的留白和紧邻的续行空白都绑定成同一字段，只因为两处共同形成较宽的书写区。
- 把附录、参考文献说明、致谢段落或摘要说明绑定成正文字段，只因为它们也是段落。

## 不负责事项

- 不新增、删除或重命名 Registry 字段。
- 不定义内容控件、占位符或编辑工具的参数。
- 不决定最终内容填写阶段如何从学生内容模型取值。
