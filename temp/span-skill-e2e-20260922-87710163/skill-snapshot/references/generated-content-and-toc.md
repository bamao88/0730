# 生成内容与目录

## 用途

帮助 Agent 判断目录、题注、编号、交叉引用和字段缓存哪些应作为学校生成机制保留，哪些只是过期
可见结果，避免把缓存文字当成真实内容。

## 触发条件

- unit 已被识别为目录、图目录、表目录或其它生成清单，需要进入局部范围拆解。
- 目录、图目录、表目录、题注、交叉引用、编号或字段缓存需要清理或刷新。
- 可见目录项与当前标题树不一致。
- 学校标题层级与 Word 样式名、编号外观或字段缓存存在冲突。
- 需要说明 LibreOffice 布局上下文与 Microsoft Word 原生字段更新之间的边界。

## 核心判断规则

目录、题注和交叉引用由固定外壳、字段指令、来源对象、关系、结果样式与当前显示缓存共同组成。
可见缓存只是历史结果，不是内容真值。

目录单元在主流程里先被识别为生成区；具体 `generated_mechanism` 判断必须落到
`reading_block` / `range_id` 层，而不是作为 unit-level terminal keep 结束。

目录 unit 下钻时不能只套用通用生成区抽象。先把学校固定外壳、真实生成机制、结果样式、可见缓存
和来源标题族分开；它们可以落在不同 block/range，也可以在同一 block 内用有序 `parts` 表达。

### 快速路由摘要

- 目录 unit 下钻先分离固定外壳、真实生成机制、结果样式、可见缓存和来源标题族。
- 生成机制必须落到 `source_entry_id` 对应文本的 `generated_content` part，不以 whole-unit terminal keep 结束。
- 目录缓存文字不保留为正文内容，但缓存 range 必须由 `generated_content` part 接管，并且只在 `field_id_vocabulary` 中存在目录字段时写 `field_id`；不要只删除缓存，也不要把生成机制只挂到将删除的格式说明上。
- 可见目录缓存只是证据，不是正文标题树；没有来源标题族和层级证据时返回 `needs_input`。
- 样式名、编号外观或旧缓存不能单独决定 TOC level；必须结合学校材料和正文代表结构。
- 目录 generated judgment 仍是普通 `source_entry_id + parts` 输出；不要输出旧的目录专属对象形状。
- 只有可见目录缓存行或真实目录字段范围可以成为 `generated_content` part；固定“目录”标题、空行说明、分支标签和格式说明
  仍是普通 part，不得为了满足 generated area 要求把它们标成目录生成内容。

### 目录输出结构

目录单元的输出不是普通字段槽，也不是正文成员列表。每个可执行目录缓存或真实目录字段范围输出一条
ordinary judgment，范围用 `source_entry_id` 表达；目录语义用
`generated_content` part、输入词表字段和 `reason` 表达：

```json
{
  "source_entry_id": "source-entry-toc-cache-row",
  "parts": [
    {"text": "1 前言 ........ 1", "role": "generated_content", "field_id": "输入词表中的目录字段"}
  ],
  "reason": "这是可见目录缓存。来源标题族、收录层级、编号样式、结果样式和刷新依据来自当前学校材料；旧缓存只作证据。"
}
```

`reason` 中说明进入目录的来源语义字段和 TOC level；字段 ID 只能引用本轮 `field_id_vocabulary` 中已经存在的值。
同一目录有多套学校分支时，每个分支各写一条 generated judgment，并在 `reason` 中说明适用条件。
固定“目录”标题、空行说明、分支标签和格式说明仍按普通 judgment 单独覆盖；不要把它们塞进
generated-content part 代替范围 owner。
如果一个目录相关 unit 只包含固定标题、空行或格式说明而没有目录缓存/字段范围，该 unit 仍输出普通
fixed/layout/template-note judgment，不输出目录生成 part；目录生成 part 应落到同页或相邻目录样例中的缓存/字段范围。

### TOC 方法

1. 保留学校固定“目录”标题、真实 TOC 字段和学校展示的分级样式。
2. 先完成最终保留的固定标题、正文代表结构和可选区；不要用旧缓存反推尚未完成的语义。
3. 从最终标题树选择应进入目录的来源标题族，并由你为每个来源指定 1–3 级。不要假设所有固定标题
   必须进入，也不要让代码通过标题词或编号正则代选。
4. 在 `reason` 中写清来源标题族与目标层级。宿主负责后续刷新和机械更新，不替你选择
   目录来源。
5. 对目录样式写清应保留的语义预期，例如标题、缩进、点引导线、页码占位、颜色和下划线。
6. 目录缓存 range 是生成机制的载体。不要把生成机制只写在要删除的格式说明 judgment 上，再把所有
   缓存条目单独标成 cleanup；缓存条目应由 `generated_content` part 接管，并从输入词表选择目录字段。
7. 如果只能看见旧目录缓存，先标明它是缓存证据；没有来源标题族和层级证据时返回 `needs_input`，
   不要用普通 generated-content 标签或自然语言总结凑完整。

若一级节标题和二级节标题共用一个 Word 样式，但学校通过编号、缩进或关系表达两级，仍可为它们
选择不同 TOC level。反之，样式名或 `1.1` 外观本身也不能脱离当前材料决定语义。

### 原生 Word 边界

LibreOffice 渲染适合风险扫描，但不能完全证明 Microsoft Word 更新域后的精确结果。交付复核由
宿主完成；Agent 只判断目录来源、层级和应保留的学校显示关系。不要用全局字段更新误伤声明、
引用或其他域。

清理题注、书签、编号或交叉引用附近对象时，把可见文字与字段/关系边界分开看；只删除缓存文字
可能破坏机制，只保留缓存而丢掉来源也不算完成。

## 反例

- 直接根据旧目录缓存删除标题，忽略标题树尚未完成。
- 让代码按标题词、编号正则或样式名自动决定目录层级。
- 只保留“目录”可见文字而删除真实字段，导致后续 Word 无法更新页码。
- 全局更新所有字段，误伤声明、引用或其他非目录域。

## 不负责事项

- 不定义目录刷新工具的参数或执行细节。
- 不决定最终内容填写阶段的学生标题树生成策略。
- 不把某次 LibreOffice 渲染结果提升为 Microsoft Word 原生字段更新的绝对证明。
