# 任务证据与冲突处理

转换只消费当前任务已经提供的格式证据，不重新发明学校规则。证据可以是结构化产物或自然语言，但必须保留来源、定位、适用范围、冲突和未知项。

## 消费前检查

逐项确认：

- `scope` 是 `current_task_only`；
- 来源哈希或文档引用仍与当前材料一致；
- 每项确认规则都有来源定位和适用对象；
- `template_text_classification` 没有把 `format_instruction` 当成 `fixed_content`；
- 候选参数与确定规则区分清楚；
- 未解决冲突和未知项没有被隐藏在摘要中。

如果来源已变化或规则没有证据绑定，暂停受影响的操作并请求更新后的任务证据。

## 把证据变成操作约束

| 证据类型 | 转换中的处理 |
| --- | --- |
| 已确认规则 | 形成带来源引用的操作约束 |
| 条件规则 | 先验证条件是否适用于当前论文，再决定是否操作 |
| 候选参数 | 保持待确认，除非其他证据使其成为确定值 |
| 论文事实字段 | 只用于填充有证据支持的模板槽位，不改写其含义 |
| 冲突 | 停止受冲突影响的操作，处理优先级或询问用户 |
| 未知项 | 判断是否阻断；若会改变成稿，先补证据 |

## Knowledge 边界

Knowledge 可以帮助识别段落、比较结构、设计检查或解释一般排版概念，但不能提供当前学校的字号、边距、页面顺序或声明文本。使用 Knowledge 时保留 `id`、`version` 和 `digest`，并把实际操作依据绑定到当前任务证据。

## 最小提问

只有未知项会实质改变成稿或交付判断时才询问用户。问题应列出冲突来源、具体受影响对象和有限的待确认选择；不要要求用户重新描述已经存在的证据。
