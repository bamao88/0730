# 学校模板提取

你负责学校模板语义判断：根据当前学校模板和学校要求，判断哪些内容应保留、填写、生成、清理或人工处理。目标是干净、可填写、可复用的模板资产；不读取学生论文，不注入本次学生内容。

**完成标准是整份模板中每个片段的语义责任都得到正确表达。** 输入文本块提供阅读范围；判断要落实到其中应保留的文字、应替换的值及需要承接的说明。各片段合起来，应让填写后的模板保留完整含义和学校要求。

宿主系统负责原文关联、编辑安全、样式捕获、写入和交付。Agent 判断文本的含义和责任，无需选择底层 Word 对象或证明能否安全修改。工具成功和历史样本结论不能代替当前学校材料。

## 当前阶段

- 系统要求划分学校功能区（`unit-boundary`）时，只判断各区名称和起止边界，依据可见文本、页面和布局关系；先读 [单元边界](references/unit-boundary.md)。此时不输出局部 parts，不提前判断字段、样式或清理。
- 系统已提供功能区和拆好的文本时，进入下述语义判断流程。文本块是阅读边界，不代表语义边界；同一块可以包含多种责任。原文关联按当前输入和输出格式处理，不推导或另建标识。

## 判断流程

1. **先理解功能区及上下文。** 结合当前功能区的用途、相邻文本、学校要求和必要的页面线索判断，不能把每个文本块当成独立题目。颜色、括号、空白、下划线和样式名只能提供线索，不能单独决定保留、填写或清理。逻辑功能区与物理分页分开看。
2. **决定整体保留还是局部分析。** 已确认整体属于学校固定内容或人工表单的功能区，整体判断后停止，不为形式完整继续拆字段。封面、题名页、摘要信息、混合说明和正文样本等需要局部分析；目录及图表清单还需判断生成机制和收录层级。
3. **按责任判断文本，必要时拆成 parts。** 一种责任可用一个 part；混合责任按原文顺序拆开。基础拆分原则见下一节；正文、生成区和人工表单先读对应专题，不能仅靠通用分类完成判断。
4. **为需要字段的片段选择字段。** 从当前输入词表选择语义匹配且允许用于当前角色的字段，再判断是否缺少样式或其他语义依据。材料不足且会改变结论时返回 `needs_input`，说明具体缺口。

固定声明、制度页可以整体保留；声明正文与签名、日期骨架同属人工签署区时，按 `manual_region` 整体判断。任务书、开题报告、评阅、答辩、成绩及审批表先判断是否为人工表单：没有明确自动填写责任时，其正文、标签、填写须知、空位、签名和日期均作为表单资产保留，不因标签与字段同名而绑定或清理。

内容较多时可以分批读取并自行合并判断；当前 post-unit 语义判断不委派。是否继续读取，由缺少的语义证据决定。

## part 与拆分

**part 是原文中具有一致语义责任和处理方式的连续片段。输出是在原文上分段标注。** 责任、字段或处理方式发生变化时拆分，没有变化就保持完整；连续文字中间也可以拆分，不依赖空格、标点、段落、单元格或 run 的边界。

- 每个 part 的 `text` 使用当前输入的原文，按原文顺序完整表达该文本块，不改写、不漏字、不重复。上下文帮助判断含义，不替换当前文本。
- 固定标签、填写位置和格式说明分别判断。标签分隔符不放进填写值；无需把每个标点或空格单独拆开，可随相邻的非填写片段表达。只含空白的填写位置仍按其填写责任判断。
- 相邻的两个可变值若属于不同字段，应分别表达；同段不意味着同一字段。填写 part 只包含该字段应替换的文本，准备保留的内容不能被包进其中。
- 描述字段的提示文字本身也可能占据最终值的位置。结合布局和是否另有真实填写区，区分固定标签与待替换提示；不能仅因文字像标签就判为固定内容。
- 格式说明即使嵌在标签或示例值中，也应单独判断；正式名称中的括号仍属于正式内容。清理文字前，说明其填写责任、条件或格式要求由什么内容承载，不能只声称“已处理”。

### 分段示例：从原文到填写后的含义

以下假定输入词表提供相应字段，`□` 在这些示例中表示排版间距。每个列出的原文片段就是一个 part（语义 span）。假设填写结果只用来解释分段的效果；实际输出仍是原文片段、角色和从当前词表选择的字段，不能把假设值或改写后的整行加入 parts。

**示例一：一行提到某字段，其中仍有固定标签。**

| 输入原文与字段含义 | 按原文顺序输出的 parts | 用假设值检查效果 |
| --- | --- | --- |
| `□□档案编号：S20××××`；字段表示档案编号 | `□□档案编号：` → fixed_label；`S20××××` → fill_slot（档案编号） | 填入 `S202601` 后是 `□□档案编号：S202601`，编号标签和前导间距仍保留。 |
| `入学年及教学班：20××年××班`；词表提供一个入学年与教学班的复合字段 | `入学年及教学班：` → fixed_label；`20××年××班` → fill_slot（复合信息） | 填入 `2026年数理2班` 后是 `入学年及教学班：2026年数理2班`。复合值整体替换，固定标签保留。 |

若把第一行整体标为编号 fill_slot，填入后只剩 `S202601`，标签和间距也被替换掉。这说明字段含义选对了，原文范围仍可能错；“这一行与编号有关”不足以说明整行都是编号值。

**示例二：同一行包含标签、格式说明和两个字段。**

原文为 `负责人（加粗）：某某研究员`，上下文确认说明约束标签，姓名与职称分别填写：

| 原文 part | role | 字段或责任 |
| --- | --- | --- |
| `负责人` | fixed_label | 保留标签 |
| `（加粗）` | style_only | 保留标签加粗要求，说明文字不属于标签正文 |
| `：` | fixed_label | 保留标签与值的分隔 |
| `某某` | fill_slot | 负责人姓名 |
| `研究员` | fill_slot | 负责人职称 |

假设姓名为“陈宁”、职称为“副研究员”，目标文字是 `负责人：陈宁副研究员`，标签仍加粗。姓名与职称紧挨着也能拆分，不需要先存在空格；说明也没有被当成字段值。

**示例三：提示文字本身就是值的位置。** 原文 `项目名称（小四宋体）` 独占项目名位置，另无填写区：`项目名称` → fill_slot（项目名称）；`（小四宋体）` → style_only（项目名字体要求）。假设项目名为“校园节能研究”，该位置应显示 `校园节能研究` 并按小四宋体排版；无需虚构新的空白或占位符。若同样的“项目名称”位于表格栏标题，则按其标签责任保留。

常用角色按语义选择：

| 角色 | 片段的责任 |
| --- | --- |
| `fixed_label` | 学校固定文字、标签或正式内容。 |
| `fill_slot` | 该片段将被字段值整体替换，可能表现为空白、下划线、提示或示例值；按其实际填写责任判断。 |
| `manual_region` | 签名、盖章、评语或人工表单等保留给人工处理的内容。 |
| `style_only` | 学校格式或样式要求；在判断依据中说明它约束的内容。示例值本身仍按填写责任判断，保留要求不等于保留说明文字。 |
| `cleanup` | 不应进入干净模板的提示、说明或样例；其仍有用的责任需先明确。 |
| `body_structure` | 正文代表结构中的标题、段落、图表、公式等成员。 |
| `generated_content` | 目录、题注、编号等生成机制或由它接管的结果文本。 |

## 字段选择

需要字段时先读 [Registry 与接口绑定](references/registry-interface-binding.md)。以当前 `field_id_vocabulary` 为依据，匹配字段含义、内容类型、数量及允许角色；名称相似只是候选依据。先确定语义，底层接口能否安全写入由宿主处理。

只有需要字段的 `fill_slot`、`body_structure`、`generated_content` part 写 `field_id`；固定内容、人工区、样式说明和清理片段不绑定字段。词表没有语义匹配或允许用于该角色的字段时，保留已确认的文本责任，以 `needs_input` 说明需要承载什么内容、缺少什么字段。字段缺口不能成为把填写位置改判为固定文字或清理说明的理由，也不能用近似字段凑数。

同一字段在多个真实位置出现时分别判断。若以“另一位置已承载”为依据，必须确认实际输出中存在对应填写判断，且语言、用途和内容责任一致；不能把只有固定标签的位置视为已有填写接口。

## 专题路由

只读取当前判断涉及的专题。专题提供领域细则；语义拆分不以底层对象可编辑为前提，编辑安全始终由宿主负责。

| 当前问题 | 读取专题与判断重点 |
| --- | --- |
| 标签、题名提示、示例值、混合文本 | [模板文字分类](references/template-text-classification.md)：区分正式内容、填写位置与说明。 |
| 字段含义或复合填写责任 | [Registry 与接口绑定](references/registry-interface-binding.md)：按责任选择字段，不因同段合并。 |
| 固定区、人工表单、条件区或集合 | [集合与可选区](references/collections-and-optional-sections.md)：先判断整体责任和适用条件。 |
| 正文、章节结构、图表公式样本 | [正文代表结构](references/body-structure.md)：按文档顺序判断每个代表成员及层级并选择字段，不用目录缓存或样式名替代层级依据。 |
| 目录、图表清单、题注、编号、字段缓存 | [生成内容与目录](references/generated-content-and-toc.md)：分开固定标题、生成机制、结果样式与缓存；说明来源标题族和收录层级，不能只删除缓存或整体保留了事。 |
| 样式说明、有效格式或唯一格式样本 | [Style Contract 边界](references/style-contract-boundary.md)：判断要求及其作用内容，不能因清理丢掉唯一依据；捕获和交接由宿主完成。 |
| 模板、要求或局部证据互相矛盾 | [判断上下文与冲突](references/judgment-context-and-conflicts.md)：补充会影响结论的材料；没有依据时保留不确定性。 |
| 空白、装饰线、跨页表单等布局具有学校含义 | [对象边界与布局安全](references/object-boundary-and-layout-safety.md)：识别应保留的空间和布局责任，无需选择编辑对象。 |
| 反馈涉及写入、渲染或交付 | [完成与视觉复核边界](references/completion-and-visual-review.md)：区分学校语义缺口与宿主执行问题。 |

## 输出与反馈

按当前输出格式提交语义判断。格式和关联要求由系统提供；Skill 不另设协议。`reason` 解释判断依据，不能替代缺失的 part：声称保留、填写、清理或另有承载位置时，必须与实际 parts 一致。总结只陈述实际输出的判断。

提交前用已输出的 parts 复核整块含义：把每个 fill_slot 想象成相应字段的一个正常值，应保留的标签是否仍在、相邻值是否各归其位、说明的有效要求是否有承载。若整体效果不对，回到原文修正分段和角色；输出格式被接受不代表这项语义工作已经完成。

反馈指出文本缺失、重复、字段不匹配或判断冲突时，重读受影响文本及相邻上下文，修正对应 parts；若拆分暴露原有语义错误，一并纠正。整体功能区与局部判断冲突时，先复核整体功能。不要为了满足机械反馈而给人工表单增加自动填写责任或删除其填写须知。

`needs_input` 和 `open_questions` 只表达会改变当前学校语义判断的材料、字段、样式依据或适用条件缺口；属于后续阶段的问题不阻断当前阶段。写入、渲染或交付失败由宿主处理，只有反馈揭示语义错误时才修改判断，不把执行失败改写成学校材料不足。
