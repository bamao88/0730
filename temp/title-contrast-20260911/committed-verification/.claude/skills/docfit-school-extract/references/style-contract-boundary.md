# Style Contract 边界

## 用途

帮助 Agent 区分模板提取阶段应保留和交接的学校样式事实，与最终内容填写阶段才会执行的样式选择。
Agent 只判断样式事实是否属于学校模板语义；Style Contract 的捕获、定位和交付由宿主完成。

## 触发条件

- 学校模板展示了正文、标题、图表、公式、列表、参考文献或表单样式样本。
- 样式名、直接格式、主题、默认值或视觉结果给出不同信号。
- 清理说明/样例可能导致学校样式事实没有承载位置。
- 当前模板没有某类学生内容的学校样式，需要判断是否留给最终内容填写兜底。

## 核心判断规则

- 学校明确展示的样式事实应随对应代表范围或接口保留。
- 样式事实来自有效显示关系与结构上下文的组合，不只来自 Word 样式名。
- 清理样例前，确认同类样式能力仍有承载范围；不能为了干净删除唯一学校样式依据。
- 模板提取不统一全篇格式，不做无语义的颜色、字体或行距清洗。
- 学校没有依据的内容类型，不在模板提取阶段发明样式；由后续最终内容填写选择通用兜底。
- Style Contract 交接的是“下游可依赖的样式事实与缺口”，不是学生正文的最终排版实例。

## 反例

- 因为正文样例是红色说明文字，就把全部正文样式都改成黑色后再当作学校样式事实。
- 只保留标题文字，删除唯一能证明段前段后、编号或字体关系的代表段落。
- 样式名叫 `Normal` 就认定它不是学校正文样式。
- 模板没有公式样例时，提前为公式设计最终样式。

## 不负责事项

- 不决定最终内容填写的兜底样式、冲突合并或学生内容排版策略。
- 不定义样式编辑工具参数。
- 不作为跨学校样式规范；每次必须依据当前学校材料。
