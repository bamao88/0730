# 单元边界

## 用途

帮助 Agent 按学校功能划分模板单元，形成可覆盖、不可重叠、可交接的判断范围。单元边界用于组织
语义判断和后续复核，不是运行时状态或编辑顺序。

## 触发条件

- 模板很长，需要先拆成封面、声明、摘要、目录、正文、附录、表单等功能区。
- 一个页面、表格或分节同时承载多种学校责任。
- 页眉页脚、页码、装饰线、印章位或跨页表格影响多个功能区。
- 后续局部分析需要可复用的 unit 范围，主 Agent 必须先给出明确边界。

## 核心判断规则

- 先按学校功能划分，再给出足以定位开始和结束的可见边界。
- 每个 unit 只需要 `unit_id`、`unit_name`、`start_boundary`、`end_boundary`；边界内容可包含可见起止文本、页码或页面区域。
- 边界应覆盖当前判断需要的真实对象，包括标题、包装段、页眉页脚、表格外壳、字段和锚点。
- 同一对象不能被两个单元同时拥有；跨单元依赖应显式记录，例如目录依赖最终标题树。
- 字段、生成、样式、删除和清理责任只作为后续 post-unit 判断，不作为 unit-boundary 输出要求。
- 边界证据不足时返回顶层 `needs_input`；不要把字段、样式、清理或后续 open questions 放进 unit 输出。
- 边界不清会影响最终文件时，先补可读上下文或缩小问题；不要用页码粗分掩盖职责冲突。

## 反例

- 把第一页永久等同于封面，忽略第一页还包含声明或页眉页脚规则。
- 每个表格行都拆成独立单元，导致同一个表单骨架的固定责任被重复判断。
- 正文样例、目录来源和目录缓存互相依赖时，只在目录单元里处理全部问题。
- 只给“第 3 页”作为边界，没有可见起止文本或区域线索。

## 不负责事项

- 不定义 Harness 覆盖检查、状态推进或 payload 字段。
- 不规定工具 inspect/edit 的参数。
- 不保存当前学校的最终单元清单；每次任务必须从当前模板材料生成。
