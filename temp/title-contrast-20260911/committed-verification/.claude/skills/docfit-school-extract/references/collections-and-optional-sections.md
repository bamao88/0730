# 集合与可选区

## 用途

帮助 Agent 判断参考文献、成果、致谢、附录等集合或条件区域应该保留为一个可填写能力、拆分为多个
接口，还是作为不适用区域清理。

## 触发条件

- 模板存在多条参考文献、成果、附录样例或同类条目。
- 某区域可能不是每篇学生论文都出现，但出现时学校给出了格式责任。
- 固定标题、说明文字和真实条目混在一起。
- 删除可选区域前，需要确认该能力不适用或已有替代承载位置。

## 核心判断规则

### 集合

Registry 的 `cardinality=many` 通常表示一个接口内部承载多条数据，不表示“每种样例类别一个槽”。
对参考文献、成果等区域：

- 先判断固定标题/地标覆盖的逻辑集合边界；
- 选择一个能代表本校真实条目版式的对象作为集合接口；
- 删除同一集合中的其他类别标签和条目实例；
- 只有新地标、独立容器或明确学校规则证明另一个独立责任时，才建立第二个接口。

若只有说明而无真实条目，说明仍证明内容责任；在合适的正文位置建立接口后清理说明，不能留下
无承载能力的固定标题。

### 致谢与附录

- “致谢”通常是固定标题；从真实正文样例保留当前输入词表中表示致谢正文的接口，再清理其余样文。
- “附录”固定标签与学生标题同段时，保留标签，只在可变标题对象上建立当前输入词表中表示附录标题的接口；
  另用真实内容样例建立当前输入词表中表示附录正文的接口。
- 若附录没有真实内容样例，可复用说明段的正文位置作为 body，但不要把说明文字保留下来。
- 多个连续 run 共同承载一个学生值时，应形成一个逻辑接口，而不是按文字碎片制造多个槽。

### 可选区

把“最终论文是否一定出现”与“出现时如何填写”分开。学生可选并不意味着模板中应删除该能力；
学校材料未明确排除时，保留结构并提供接口。只有材料明确该条件不适用，才删除整区，同时复核
分节、分页、页眉页脚和后续页面。

任何保留区域都要责任闭合：不能只剩孤立标题、空节或没有填写承载的表格。具体字段组合来自当前
学校材料与 Registry，不是本 reference 的跨学校清单。

## 反例

- 因为成果区域列出“论文、专利、获奖”三类样例，就建立三个互斥接口，而不是一个成果集合能力。
- 把“致谢”标题和学生正文合成一个字段，导致下游无法保留固定标题。
- 只因为学生论文可能没有附录，就删除学校明确展示的附录能力。
- 删除参考文献说明后只剩空标题，没有保留任何可填写条目版式。

## 不负责事项

- 不列出跨学校固定字段清单；字段组合必须来自当前学校材料和 Registry。
- 不定义最终内容填写如何展开 many 条目。
- 不规定工具删除、替换或包装集合对象的参数。
