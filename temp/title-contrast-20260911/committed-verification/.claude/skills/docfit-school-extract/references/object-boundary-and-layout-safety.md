# 对象边界与布局安全

## 用途

帮助 Agent 识别文本之外的学校布局责任，例如空白、图片、表单框架和分页关系。Agent 判断哪些内容
与空间应保留，底层对象选择和编辑安全由宿主处理。

## 触发条件

- 目标对象附近有表格、图片、文本框、页眉页脚、分节、分页、字段、书签、脚注或批注。
- 固定标签、学生值和说明在同一行，布局关系影响它们的含义。
- 删除父对象会影响子对象，或包装段同时承载布局和内容。
- 视觉位置、空白、装饰线、印章位或表单框架本身具有学校责任。

## 核心判断规则

- 按可见文本与布局关系表达最小必要的语义范围；文字同段或紧密相邻不限制语义拆分。
- 布局对象可能没有学生内容，但仍承担视觉或空间责任；不要因为无文字就删除。
- 同一区域既有应清理的说明又有应保留的内容时，分别表达责任及预期布局。
- 历史分页缓存、旧截图或旧检查结果不能决定当前语义。
- 编辑失败由宿主处理；反馈若揭示原文含义或布局关系判断有误，再修正语义结论。
- 任何影响布局的语义处理都要写清相邻结构与页面预期；后续复核由宿主完成。

## 反例

- 删除一个看似空白的段落，却同时删除图片锚点、分页或页眉页脚边界。
- 把表格边框当装饰清理，实际破坏学校表单骨架。
- 只判断示例值，遗漏同一单元格里相邻说明和其它填写位置的责任。
- 用 `lastRenderedPageBreak` 或旧截图单独判断当前逻辑分页。

## 不负责事项

- 不定义 OOXML 变更算法、工具参数或权限策略。
- 不替代完成阶段的最终全页视觉复核。
- 不决定学生内容最终如何运输对象；这里只判断模板提取阶段的内容与布局责任。
