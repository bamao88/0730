# 通用论文领域母稿

> 状态：内容与结构领域盘点初稿
>
> 目标：为论文转换上下游提供一组可识别、可传递的通用语义锚点、候选字段和经验入口，再决定如何投影为正式 Knowledge。
>
> 重要边界：这里列出的是“可表达范围”，不是任何学校的必需目录、默认格式或现有公共 Schema。
> 本轮范围：暂不建立语义样式角色、样式属性目录、继承链或任何字体字号等具体样式；只固定后续“样式观测与确定性补全合同”的职责边界。

## 1. 建模目标：提供协作语言，而不是规定 Agent 怎样工作

DocFit 后续要解释不同学校的模板和要求，也要把学生论文安全地映射到目标结构。如果缺少
一份共同的领域母稿，Agent、Knowledge、Tool 和 Eval 容易分别形成不同的论文对象理解。

这份母稿的首要目标，不是要求 Agent 把每个任务完整序列化为本模型，更不是要求 Agent
按照模型中的目录、字段顺序或处理模式逐步工作。它先把已经确认会反复出现的论文内容、
关系、状态和风险命名，为不同阶段提供可选择的公共语言：

- 论文内容在语义上是什么；
- 内容通常由哪些单元和字段构成；
- 模板中什么位置可以承接这些单元；
- 不同来源和所有权的内容应当保留、填充、生成、移除还是交给人工；
- 未知、复合、审阅中和非正文对象怎样无损保留；
- 哪些关系需要验证，哪些差异必须由当前学校证据决定。

### 1.1 字段是跨阶段接缝，不是必填表单

这里的字段首先是一份**可表达能力清单**。上游在检查源论文或学校材料时，可以只产出
当前有证据、有下游用途的字段；下游在绑定、修改、样式判断或验证时，也只消费与当前
问题相关的字段。没有被使用的字段不需要为了“模型完整”而填充，无法确认的内容可以保留
为未知或候选，不得为了符合模型而猜值。

因此，这个模型希望形成的是弱耦合的语义接缝：上游和下游可以用同一个锚点讨论
`object.caption`、`object.note` 或 `binding.edge`，但不要求它们共享一份巨大的强制对象、
固定序列化格式或固定工作流。Agent 仍可使用自然语言、页面观察、局部结构和其他中间表示
完成推理；只有在稳定字段有助于传递、复核或复用时，才把判断投影到这些锚点上。

### 1.2 模型帮助 Agent 认出“这是什么”，不替学校决定“它应该怎样”

模型提供从当前材料中的具体内容回到通用概念的入口。理想使用方式是：

```text
当前学校材料中的具体内容
  → 识别或候选映射到通用语义锚点
  → 按锚点读取相关通用经验
  → 结合当前任务的声明、结构观察和页面证据作出局部判断
  → 只把下游需要的字段、关系和证据继续传递
```

例如，Agent 在某校模板中看见一个中英文图题区域，可以将其理解为两个相互配对的
`object.caption`。这个识别让 Agent 知道应该检查语言、配对关系、相对顺序、与图形主体的
邻接以及相关样式证据；它不意味着图题必须出现在图形上方或下方，也不意味着应当使用
某种字体、字号、段前距或对齐方式。位置、顺序、必需性和物理样式仍由当前学校证据决定。

### 1.3 经验是按语义锚点检索的条件性参考

正式 Knowledge 未来除了提供概念和字段，还可以围绕稳定 `semantic_id` 组织通用经验。
经验的职责是让 Agent 在认出某类内容后，快速知道有哪些信号值得看、有哪些常见变体和
风险、哪些问题需要验证；经验不是目标值、学校规则或自动执行指令。

经验条目至少需要表达以下概念，具体存储形式留到正式 Knowledge 设计时决定：

| 经验概念 | 回答的问题 |
|---|---|
| 适用锚点与条件 | 这条经验与哪些语义对象、文档范围和前提有关 |
| 可观察信号 | 可以从文字、结构、样式、页面和上下文看什么 |
| 常见变体 | 同类对象通常可能以哪些合法形态出现 |
| 风险与歧义 | 哪些相似对象容易误判，哪些内容不能静默改写或丢失 |
| 建议检查项 | 为形成或验证当前任务结论还应检查什么证据 |
| 禁止推断 | 哪些位置、顺序、样式值或学校事实不能从通用经验直接推出 |

样式是一个需要单独收紧的特例。Knowledge 可以告诉 Agent“识别某类语义对象时应检查哪些
样式事实”，例如段落样式、直接格式、最终生效格式、对齐、段前段后、行距以及同页关系；
但它不向 Agent 提供字体字号默认值、学校样式库或缺失值补全经验。样式事实的解析、缺失检查
和有依据补全由后续“样式观测与确定性补全合同”约束，不能从通用经验直接产生目标值。

### 1.4 明确不追求什么

本模型不追求：

- 成为 Agent 必须逐字段填写的完整表单或思考步骤；
- 成为跨所有组件强制共享的公共 Schema、内容总线或工作流状态机；
- 穷尽所有论文对象，或把未知内容硬塞进最接近的已知类型；
- 规定某类内容必然位于某个位置、遵循某种顺序或使用某个样式；
- 用历史学校案例替代当前学校证据，或者把经验直接升级为学校规则；
- 因为模型中存在某个字段，就要求每个上游都生产、每个下游都消费。

它的价值不在于直接驱动运行时，而在于成为后续拆分工作的同一上游：

```text
通用论文领域母稿
  ├─ 为 Knowledge 提供统一概念、经验索引和方法来源
  ├─ 为未来按需数据投影提供字段盘点依据
  ├─ 为 Tool/Eval 提供可选择的对象和风险覆盖清单
  └─ 为学校任务提供“差异填充”，而不是重新建模
```

## 2. 总体领域模型

### 2.1 稳定语义层：产品词汇与任务内逻辑实例

稳定语义层回答“论文里是什么”，但其中存在两个不同稳定范围：`semantic_id`、`node_kind`
和 `relation_kind` 是随产品 Knowledge 版本发布的通用概念词汇；所有 fact/unit/ref/object
实例统一使用的 `instance_id` 以及关系实例的 `relation_id` 只在一次授权任务的文档谱系内稳定，用来续接源文件、工作副本和候选文件中
仍被判断为同一逻辑对象的内容。二者都不能由某次 DOCX 检查得到的 locator 代替。

任务内论文实例由一棵主阅读顺序树、若干附着内容子树和三个侧向注册/关系视图组成：

- 主内容树只保存实际占据论文主阅读位置的区域、单元、内容块和行内节点；
- 附着内容子树保存脚注、尾注、页眉页脚等拥有自身内部顺序、但通过锚点依附于主内容或节的内容；
- 共享事实注册表保存题名、作者、日期等可被多个位置引用的唯一语义真值；
- 关系图保存引文、交叉引用、事实引用、生成依赖和其他非包含关系；
- 保留对象注册表保存批注、修订、未知部件等不能靠主阅读顺序完整表达的对象。

这些视图通过语义身份和任务内实例身份连接，但不能伪装成同一种父子关系。稳定语义层不保存
目标学校的具体字体、字号、页边距、Word style ID，也不保存某次 Tool 检查得到的临时定位器。

### 2.2 当前任务投影层：证据、位置与处理状态

当前任务投影层回答“在这份源文件、模板或候选文件里观察到了什么，以及当前准备怎样处理”。
它把稳定内容实例投影到当前文档 hash 下的 `object_ref`、节引用、文字锚点或页面证据，并
附加任务证据、置信度、冲突、候选绑定、处置判断和验证结果。

文档发生编辑后，旧快照定位器失效；任务内实例身份只在重新识别有足够证据时继续作为
对照锚点。Agent 必须检查新快照并建立新的投影，不能仅因 ID 已存在就假定对象仍相同。
任务投影不会写回产品通用 Knowledge。

### 2.3 模板树与绑定：目标位置和当前任务适配

模板树描述当前目标模板中的固定区域、可填写位置、容器、重复区域、生成字段、条件区域和
手工区域。它是逻辑视图，不等同于 DOCX 原始 XML 节点树。

绑定把稳定内容实例或共享事实映射到模板节点，并说明填入、追加、重复、生成、保留或人工
处理等结构行为。绑定属于当前任务投影，不拥有内容真值，也不能根据模板外观反向改写已经
确认的内容语义。

### 2.4 样式边界：后续建立“样式观测与确定性补全合同”

样式负责“怎样呈现”，但这里需要的不是给 Agent 阅读的样式知识库，也不是一套通用默认
样式。后续独立产物统一称为**样式观测与确定性补全合同**：它规定 Agent、Tool 和确定性程序
怎样交接样式事实、语义绑定、缺失属性、标准条款和最终来源，不规定 Agent 的推理流程。

目标数据流是：

```text
模板 DOCX
  → Tool/程序完整解析可观察样式
  → Agent 判断这些样式观察分别属于哪个语义对象
  → Tool/程序检查完全展开后的每个样式属性是否缺失
  → 仅对缺失属性匹配具有明确版本、条款和适用范围的国家标准
  → 仍无依据的属性保持 unresolved，不生成通用默认值
```

职责固定为：

- Tool/程序展开 Word 命名样式继承、直接格式、主题/默认值和最终生效格式，并记录完整
  `source_chain`、覆盖状态、缺失属性和冲突；
- Agent 识别“中文图题”“一级标题”“表下注释”等语义对象，把当前模板样式观察绑定到
  已确认的 `semantic_id`；`semantic_id` 是 Agent 的语义判断，不是 Tool 从样式外观自动推出的事实；
- Agent 可以报告模板中观察到的字体、字号、行距等事实，但不能生成缺失属性值；
- Agent 只获得应该检查哪些样式事实的方法，不获得字体字号默认值、学校样式库或补全经验；
- 国家标准规则如果以后实现，应作为现有 Tool/程序内部版本化、可追踪的确定性数据，
  不是 Agent-facing Knowledge，也不是第六类产品资产；
- 当前任务必须先用证据确认适用的标准、版本、条款范围和对象条件，程序只匹配已确认的
  适用条件，不能根据学校名或外观自行决定规范适用性；
- 国家标准未覆盖的属性保持 unresolved，交给用户确认或继续使用已经真实存在的模板继承结果，
  不能再增加一层“通用基础样式”或模型猜值。

合同只需要两类逻辑记录。下面是语义草图，不是现有公共 Schema。

模板观察：

```yaml
style_observation:
  subject_ref: <当前模板快照中的对象>
  semantic_id: object.caption
  observed_properties: {}
  source_chain: []
  coverage_status: observed | partial | unavailable | conflicting
  missing_properties: []
  conflicts: []
```

其中 `observed_properties` 和 `source_chain` 由 Tool/程序产生，`semantic_id` 在 Agent 完成
语义识别后绑定；`missing_properties` 只能在继承、直接格式、主题和默认值已经完整展开后计算，
不能把“当前节点没有直接写这个属性”误判为缺失。

程序解析后的目标样式：

```yaml
resolved_style:
  semantic_id: object.caption
  applicability: {}
  properties: {}
  property_provenance:
    font_family:
      source_kind: template
      source_ref: <模板观察引用>
    font_size:
      source_kind: explicit_school_requirement
      source_ref: <学校要求证据引用>
    line_spacing:
      source_kind: national_standard
      standard_ref: <标准版本与条款引用>
  standard_refs: []
  unresolved_properties: []
```

`property_provenance` 必须逐属性记录来源，至少区分模板直接值、模板继承计算、明确学校要求、
国家标准和用户确认；每项来源还必须能指向当前模板证据、学校要求证据、用户确认，或带版本
与条款的 `standard_ref`。只给最终值而没有逐属性来源的 `resolved_style` 不可用于修改或验证。

正确的补全规则只有一条：

> 模板完整展开后仍缺失 → 检查当前任务已确认适用的国家标准 → 有明确条款才补 →
> 没有明确条款则保持 unresolved。

本轮不定义具体样式属性目录、国家标准规则表、存储 Schema 或 Tool 参数；正式实现前仍需按
00–06 协调更新 Tools 与数据设计，并保留现有五类资产和 Agent/Tool 判断边界。

## 3. 通用论文领域锚点与内容结构

本节是整份母稿的主视图。后续章节只解释语义锚点、内容节点、侧向关系和验证方式，不另建
一套论文目录。对象目录中使用统一紧凑标记：

```text
节点名 `semantic_id` <节点类别> [候选基数；典型来源角色；安全倾向]
```

- 节点类别分为 `fact`（论文级事实）、`unit`（实际文档单元）、`ref`（对事实的引用）、
  `object`（单元内部拥有的内容对象）和 `relation`（不表示包含的连接）；
- `├─` / `└─` 表示拥有或包含，`→` 表示引用另一个节点但不重复拥有其值；
- 基数是通用候选范围，不是学校必需性；
- 所有权和默认处置只是概念目录中的候选提示；当前实例的实际判断放入 `task.projection`；
- `*` 表示开放重复，`+` 表示至少一个，`?` 表示可选，`1` 表示当前父节点下的唯一逻辑节点。

### 3.1 母稿总览图（分层与投影，不是包含树）

```text
产品通用概念词汇 `docfit.thesis_domain`（随 Knowledge 版本发布）
├─ 语义角色目录 `semantic_id catalog`
├─ 节点形态目录 `node_kind catalog`
├─ 关系边词表 `relation_kind catalog`
└─ 识别方法、解释原则、处理模式与验证覆盖
            │ `semantic_id` / `node_kind` / `relation_kind` classify
            ▼
当前授权任务的语义工作区 `task.semantic_workspace`
├─ 任务内论文逻辑实例 `thesis.model`
│  ├─ 主阅读顺序树 `thesis.primary_flow`
│  │  ├─ 前置内容 `thesis.front_matter`
│  │  ├─ 正文内容 `thesis.body`
│  │  └─ 后置内容 `thesis.back_matter`
│  ├─ 附着内容子树 `thesis.attached_flow*`
│  ├─ 论文级共享事实注册表 `thesis.facts`
│  ├─ 非包含关系图 `thesis.relations`
│  └─ 审阅与未知保留注册表 `thesis.preservation`
├─ 当前目标模板逻辑树 `template.document`
├─ 当前任务投影 `task.projection`
│  ├─ 当前任务证据账本 `task.evidence`
│  ├─ 来源结构与表示 `projection.structure_and_representation*`
│  ├─ 处理判断覆盖 `task.decision_overlay*`
│  ├─ 快照—逻辑实例映射 `projection.snapshot_map*`
│  ├─ 论文实例/事实实例 → 模板节点 `binding.edge*`
│  └─ 验证记录 `task.validation*`
└─ 当前提交包逻辑树 `submission.package`
   └─ 论文产物项 `submission.thesis`
      └─ 候选文档引用 `artifact_ref` → candidate `document_sha256`
            ▲ `snapshot_map` 只用匹配 hash 的 locator 建立投影
            │
不可变文档快照层 `document.snapshots`
├─ 源论文快照 `source.document_sha256` + `snapshot_locator*`
├─ 目标模板快照 `template.document_sha256` + `snapshot_locator*`
└─ 候选文档快照 `candidate.document_sha256` + `snapshot_locator*`

关键非包含连接
├─ 产品词汇 ──classifies──> 论文/模板逻辑实例
├─ 文档快照 ──snapshot_map──> 论文/模板逻辑实例
├─ 论文内容或事实实例 ──binding.edge──> 模板逻辑节点
├─ evidence record ──evidence.supports──> 实例/关系/判断/绑定
└─ `submission.thesis` ──artifact_ref──> candidate `document_sha256`

同一组锚点的职责消费者
├─ Skill：选择和组合语义实例、关系、证据与绑定
├─ Tool：解析或消费特定 document hash 下的快照定位器
└─ Eval：断言语义实例、关系、来源覆盖和可见结果
```

上图的层间箭头表示分类、投影或引用，不是运行步骤；同一任务内也允许反复检查、判断、修改
和验证。工作区中的论文实例、任务投影、模板树和提交包树是并列协作视图，只有各自标明的
`children[]` 才表示包含。`submission.thesis` 只引用候选文档产物，不复制论文语义树；目标
模板默认是任务输入而非提交包内容。学校要求、模板参数、文档正文和任务结论不得反向晋升为产品词汇。

### 3.2 Skill 可复用的论文语义锚点模型

结论是：完整论文不能只建成一棵树。最稳定的公共接口是“一棵主阅读顺序树 + 若干附着
内容子树 + 共享事实注册表 + 非包含关系图 + 保留对象注册表”。只有拥有/包含和阅读顺序
进入树；引用、来源、任务判断和模板映射通过 ID 连接。

| 视图 | 保存什么 | 不保存什么 |
|---|---|---|
| 主阅读顺序树 `thesis.primary_flow` | 前置、正文、后置区域内实际可遍历的单元、块和行内节点 | 共享事实真值、反向索引、任务状态 |
| 附着内容子树 `thesis.attached_flow*` | 脚注、尾注、页眉页脚等有内部顺序但依附于其他对象的内容 | 它们与主内容的连接关系 |
| 共享事实注册表 `thesis.facts` | 题名、作者、日期等唯一语义真值 | 事实在页面中的每次出现位置 |
| 非包含关系图 `thesis.relations` | 事实引用、文内引文、交叉引用、脚注连接、生成依赖等边 | 被连接节点的第二份内容 |
| 保留对象注册表 `thesis.preservation` | 批注、修订、未知或 opaque 部件及其锚定范围 | 将未知对象猜成已有内容类型 |

真正用于遍历论文内容的主树只有下面这一棵：

```text
论文主阅读顺序树 `thesis.primary_flow`
└─ 有序区域 `children[]`
   ├─ 前置内容区域 `thesis.front_matter`
   │  └─ 有序单元 `children[]` = (`front.unit`)*
   │     ├─ 封面/题名页/书脊
   │     ├─ 声明/审批单元
   │     ├─ 摘要/图形摘要/献词/题辞/前言
   │     └─ 目录、图表公式清单、缩略语表、符号表等
   ├─ 正文区域 `thesis.body`
   │  └─ 正文根 `body.main`
   │     └─ 有序子节点 `children[]` = (`content.block` | `body.section[level=1]`)*
   │        ├─ 内容块 `content.block`
   │        └─ 章节 `body.section[level=1]`
   │           ├─ 标题身份 `heading`
   │           └─ 有序子节点 `children[]` = (`content.block` | `body.section[level=2]`)*
   │              └─ ……按同一规则递归到 `level=N`
   └─ 后置内容区域 `thesis.back_matter`
      └─ 有序单元 `children[]` = (`back.unit`)*
         ├─ 参考文献
         ├─ 附录
         ├─ 致谢/作者简介/成果清单/术语表
         └─ 可用性声明、披露、索引和补充材料等
```

上图表达的是实例结构规则，不规定任何学校必须采用该固定顺序。实际 `children[]` 只保存
当前论文观察或当前任务确认的顺序；角色目录只定义哪些节点可以出现。

每个能够被 Skill 持续讨论的论文对象使用同一组语义锚点：

```text
语义锚点 `semantic_anchor`
├─ 通用语义角色 `semantic_id`
├─ 当前逻辑实例 `instance_id`
├─ 节点结构形态 `node_kind`
├─ 直接父实例 `parent_instance_id?`
├─ 同级顺序 `sequence?`
└─ 内容身份摘要 `content_identity?`

当前任务投影 `task.projection`
├─ 快照映射 `snapshot_map`：`instance_id` → 当前 hash 下的 `snapshot_locator*`
├─ 证据支持边 `evidence.supports`：evidence record → `instance_id`/关系/判断/绑定
├─ 判断覆盖 `decision_overlay`：出现状态、所有权判断、处置、冲突和置信度
├─ 模板绑定 `binding.edge`：内容/事实 `instance_id` → template node ID
└─ 验证记录 `validation`：同一 `instance_id` 的源快照与候选快照证据
```

`semantic_id` 是跨任务可复用的概念，例如 `body.section` 或 `object.figure`；`instance_id`
标识当前任务里具体的“第二章”或“图 3-2”。Tool 返回的 `object_ref` 只是某个 document hash
下的快照定位器，不能充当语义身份。`content_identity` 也只是续接证据之一，不是另一种 ID。

#### ID 的稳定范围与生命周期

这里的“稳定”不是永久不变。产品词汇、任务内逻辑身份和单文件快照定位器有不同生命周期：

| 身份或定位 | 稳定范围 | 创建与续接规则 | 失效、变更或迁移规则 |
|---|---|---|---|
| `semantic_id` | 产品通用；随 Knowledge 版本发布 | 从通用概念目录选用，不为单篇论文临时发明同义 ID | 概念改名或拆分必须由 Knowledge 版本提供别名或迁移说明 |
| `node_kind` / `relation_kind` | 产品通用词表 | 描述结构形态或边语义，不标识具体对象 | 词表变化按 Knowledge 版本治理，不能由学校模板静默改名 |
| `instance_id` | 一次授权任务的文档谱系 | 首次确认 fact/unit/ref/object 等逻辑对象时创建；只有新快照仍可证实为同一对象时续接 | 跨任务不复用；事实含义分裂、对象拆分/合并/复制或无法确认同一性时按下表建立新实例 |
| `relation_id` | 一次授权任务的关系图 | 为一个明确的 source—target 语义边创建；同一边跨候选快照可续接 | 起点、终点或边语义改变时建立新关系；不得把多目标集合藏进一个 ID |
| `template_node_id` | 当前任务的目标模板逻辑实例 | 模板逻辑节点经识别后创建，快照位置另存 | 模板逻辑节点被替换、拆分或含义改变时建立新 ID；不等同于 XML locator |
| `binding_id` | 当前任务的一条内容—模板绑定边 | 来源、目标、动作和证据范围明确时创建 | 任一端点或绑定语义改变时修订为新边；旧记录保留可追溯身份，不覆盖成别的含义 |
| `evidence_id` | 当前任务的一次具体声明或观察 | 对特定来源、范围和内容建立不可混淆的记录 | 不能把原记录改写成另一项证据；新快照或新确认形成新记录 |
| `validation_id` | 当前任务的一次具体检查 | 绑定确切 candidate hash、检查范围和结果 | 候选文件编辑后旧结果仍可审计，但不再证明新 hash 通过 |
| `snapshot_locator` = document hash + locator kind/value | 一个确切文档快照 | 每次检查从当前文件获取；kind 可以是 object/section/text/page 等 Tool 支持的定位种类 | 文件 hash 改变即失效，必须重新检查；旧记录只作为旧快照证据，不得靠 `instance_id` 推算 locator |

“一次授权任务的文档谱系”指当前源文件以及在同一任务中由它产生并获准处理的工作副本、
候选文件和交付候选；它不是跨任务数据库身份，也不授权读取其他文件。

编辑后重新检查时，先让旧快照定位器失效，再依据父子位置、顺序、文字锚点、内容摘要、
来源覆盖和关系闭包判断是否续接逻辑实例：

| 新快照变化 | ID 处理 |
|---|---|
| 只移动或重排版，逻辑内容和范围仍可确认相同 | 保留 `instance_id`，更新父实例、顺序和 `snapshot_map` |
| 只纠正语义分类，逻辑内容范围没有改变 | 可保留 `instance_id`，以新证据更新 `semantic_id` 判断并保留判断历史 |
| 一个对象拆成多个对象 | 原实例停止映射到新候选；各结果创建新 `instance_id`，并各自用 `relation.derived_from` 指向原实例 |
| 多个对象合成一个对象 | 合并结果创建新 `instance_id`，用多条 `relation.derived_from` 分别指向各输入实例 |
| 复制或派生出另一个对象 | 新对象使用新 `instance_id`；需要表达来源时建立 `relation.derived_from` |
| 对象从候选中删除或按证据不再出现 | 不回收原 ID 给其他对象；候选 `snapshot_map` 无映射，并由判断与验证记录授权缺失 |
| 无法可靠确认是否仍为同一对象 | 不强行续接；建立新实例或标记 `needs_review` |

这套生命周期规则只约束锚点的含义，不要求 Skill 按固定阶段运行，也不预设持久化实现。

#### 关系边命名与方向

`thesis.relations` 只保存规范化的单条语义边。边名统一使用单数谓词
`relation.<predicate>`；每条边只有一个 source 和一个 target。`map`、`links`、`backlinks`
或按目标分组的集合只能从真实边派生，统一落入三个通用索引：
`relation_index.by_source`、`relation_index.by_target` 和 `relation_index.by_kind`。索引值只引用
`relation_id`，不复制边内容，也不为某类关系另造 `*_map` 名称。

| 规范边名 | 固定方向 | 典型用途 |
|---|---|---|
| `relation.fact_occurrence` | ref 出现位置 → 一个共享事实 | 封面题名、摘要关键词等页面出现位置引用论文级真值 |
| `relation.citation` | 一个文内引文标记 → 一个参考文献条目 | `[1-3]` 表达为三条边，并用 `target_sequence` 保留目标顺序 |
| `relation.cross_reference` | 一个交叉引用标记 → 一个内部内容目标 | 标题、图、表、公式、附录等 |
| `relation.note_reference` | 一个脚注/尾注标记 → 一个注释正文 | marker 与附着内容流的连接 |
| `relation.hyperlink` | 一个超链接节点 → 一个内部或外部目标 | 显示文字仍由源节点拥有 |
| `relation.generated_from` | 一个生成内容节点 → 一个直接来源对象 | 目录项、图表清单项、题注编号、页码等；多依赖用多条边 |
| `relation.anchored_to` | 一个附着或保留对象 → 一个内容实例或范围 | 页眉页脚适用节、批注/修订锚点、对象注释范围 |
| `relation.paired_with` | ID 规范排序中较小的一端 → 较大的一端 | 双语题名、摘要、关键词或图表 caption 配对；只存一条对称关系边 |
| `relation.derived_from` | 一个新任务实例 → 一个来源实例 | 拆分、合并、复制时保存任务内实例谱系 |

`binding.edge` 是当前任务中内容/事实到模板节点的适配边，`evidence.supports` 是证据到观察或
判断的支持连接；二者不属于论文固有的 `thesis.relations`，也不使用 `relation.*` 名称。

这些锚点服务 Skill 的可回看活动，不把 Skill 固定成工作流状态机：

| Skill 活动 | 使用的锚点 | 形成的连接 |
|---|---|---|
| 检查与识别 | document hash、快照定位器、候选 `semantic_id` | 建立或更新 `snapshot_map` 与来源观察 |
| 解释与判断 | 内容/事实 `instance_id`、关系 ID、证据引用 | 附加任务级置信度、冲突、适用性和处置候选 |
| 模板匹配与修改 | 内容 `instance_id`、template node ID、当前有效快照定位器 | 建立 binding；写入前重新解析当前目标，写入后不复用旧 ref |
| 验证与视觉复核 | 同一逻辑实例的新旧快照投影、关系依赖和页面证据 | 检查内容保留、结构关系、任务规则和可见结果 |
| 可选委派 | 明确的 `instance_id`/关系集合及其证据闭包 | 形成 `analysis_scope`，不建立固定单元到 Agent 的映射 |

因此，后续 Knowledge、Skill、Tool 和 Eval 应共享 `semantic_id` 词汇，但职责不同：Knowledge
解释概念，Skill 选择和组合锚点，Tool 返回/消费当前快照引用，Eval 用锚点断言内容与关系；
任何一方都不应另造一套 cover/body/reference 命名。

```text
│  │  ├─ 插图目录 `front.list_of_figures?`
│  │  ├─ 表格目录 `front.list_of_tables?`
│  │  ├─ 公式目录 `front.list_of_equations?`
│  │  └─ 清单标题 + 分级条目 + 目标 + 页码 `front.generated_list.entry*`
│  └─ 术语性清单 `front.terminology_lists*` [?/*；student/mixed；preserve/fill/generate]
│     ├─ 缩略语表 `front.abbreviations?`
│     ├─ 符号表 `front.symbols?`
│     └─ 术语/符号 + 全称/定义 + 单位 + 语言 `front.terminology_entry*`

│  ├─ 正文根 `body.main` [1；student；preserve/fill]
│  │  └─ 有序子节点 `body.main.children*` = (`content.block` | `body.section`)*
│  │     ├─ 可出现：未归入标题的内容块 `content.block*` [?/*；student；preserve]
│  │     └─ 可出现：一级正文单元 `body.section[level=1]*` [*；student；preserve]

│  │        │  └─ 章节角色 `section_role?` = chapter/section/unnumbered/custom

│  │     └─ 编号/作者/题名/载体/出版信息/标识符 `back.reference_entry.parts?`

│  │  ├─ 附录编号/标题 `back.appendix.identity`
│  │  └─ 标题/段落/列表/图/表/公式等 `back.appendix.content*`
│  ├─ 致谢 `back.acknowledgements?` [?；student；preserve/fill]
│  ├─ 作者简介 `back.author_biography?` [?；student；preserve/fill]
│  ├─ 成果与发表清单 `back.achievements_or_publications*` [?/*；student；preserve/fill]
│  ├─ 术语表 `back.glossary?` [?；student/mixed；preserve/fill]
│  ├─ 数据/代码可用性 `back.availability?` [?；student；preserve/fill]
│  ├─ 资金/利益/贡献声明 `back.disclosures*` [?/*；student/mixed；preserve/fill]

│  └─ 补充材料 `back.supplementary*` [?/*；student；preserve]

│  │  └─ 注释正文 `note.content*`
│  └─ 节级页眉/页脚内容流 `running_content.flow*`

│  ├─ 脚注/尾注引用 `relation.note_reference*` = 一个 marker → 一个 `note.content`
│  ├─ 文内引文 `relation.citation*` = 一个 `inline.citation` → 一个 `back.reference_entry`
│  ├─ 交叉引用 `relation.cross_reference*` = 一个 marker → 一个标题/图/表/公式/附录目标
│  ├─ 超链接 `relation.hyperlink*` = 一个 `inline.hyperlink` → 一个内部或外部目标
│  ├─ 事实出现 `relation.fact_occurrence*` = 一个 ref → 一个 `thesis.facts` 事实
│  ├─ 生成来源 `relation.generated_from*` = 一个生成内容节点 → 一个来源对象
│  ├─ 内容锚定 `relation.anchored_to*` = 一个附着/保留对象 → 一个内容实例或范围
│  ├─ 对象配对 `relation.paired_with*` = 一个语义对象 → 一个对应对象
│  └─ 实例派生 `relation.derived_from*` = 一个新任务实例 → 一个来源实例
└─ 审阅与未知保留对象 `thesis.preservation` [?/*；mixed/manual；preserve/unknown_keep]
   ├─ 批注及回复 `review.comment*`
   ├─ 插入/删除/移动修订 `review.revision*`
   ├─ 未知可见节点的原始载荷 `extension.unknown_payload*` → `content.unknown_visible*`
   └─ 自定义/未知非可见部件 `extension.opaque_part*`
```

外封面条目只是说明节点可以怎样交错，不是学校通用顺序。当前来源或模板观察到的实际顺序
才写入该单元 `children[]`；每个子节点都有自己的 `instance_id`、`parent_instance_id` 和
`sequence`。表格、文本框或“标签—值”需要保持局部结构时使用 `front.cover.group`，组内仍是
有序 `children[]`。题名、作者等 ref 节点占据自己的出现位置，但它们指向哪个共享事实只由
独立的 `relation.fact_occurrence` 边表达。题名页、书脊、声明和摘要等复合前置单元沿用同一条
“有序子节点 + 侧向关系”原则。`front.fact_occurrence_ref` 在允许成员表达式中只是 ref 类型
并集，不是实际包裹节点，也不是新增的 `semantic_id`。

`content.block`、paragraph、figure、table、equation 和 inline 等结构形态不作为上面实例树的
额外分支；它们的允许结构统一放在第 6.3–6.5 节节点字典中。

### 3.4 怎么读共享事实、文档单元和引用

“论文级共享事实”与“文档单元”不是一一对应关系，它们是内容树中的两个维度：

| 节点类别 | 回答的问题 | 是否占据文档中的一个位置 |
|---|---|---|
| `fact` | 这个事实是什么，例如论文题名、作者姓名、提交日期 | 不一定；它是唯一语义真值 |
| `unit` | 文档中实际有哪些有序单元，例如外封面、摘要、正文、参考文献 | 是；拥有结构边界和内部顺序 |
| `ref` | 某个单元在哪个位置使用哪个事实 | 是；引用事实，但不再复制一份真值 |
| `object` | 某个单元自己拥有的内容是什么 | 是；例如固定声明、摘要正文、标志图形 |

因此，`thesis.facts` 更准确地说是“论文级共享事实注册表”，不是 DOCX 的原始数据，也不是
一个封面之前实际出现的页面单元。DOCX 中观察到的原始文字、表格或对象属于
`task.evidence.source_observation`；它们经过识别后形成共享事实，并通过 `evidence.supports`
边记录“哪条证据支持哪个事实实例”。

外封面的关系应这样读：

```text
共享事实注册表 `thesis.facts`
└─ 论文题名事实实例 <fact>
   ├─ 通用语义角色 `semantic_id = metadata.title.primary`
   ├─ 当前任务实例身份 `instance_id = <title-fact-instance>`
   ├─ 原始值 `raw_content`
   └─ 规范化视图 `normalized_content?`

当前任务证据账本 `task.evidence`
└─ 来源观察 `evidence.source_observation`
   └─ `evidence.supports` → `<title-fact-instance>`

外封面 `front.cover` <unit>
└─ 有序子节点 `children[]`（以下只是一种观测顺序）
   ├─ 标志图形 `front.cover.mark` <object>
   ├─ 学校固定文字 `front.cover.fixed_content` <object>
   ├─ 题名局部标签 `front.cover.title_label` <object>
   ├─ 题名出现位置 `front.cover.title_ref` <ref>
   ├─ 作者局部标签 `front.cover.author_label` <object>
   ├─ 作者出现位置 `front.cover.author_ref` <ref>
   └─ 人工内容 `front.cover.manual_content` <object>

非包含关系图 `thesis.relations`
├─ `relation.fact_occurrence`: `<cover-title-ref-instance>` → `<title-fact-instance>`
└─ `relation.fact_occurrence`: `<cover-author-ref-instance>` → `<author-fact-instance>`
```

同一个题名事实可以被多个单元引用：

```text
按目标反查 `relation_index.by_target`（派生，不拥有边）
└─ `<title-fact-instance>` (`semantic_id = metadata.title.primary`)
   ├─ ← `relation.fact_occurrence` ← `<cover-title-ref-instance>` (`front.cover.title_ref`)
   ├─ ← `relation.fact_occurrence` ← `<title-page-title-ref-instance>` (`front.title_page.title_ref`)
   ├─ ← `relation.fact_occurrence` ← `<spine-title-ref-instance>` (`front.spine.title_ref`)
   └─ ← `relation.fact_occurrence` ← `<abstract-title-ref-instance>` (`front.abstract.title_ref`)
```

这里没有四份论文题名，只有一个事实和四个出现位置。反过来，一个外封面单元可以引用题名、
作者、学院、专业、导师、日期等多个事实。因此二者通常是多对多关系，不应强行把元数据字段
逐个变成封面的子内容真值。

每个 `ref` 节点及其当前任务投影至少需要表达：

| 所属视图 | 字段 | 含义 |
|---|---|---|
| 任务内 ref 实例 | `instance_id` | 当前事实出现位置的逻辑实例身份 |
| 任务内 ref 实例 | `parent_instance_id` | 它属于哪个文档单元，并在该单元 `children[]` 中占据什么顺序 |
| 关系图 | `relation.fact_occurrence` | 从当前 ref 的 `instance_id` 指向一个共享事实实例的 `instance_id` |
| 任务内 ref 实例 | `observed_content?` | 该出现位置自身的可见内容；拥有独立位置的标签必须作为相邻 `front.local_content` 子节点 |
| 快照映射 | `snapshot_locator` | 当前 document hash 下这个出现位置的有效来源范围与 locator kind/value |
| 判断覆盖 | `presence_status` | 该位置当前是 present、missing、unknown 还是 needs_review |
| 判断覆盖 | `consistency_status` | observed content 与共享事实是否一致、冲突或尚未验证 |

不是所有单元内容都要进入 metadata：摘要正文、声明固定正文、献词、正文段落、图表等由各自
单元直接拥有。只有论文级身份、人员、机构、日期、权利和可发现性等可共享事实进入
`thesis.facts`。

如果外封面和内封面观察到的题名不同，不能为了维持“一个事实”而静默选择其一。两个 ref
分别保留各自的 `observed_content`，快照映射保留各自的 `snapshot_locator`；冲突状态写入当前任务
的 `decision_overlay`，待更多证据或用户确认后再决定共享事实值。

### 3.5 正文内容层级怎么读

正文采用三层模型，不把“章节”“段落”“段落中的文字”放在同一层比较：

| 层 | 容纳什么 | 解决的问题 |
|---|---|---|
| 正文容器层 | `body.main` | 确定正文的起止边界，并容纳正文最外层节点 |
| 章节/内容块层 | `body.section`、`content.block` | 同时表达标题嵌套和段落、图、表、公式等实际阅读顺序 |
| 行内节点层 | `inline.text`、`inline.math`、`inline.citation` 等 | 表达一个段落内部文字、公式、引文标记互相穿插的顺序 |

可以把核心结构读成下面四条语法：

```text
BodyMain.children[]    = (BodySection | ContentBlock)*
BodySection.children[] = (BodySection | ContentBlock)*
ContentBlock           = Paragraph | List | Quote | Figure | Table | Equation | …
Paragraph.children[]   = (InlineText | InlineMath | InlineCitation | InlineCrossReference | …)*
```

其中，`children[]` 是一个统一的有序序列，不是“内容块列表”和“子章节列表”两份数据。
例如下面这篇论文必须按从上到下的顺序读取：

```text
正文根 `body.main`
├─ 无标题前导段落 `body.paragraph`
├─ 第一章 `body.section[level=1]`
│  ├─ 正文段落 `body.paragraph`
│  ├─ 陈列公式 `object.equation`
│  ├─ 1.1 节 `body.section[level=2]`
│  │  ├─ 含文内引文的段落 `body.paragraph`
│  │  │  └─ 文字 → `inline.citation` → 文字
│  │  └─ 图 `object.figure`
│  └─ 本章总结段落 `body.paragraph`
└─ 第二章 `body.section[level=1]`
```

这里第一章的 `children[]` 依次是“段落、公式、1.1 节、本章总结段落”。如果把内容块和
子章节拆成两组，最后一个总结段落究竟位于 1.1 节之前还是之后就无法恢复。因此：

- `body.main.children[]` 可以同时包含无标题内容块和一级 `body.section`；
- `body.section.children[]` 可以同时包含本级内容块和直接子 `body.section`；
- 标题 `heading` 是 `body.section` 的身份组成，不是与段落并列的独立内容块；
- `content.block` 是抽象结构形态，不是正文里额外出现的容器；实际节点是段落、列表、图、表、公式等；
- 段落的 `children[]` 只容纳行内节点，不容纳下一节标题；
- 每个同级节点通过数组位置或 `sequence` 保留原始阅读顺序。

### 3.6 标题层级的递归定义

一级、二级、三级标题不定义成三种互不相关的节点，而是同一个 `body.section` 节点在不同
逻辑层级上的实例。这样可以容纳四级、五级以及学校自定义的更深层级，而无需继续增加新的
节点类型。

```text
正文根 `body.main`
└─ 有序子节点 `children*` = (`content.block` | `body.section`)*
   └─ 一级正文单元 `body.section[level=1]*`
      ├─ 本级标题 `heading`
      └─ 有序子节点 `children*` = (`content.block` | `body.section`)*
         ├─ 本级内容块 `content.block*`
         └─ 二级正文单元 `body.section[level=2]*`
            ├─ 本级标题 `heading`
            └─ 有序子节点 `children*`
               ├─ 本级内容块 `content.block*`
               └─ 三级正文单元 `body.section[level=3]*`
                  └─ ……继续递归到 `level=N`
```

每个 `body.section` 至少表达以下字段：

| 字段 | 含义 | 约束 |
|---|---|---|
| `level` | 当前单元在正文语义树中的逻辑层级 | 正整数；一级为 1，不预设最大值 |
| `parent_section_id` | 直接父级正文单元 | 一级为空；其余指向直接父 `body.section` |
| `heading_text` | 去除可分离编号后的完整标题文字 | 原始标题仍需保留 |
| `source_numbering_text` | 来源中可见的原始编号 | 可空；例如“第一章”“1.2.3” |
| `numbering_path` | 从编号中解析出的候选层级路径 | 可空；不能替代 `level` |
| `section_role` | 对层级用途的补充描述 | chapter、section、subsection、unnumbered、custom 等开放值 |
| `source_outline_level` | 来源文件声明或观察到的大纲层级 | 只作为证据，不直接覆盖逻辑层级 |
| `source_style_ref` | 来源样式或其他结构线索 | 只作为识别证据，本轮不定义样式内容 |
| `toc_membership` | 是否被目录或其他生成视图引用 | 不能仅凭是否入目录决定层级 |
| `children` | 本级直接子节点的有序并集 | 每项只能是 `content.block` 或直接子 `body.section`；两类可互相穿插 |

层级约束：

- `level=1` 的父容器是 `body.main`；
- 常规情况下，`children[]` 中的子章节满足 `child.level = parent.level + 1`；该约束不作用于内容块；
- 来源若出现从一级直接跳到三级等缺级现象，应保留观察结果并标记 `needs_review`，不能静默
  虚构一个二级标题；
- “章”是 `section_role=chapter` 的常见一级实例，不再与 `body.section` 建立平行模型；
- 无编号标题仍然可以拥有逻辑层级；编号分量数、Word 大纲级别、样式名和目录级别都只是
  判断证据，不等同于最终 `level`；
- 章节内部不得另设 `blocks[]` 与 `subsections[]` 两个独立数组；否则会丢失二者互相穿插的顺序；
- 目标模板要求的层级映射属于当前任务绑定，不写回学生内容树。

### 3.7 图、表、题名与注释怎样组成有序复合对象

图和表在正文外层各占据一个 `content.block` 位置，但它们内部不能继续压成“图题字段 +
图片字段”或“表题字段 + 表格字段 + 表注字段”。题名、主体、图例、注释、可见来源和未知可见内容
都有自己的位置，必须进入复合对象唯一的有序 `children[]`：

```text
图 `object.figure` <composite content block>
└─ 有序子节点 `children[]`
   = (`object.label` | `object.caption` | `object.asset` | `object.figure_group`
      | `object.legend` | `object.note` | `object.source_statement`
      | `content.unknown_visible`)*

表 `object.table` <composite content block>
└─ 有序子节点 `children[]`
   = (`object.label` | `object.caption` | `object.table_grid`
      | `object.legend` | `object.note` | `object.source_statement`
      | `content.unknown_visible`)*

表格主体 `object.table_grid`
└─ 有序逻辑行 `children[]` = (`object.table_row`)*
   └─ 有序单元格 `children[]` = (`object.table_cell`)*
      └─ 单元格内部有序内容 `children[]` = (`content.block`)*
```

各成员的稳定含义是：

| 成员 | 主要字段 | 说明 |
|---|---|---|
| `object.label` | `label_text`、编号语义、引用键 | 独立可见的“图 3-2”“表 4.1”等标识；与题名同段且不能安全拆分时保留在 caption 原文中 |
| `object.caption` | `caption_role`、`language`、`raw_content`、`normalized_content?` | 图名、表名、题名、副题名或短题名；中文名与英文名是两个 caption 实例，不是两种 figure/table |
| `object.asset` / `object.figure_group` | 媒体或子图及其顺序 | 图的主体；子图组内部同样保存有序成员 |
| `object.table_grid` | 行、列、合并和单元格结构 | 表的主体；不把题名或表注塞进首尾单元格来模拟顺序 |
| `object.legend` | 图例条目、符号、颜色、系列、解释 | 需要结构化表达的图例；简单说明也可保守保留为 note |
| `object.note` | `note_role`、`language?`、标记、正文 | 图注、表注、单位、缩略语或显著性说明等局部可见注释 |
| `object.source_statement` | `language?`、可见标签、原始内容、可选行内引用 | 实际显示的“来源：……”行；它占据顺序，但不等同于媒体 provenance、任务证据或 DOCX 包关系 |
| `content.unknown_visible` | 原位摘要与保留载荷引用 | 无法分类但确实位于图表复合范围中的可见内容 |

一个已确认的 figure 通常拥有一个主体（`object.asset` 或 `object.figure_group`），一个已确认的
table 通常拥有一个逻辑 `object.table_grid`；题名、注释和来源可以重复。跨页表格或被 Word
拆成多个承载片段，不自动变成多个逻辑 grid；无法确认主体边界时保留片段并标记
`needs_review`，不能为了满足基数静默合并或补造。

`caption_role` 使用 `title`、`subtitle`、`short_title`、`other` 等开放值；`note_role` 使用
`general`、`unit`、`abbreviation`、`significance`、`other` 等开放值。它们说明
成员的语义，不规定成员必须出现，也不决定顺序。

`object.label` 表达可见标识在复合对象中的位置；若它由 Word 题注编号字段产生，字段指令与
生成依赖仍由 `source.field` 和 `relation.generated_from` 表达，不再创建第二份可见标签真值。

中文名与英文名分别拥有自己的 `instance_id`、`language` 和 `sequence`，通过
`relation.paired_with` 表达语义配对。例如 `caption[language=zh-CN]` 与
`caption[language=en]` 可以配对，但是否相邻、谁在前、是否同时存在，只由来源或当前模板
证据决定。

下面两种结构都合法，不能被通用 Knowledge 强行归一：

```text
表 A `object.table`
├─ 中文表名 `object.caption[language=zh-CN]`
├─ 英文表名 `object.caption[language=en]`
├─ 表格主体 `object.table_grid`
└─ 可见来源行 `object.source_statement`

表 B `object.table`
├─ 表格主体 `object.table_grid`
├─ 一般表注 `object.note[note_role=general]`
├─ 中文表名 `object.caption[language=zh-CN]`
└─ 英文表名 `object.caption[language=en]`
```

图表局部注释 `object.note` 是复合内容块中的可见成员；带正文 marker 的脚注/尾注仍进入
`thesis.attached_flow`，并通过 `relation.note_reference` 连接。批注和修订仍属于
`thesis.preservation`。三者不能因为中文都叫“注”而混成一种节点。

同样，“来源”也必须分责：可见来源行是 `object.source_statement`；指向参考文献的标记使用
`relation.citation`；判断或 provenance 的依据使用 `evidence.supports`；图片和嵌入对象的
DOCX 包关系只属于 `snapshot_map`。它们不能合并成一个模糊的 `source` 字段。

目标模板如果要求特定排列，只在当前任务模板树中记录其有序子节点和相对顺序约束；绑定可以
指向整个图表复合对象，也可以分别指向 caption、grid/asset、legend、note 或 source statement。没有当前任务
证据时不得为了匹配常见外观重排成员，无法安全识别的相邻内容保持原位并标记 `needs_review`。

### 3.8 正文公式、文内引文和文献条目怎样连接

公式和参考文献索引都必须先出现在正文实际位置，再通过关系指向其他对象。这里的“参考文献
索引”指 `[1]`、`[1-3]`、上标编号或 `(Author, Year)` 等文内引文标记，不等同于后置部分的
主题索引 `back.index`。

```text
正文单元 `body.section`
└─ 有序子节点 `body.section.children*`
   ├─ 段落 `body.paragraph`
   │  └─ 有序行内节点 `children*`
   │     ├─ 文字 `inline.text*`
   │     ├─ 行内公式 `inline.math*`
   │     └─ 文内引文标记 `inline.citation*`
   │        ├─ 原始显示 `observed_content`
   │        └─ 引文页码等定位信息 `citation_locator?`
   └─ 陈列公式 `object.equation*`
      ├─ 表达式/来源表示 `expression`
      └─ 公式号/引用键 `identity?`

非包含关系图 `thesis.relations`
├─ 引文关系 `relation.citation*`
│  ├─ source → 一个 `inline.citation`
│  ├─ target → 一个 `back.reference_entry`
│  └─ 同一 marker 的目标顺序 `target_sequence?`
└─ 公式交叉引用 `relation.cross_reference*`
   ├─ source → `inline.cross_reference`
   └─ target → `object.equation`

后置参考文献 `back.references`
└─ 文献条目 `back.reference_entry*`
   ├─ 完整原始条目 `raw`
   └─ 可选结构化字段 `parts?`
```

公式分成两种位置语义：

| 类型 | 所属位置 | 主要字段 |
|---|---|---|
| 行内公式 `inline.math` | 段落的有序行内 `children[]` 内部 | 表达式或来源表示、原始范围、前后文字关系 |
| 陈列公式 `object.equation` | `body.main.children` 或 `body.section.children` 中的独立内容块 | 表达式、公式号、引用键、子式、说明和交叉引用 |

段落是最常见示例；行内公式和文内引文也可以出现在列表条目、表格单元格、脚注或其他允许
富文本的容器中，并由最近的实际文本容器拥有。

可编辑公式、图片公式和无法解析的公式对象都属于公式内容；解析能力不同不能改变其内容身份。
图片或 opaque 公式必须保留原始对象和来源关系，不能降级成空段落。

文内引文与文献条目的关系：

- `inline.citation` 由正文段落拥有，因为它实际出现在正文文字流中；
- 一个引文标记可以指向一个或多个 `back.reference_entry`，但每个目标各用一条
  `relation.citation`；例如 `[1-3]` 形成三条共享同一 source、分别带目标顺序的边；
- 同一文献条目可以被正文多次引用，因此引文与文献条目是多对多关系；
- `[1]`、上标 1、作者—年份只是 `observed_content/display form`，不能替代稳定的文献目标；
- 文献条目保留完整原始文本，作者、题名、年份等结构化字段只是可选增强；
- 存在但没有被正文引用的文献条目不能自动删除，是否允许由当前任务规则决定；
- `relation_index.by_source` / `by_target` / `by_kind` 只从规范边派生，不是节点内容或关系真值
  的第二所有者；按 `relation_kind` 过滤即可得到引文或交叉引用反查。

### 3.9 模板树、任务级绑定边与提交包树

模板和提交包各自可以形成包含树；绑定不是第三棵树，而是一组仅对当前任务有效的有向边记录。

```text
模板文档 `template.document` [1；school/mixed；preserve]
├─ 固定内容 `template.fixed_region*` [*；school；preserve]
├─ 标量槽位 `template.scalar_slot*` [?/*；mixed；fill/manual]
├─ 块槽位 `template.block_slot*` [?/*；mixed；fill]
├─ 容器 `template.container*` [?/*；mixed；preserve/fill]
├─ 图表等有序复合容器 `template.composite_container*` [?/*；mixed；preserve/fill]
│  └─ 观测到的有序 `children[]`
│     = (`template.fixed_region` | `template.slot` | `template.generated_region`
│        | `template.instruction` | `template.manual_region` | `template.unknown_region`)*
├─ 生成区域 `template.generated_region*` [?/*；system/mixed；generate]
├─ 条件区域 `template.conditional_region*` [?/*；mixed；preserve/review]
├─ 模板说明 `template.instruction*` [?/*；school；preserve/remove_instruction]
├─ 人工区域 `template.manual_region*` [?/*；manual；preserve/manual]
└─ 未知区域 `template.unknown_region*` [?/*；mixed；unknown_keep]

任务级内容—模板绑定边 `binding.edge*` [?/*；mixed；preserve]
├─ 边身份 `binding_id`
├─ 来源端 `source_instance_id`（fact/unit/ref/object 实例统一使用）
├─ 目标端 `target_template_node_id`
├─ 写入动作字段 `action` = replace/append/repeat/generate/preserve/manual
├─ 必要语义转换字段 `transform?`
├─ 空内容行为字段 `empty_behavior`
├─ 证据引用字段 `evidence_refs+`
└─ 唯一性/兼容性/无损验证字段 `validation_refs+`

提交包 `submission.package` [1；mixed；preserve]
├─ 论文文档 `submission.thesis` [1；mixed；preserve/fill/generate]
│  └─ 候选产物引用 `artifact_ref` → candidate `document_sha256`
├─ 伴随文档 `submission.companion_document*` [?/*；mixed；preserve/manual]
│  ├─ 任务/研究计划类材料 `companion.plan_or_assignment*`
│  ├─ 进度/变更类材料 `companion.progress_or_change*`
│  ├─ 答辩/评阅/审批类材料 `companion.review_or_approval*`
│  └─ 成绩/意见/签署类表单 `companion.grade_or_signature*`
├─ 研究附件 `submission.attachment*` [?/*；student/mixed；preserve]
└─ 提交清单 `submission.manifest?` [?；mixed；preserve]
```

### 3.10 单个内容节点及任务覆盖怎样连接

```text
任务内论文逻辑实例 `thesis.instance`
├─ 节点类别 `node_category` = fact/unit/ref/object
├─ 通用语义角色 `semantic_id`
├─ 当前逻辑实例 `instance_id`
├─ 节点结构形态 `node_kind`
├─ 语言 `language?`
├─ 内容载荷 `content`
│  ├─ 原始内容 `raw_content`
│  ├─ 规范化视图 `normalized_content?`
│  ├─ 富文本/表达式/媒体 `rich_content_or_asset?`
│  └─ 内容身份摘要 `content_identity?`
└─ 有序包含结构 `containment`
   ├─ 直接父实例 `parent_instance_id?`
   ├─ 所属主流或附着流 `flow_id`
   ├─ 有序子节点 `children*`
   └─ 层级/顺序/组 `level_sequence_group?`

当前任务投影 `task.projection`
├─ 快照映射 `snapshot_map*` → `instance_id` / relation ID
├─ 证据支持边 `evidence.supports*` → `instance_id` / relation ID / decision ID / binding ID
├─ 判断覆盖 `decision_overlay*`
│  ├─ 实际所有权/来源角色 `owner`
│  ├─ 出现状态 `presence_status`
│  ├─ 处置候选 `disposition`
│  ├─ 置信状态 `confidence`
│  └─ 冲突与适用性 `conflicts/applicability?`
├─ 模板绑定 `binding.edge*`
└─ 验证记录 `validation*`
```

`owner`、`presence_status`、`disposition`、`confidence` 和验证结果都可能随着当前任务证据
变化，因此不能写进任务内论文逻辑实例。共享事实引用、引文、交叉引用、配对和生成依赖属于
`thesis.relations`，也不能为了方便而塞回包含结构。

## 4. 所有领域对象共享的字段

### 4.1 通用语义分类与任务实例身份字段

| 字段 | 含义 | 填写深度 |
|---|---|---|
| `node_category` | fact、unit、ref、object 等语义节点类别 | 关系使用独立 relation ID，不伪装成内容节点 |
| `semantic_id` | Knowledge 版本内跨任务、跨文档稳定的语义角色标识 | 使用领域名，不使用具体文档 locator；不得把旧 ID 改义复用 |
| `instance_id` | 当前任务中 fact/unit/ref/object 逻辑实例统一使用的身份 | 仅在证据支持同一对象时跨源/候选快照续接；不能直接等同于 Tool locator |
| `node_kind` | text、scalar、section、paragraph、figure、table、collection 等结构形态 | 与 `semantic_id` 分离；同一形态可承载不同语义角色 |
| `language` | 单元或文本运行使用的语言 | 允许继承、局部覆盖和未知 |
| `content_identity` | 在不复制正文的前提下辅助同一任务内续接实例的内容身份 | 只说明能力，不固定摘要或匹配算法 |
| `domain_cardinality` | 通用概念允许的 one、optional、many 等候选范围 | 属于概念目录约束，不代表当前学校要求或实例状态 |

### 4.2 语义字段与节点形态必须分离

历史版本已经证明，“这项内容是什么”和“用什么结构保存”是两个不同维度。本母稿沿用
这个领域结论，但不固定旧版字段名或 Schema：

| 维度 | 回答的问题 | 例子 |
|---|---|---|
| 语义字段 | 这项内容在论文中是什么 | 中文题名、导师姓名、中文摘要、正文、参考文献 |
| 节点形态 | 这项内容由什么结构承载 | text、person、section、paragraph、figure、table、collection |

中文题名和外文题名可以有不同语义字段，但都使用文本节点；中文摘要和外文摘要可以有
不同语义字段，但都使用“区域容器 + 段落 + 关键词”的复合结构。内部节点通常依靠父子
关系获得语义，不需要为每个表格单元格或题注都制造全局字段。

### 4.3 通用内容字段

| 字段 | 含义 |
|---|---|
| `text` | 普通文字或富文本内容 |
| `value` | 日期、编号、布尔值、标识符等结构化值 |
| `rich_content` | 含强调、上下标、超链接、公式等行内语义的内容 |
| `media` | 图片、图形、音视频或其他嵌入对象的语义引用 |
| `expression` | 数学公式、代码、算法或其他结构化表达式 |
| `raw_content` | 从来源观察到的完整原始内容，用于无损保留和回查 |
| `normalized_content` | 在不丢失原文的前提下形成的结构化或规范化视图 |
| `content_identity` | 内容身份或变更检查所需摘要；只说明能力，不固定算法，也不作为正文副本 |

`fixed_text`、`placeholder` 等名称描述的是当前模板观察或任务判断，不是所有内容节点共享的
稳定载荷字段；它们进入 `task.projection`。

### 4.4 有序包含结构字段

| 字段 | 含义 |
|---|---|
| `parent_instance_id` | 当前节点在所属内容流中的直接父实例 |
| `flow_id` | 当前节点属于主阅读流还是某个附着内容流 |
| `children` | 有序子节点集合；正文根/章节保存内容块与子章节，图表复合对象保存 caption、asset/grid、legend、note、source 等成员，段落保存行内节点；都不得按类型拆组后重排 |
| `sequence` | 同级单元的逻辑顺序 |
| `level` | 标题、列表、目录或附录等语义层级；标题层级为从 1 开始的开放正整数 |
| `parent_section_id` | 层级正文单元的直接父级；一级标题为空，其他层级指向父 `body.section` |
| `group` | 多个对象组成的复合单元 |
| `label` | 图、表、公式、附录等可引用标签 |

### 4.5 非包含关系字段

| 字段 | 含义 |
|---|---|
| `relation_id` | 当前逻辑关系实例的身份 |
| `relation_kind` | 第 3.2 节规范词表中的 fact_occurrence、citation、cross_reference、note_reference、hyperlink、generated_from、anchored_to、paired_with、derived_from 等单数谓词 |
| `source_instance_id` | 关系起点；不因此拥有目标内容 |
| `target_instance_id` / `target_ref` | 一个关系的唯一终点；fact/unit/ref/object 等内部目标统一使用 `instance_id`，外部超链接使用受验证的目标引用 |
| `target_sequence?` | 同一 source 拥有多条同类边时的目标顺序，例如多目标文内引文 |
| `relation_index.by_source/by_target/by_kind` | 从规范边派生的三种通用索引；值只引用 `relation_id`，不拥有边，也不成为目标节点的第二关系真值 |

需要多个目标或多个生成依赖时建立多条关系边，不能在一个 `relation_id` 下保存 target 数组。
边的 source、target 或 `relation_kind` 改变表示关系含义已经改变，应建立新的关系实例。

### 4.6 当前任务投影、证据与验证字段

| 字段 | 所属投影 | 含义 |
|---|---|---|
| `snapshot_locator` | `snapshot_map` | `document_sha256` + locator kind/value；kind 可表示 Tool 的 object/section/text/page 等定位，只对匹配 hash 有效 |
| `representation` | `snapshot_map` | text、field、media、drawing、textbox、embedded object、opaque 等当前来源形态 |
| `evidence_id` / `evidence_type` | `task.evidence` | evidence ledger 中不可变记录的身份及其 normative/template/source/render/user-confirmation 来源类型 |
| `source_evidence_id` + `target_endpoint` | `evidence.supports` | 从一条证据记录指向被支持的实例、关系、判断或绑定；不把证据画成内容父节点 |
| `owner` | `decision_overlay` | 当前任务判断的 student、school、system、mixed 或 manual 来源/修改责任 |
| `presence_status` | `decision_overlay` | present、missing、unknown、not_applicable、needs_review |
| `disposition` | `decision_overlay` | preserve、fill、generate、remove_instruction、manual、unknown_keep 等任务候选处置 |
| `condition` / `applicability` | `decision_overlay` | 当前判断适用的对象、章节、语言和条件 |
| `confidence` / `conflicts` | `decision_overlay` | 判断置信状态和未解决冲突；不是证据来源类型 |
| `fixed_text` / `placeholder` | `decision_overlay` | 对当前模板文字的分类结果；不能自动成为通用节点属性 |
| `validation_rules/results` | `validation` | 针对实例、关系、来源覆盖和可见结果的检查要求与结果 |

`evidence.unresolved` 不是一种证据来源；它应拆成证据账本中的原始来源，以及
`decision_overlay` 中的 unknown/conflict 判断。来源观察到事实的连接统一使用
`evidence.supports`；`relation.derived_from` 只表达任务内内容实例谱系，二者不能混名或使用父子包含。

### 4.7 无损表达原则

- 规范化字段不能替代原始内容；姓名、题名、编号、日期和引文等默认保留原文。
- 一项来源内容可以拆成多个语义子节点，但所有子节点合起来必须能追溯回完整来源范围。
- 无法结构化的内容进入 opaque/unknown 节点，不能因为解析器不认识就当作空内容。
- 图片、嵌入对象、文本框、字段、批注和修订不因纯文本为空而被视为无内容。
- 索引和反查结构只服务定位，不成为内容树的第二事实源。

## 5. 论文级共享事实（metadata）字段目录

这些字段构成论文级可共享事实的候选全集，不是页面单元目录，也不是源文件原始对象清单。
学校可能只要求其中一部分，也可能提供扩展字段。它们以 `metadata.*` 作为事实语义 ID，
统一注册在 `thesis.facts` 中；`thesis.metadata` 不再作为与正文并列的伪页面容器。

### 5.1 作品身份

- 主标题、副标题、并列标题、译名；
- 论文类型或成果类型；
- 学位层级、培养类型、研究方向；
- 学科、专业、项目或课程名称；
- 文档语言和多语言对应关系；
- 文档内部编号、外部提交编号、分类号或其他标识；
- DOI、Handle、仓储标识等作品级持久标识；
- 作品版本和修订标识；提交轮次、审核状态和本次交付状态属于 `submission.manifest` 或当前任务投影。

### 5.2 作者与相关人员

- 作者姓名、曾用名或多语言姓名；
- ORCID 或其他人员标识及其适用范围；
- 学号、候选人编号或其他任务内标识；
- 导师、联合导师、指导小组；
- 学院、系、专业、研究机构和合作机构；
- 评阅、答辩、审批或签署角色；
- 作者贡献、共同作者或合作贡献角色；
- 联系信息是否存在以及是否允许出现在交付物中。

### 5.3 时间与地点

- 完成日期、提交日期、答辩日期、批准日期；
- 学年、学期或培养周期；
- 所在城市、校区、机构或答辩地点；
- 日期的语义、语言和显示形式。

### 5.4 权利、分类与声明

- 原创性、授权、保密、解密或公开状态；
- 版权、许可、数据使用和第三方材料声明；
- 密级、期限、限制范围和批准信息；
- 伦理、利益冲突、资金支持和生成式工具使用声明；
- 签名、盖章、确认人与确认日期。

### 5.5 研究对象与可发现性

- 主题词、学科分类、关键词和受控词表标识；
- 摘要、图形摘要或面向不同受众的概要；
- 数据集、软件、代码、注册方案和补充材料标识；
- 文献引用键、外部链接、仓储位置和访问条件；
- 语言、翻译关系、无障碍说明和替代文本。

## 6. 论文语义对象字典

本节补充第 3 节主内容节点、附着内容节点、关系和保留对象的常见字段、变化点与验证重点。
有序父子结构只以 `thesis.primary_flow` 和 `thesis.attached_flow*` 为准；这里的类型表不是
第二棵内容树，关系与任务判断也不会因此变成内容子节点。

### 6.1 论文语义模型根 `thesis.model`

- **语义目的**：统一引用主阅读顺序树、附着内容子树、共享事实、关系和保留对象。
- **主内容根**：`thesis.primary_flow`；只包含有序的 front matter、body 和 back matter 区域。
- **侧向视图**：`thesis.attached_flow*`、`thesis.facts`、`thesis.relations` 和
  `thesis.preservation`；它们不是主内容根的有序子节点。
- **任务信息**：来源位置、所有权判断、出现状态、处置、绑定和验证属于 `task.projection`。
- **验证点**：主阅读树唯一且顺序完整；附着内容都有锚点；共享事实没有重复真值；关系目标
  可达；未知可见对象在原阅读位置存在占位节点并保留原始载荷。

| 单元 | 常见出现方式 | 通常包含的字段或子单元 | 关键变化点 |
|---|---|---|---|

### 6.3 正文结构单元

| 单元 | 常见出现方式 | 通常包含的字段或子单元 | 关键验证点 |
|---|---|---|---|
| 正文根 `body.main` | one | 有序 `children[]`；成员为无标题 `content.block` 或一级 `body.section` | 正文范围、节点穿插顺序和前后边界正确 |
| 层级正文单元 `body.section` | many/recursive | `level`、父级、标题、原始编号、有序 `children[]`；成员为本级 `content.block` 或直接子 `body.section` | 逻辑层级、父子关系、内容块与子章节的穿插顺序、编号观察和目录目标可分别验证 |
| 内容块结构形态 `content.block` | abstract/union | 段落、列表、引文、论证块、技术块、图、表、公式、提示块或未知块 | 只作为 `children[]` 的允许形态，不生成额外包裹节点；可在摘要、正文、附录等多个语境复用 |
| 普通段落 `body.paragraph` | many | 有序行内 `children[]`、引用、脚注标记、交叉引用 | 文本、行内语义和顺序完整 |
| 列表 `body.list` | optional/many | 有序/无序条目、层级、编号状态 | 层级、续编/重启和条目边界 |
| 引文块 `body.block_quote` | optional/many | 引文正文、来源、语言 | 与正文区分、来源关联 |
| 定义 `body.definition` | optional/many | 标签、编号、术语、定义正文 | 标签与正文关联 |
| 定理/命题 `body.theorem` | optional/many | 类型、编号、标题、陈述 | 编号与交叉引用 |
| 证明 `body.proof` | optional/many | 证明标签、正文、结束标记 | 与目标定理关联 |
| 示例 `body.example` | optional/many | 编号、标题、正文 | 层级和编号 |
| 算法 `body.algorithm` | optional/many | 编号、标题、输入、输出、步骤、注释 | 顺序、编号和复合关系 |
| 代码 `body.code` | optional/many | 语言、代码、行号、标题、来源 | 空白、换行、字符和来源完整 |
| 问卷/量表 `body.instrument` | optional/many | 名称、版本、题项、选项、计分说明、来源 | 题项顺序和引用关系 |
| 访谈/转录片段 `body.transcript` | optional/many | 说话人、时间、正文、匿名化状态 | 说话人和时间关系不丢失 |
| 注释/提示块 `body.callout` | optional/many | 类型、标题、正文、图标 | 类型不丢失，不能误作正文 |

`body.section[level=1, section_role=chapter]`。一级、二级、三级等标题同理，统一通过
递归节点和 `level` 表达。

### 6.4 图、表、公式与复合对象

| 单元 | 通常包含的字段 | 子对象 | 关键变化与验证 |
|---|---|---|---|
| 图 `object.figure` | `children[]`、引用键、复合范围身份 | label、一个或多个 caption、asset/figure group、legend、note、source statement、unknown | 内部真实顺序完整；主体、中文/英文图名、图注和来源不被拆散或按类型重排 |
| 子图组 `object.figure_group` | `children[]`、组身份 | 有序 figure part、局部 label/caption/note | 子图顺序、总题与子题关系；不能只保留拼接后的总图 |
| 表 `object.table` | `children[]`、引用键、复合范围身份 | label、一个或多个 caption、table grid、legend、note、source statement、unknown | 内部真实顺序完整；允许题名在表前或表后，并保留注释、来源与多语言题名的穿插顺序 |
| 图表标识 `object.label` | `label_text`、编号语义、引用键 | 可选行内内容 | 独立标识保持自己的位置；无法与题名安全拆分时由 caption 原文整体保留 |
| 图表题名 `object.caption` | `caption_role`、`language`、原始内容、规范化视图 | 可选行内内容 | 中文名、英文名和副题名分别建实例；配对关系和显示顺序分别验证 |
| 图表局部注释 `object.note` | `note_role`、`language?`、标记、正文 | 段落、列表或结构化注释条目 | 与脚注/尾注和审阅批注区分；单位、缩略语、显著性说明不静默丢失 |
| 图表可见来源 `object.source_statement` | `language?`、可见标签、原始内容、可选行内引用 | 行内文本、citation marker | 与 provenance、任务证据和 DOCX 包关系分开；作为复合对象成员保留实际位置 |
| 表格主体 `object.table_grid` | 行列结构、表头范围、合并和跨页观察 | 有序 table row | 只拥有表格网格，不拥有位于网格前后的题名或表注 |
| 表格行 `object.table_row` | 行序、行角色 | 单元格集合 | 逻辑行序与合并关系完整 |
| 表格单元格 `object.table_cell` | 列序、行列跨度、原始内容 | 段落、列表、图、公式或未知对象 | 不用纯文本替代内部复合内容 |
| 陈列公式 `object.equation` | 表达式、公式号、引用键、条件说明、来源表示 | 数学表达式、编号、子式 | 可编辑公式、图片公式和未知表示均需保留；交叉引用有效 |
| 公式组 `object.equation_group` | 组号、子式标识、对齐关系 | 多个 equation part | 子式顺序、分行和编号关系 |
| 图表说明 `object.legend` | 符号、颜色、系列、解释 | 有序条目集合 | 与所属图表关联，并在复合对象 `children[]` 中保留实际位置 |
| 媒体资产 `object.asset` | 媒体类型、来源关系、摘要、尺寸观察、替代文本 | 原始或嵌入资源 | 二进制身份、关系和可访问性信息完整 |
| 文本框/形状 `object.textbox_or_shape` | 可见文字、几何对象、关系、替代文本 | 段落、图片、域或未知对象 | 不能因不在普通段落流中而丢失 |
| 嵌入对象 `object.embedded` | 对象类型、显示预览、内嵌/链接关系、替代说明 | 预览、附件或 opaque payload | 无法解释时整体保留并进入人工复核 |

### 6.5 行内语义与引用单元

| 单元 | 常见字段 | 内容/关系语义 | 验证点 |
|---|---|---|---|
| 强调 `inline.emphasis` | 文本、强调类型 | 标示语义强调，不等同于任意直接格式 | 语义保留，不复制无关源格式 |
| 术语 `inline.term` | 术语、语言、显示内容 | `relation.cross_reference` 指向定义或术语表 | 与术语表或定义关联 |

| 行内公式 `inline.math` | 数学表达式、来源表示、原始范围、前后文字关系 | 段落内部的数学对象 | 文字、公式和未知表示不互相替代 |
| 超链接 `inline.hyperlink` | 显示文字、当前可见状态 | `relation.hyperlink` 指向一个外部或内部目标 | 目标有效、可见文字保留 |

### 6.8 来源结构控制、任务覆盖与未知保留

| 对象 | 所属视图 | 常见字段 | 验证点 |
|---|---|---|---|
| 分节 `structure.section_break` | `snapshot_map` 中锚定前后内容实例的来源结构 | 类型、继承关系、页面设置范围、前后锚点 | 不产生意外空白页或继承错误；不把 source ref 当语义 ID |
| 分页 `structure.page_break` | `snapshot_map` 中锚定阅读位置的来源结构 | 表示类型、前后锚点、观察原因 | 不把偶然分页当作内容身份 |
| 条件区域 `structure.conditional_region` | `decision_overlay` | 条件、所有权、空内容策略、证据引用 | 未确认条件时不静默删除 |
| 手工区域 `structure.manual_region` | `decision_overlay` | 原因、负责人、复核要求、目标实例 | 原结构完整、明确进入人工复核 |
| 未知可见对象 `content.unknown_visible` | 主内容树或附着内容树中的原位占位节点 | 实例身份、父节点、顺序、可见摘要 | 仍占据原阅读位置，不能只留在注册表 |
| 未知原始载荷 `extension.unknown_payload` | `thesis.preservation` | 原对象、上下文、来源、风险、占位实例 ID | 内容不丢失，且能回指原位占位节点 |

### 6.9 审阅、修订和关系对象

这些对象不一定属于论文最终可见正文，但会影响内容真值、协作状态或其他对象的可达性。
纯文本抽取不能证明它们不存在。

| 对象 | 所属视图 | 领域处理原则 | 验证点 |
|---|---|---|---|
| 批注 `review.comment` | `thesis.preservation` + `relation.anchored_to` | 默认保留；是否清理必须由当前任务明确授权 | 批注数量、正文和锚定范围不静默变化 |
| 修订 `review.revision` | `thesis.preservation` + `relation.anchored_to` | 不自动接受或拒绝；保持源状态 | 修订计数、范围和可见结果可追溯 |
| 书签/命名锚点 `source.bookmark_anchor` | `snapshot_map` | 作为来源快照定位证据保留，不伪装成语义关系边；交叉引用仍指向逻辑内容目标 | 书签 locator 与 document hash 匹配，目录和交叉引用目标仍有效 |
| 内容控件 `source.content_control` | `snapshot_map`；内部可见内容仍在内容树 | 区分承载容器、说明占位和固定内容 | 内部内容及来源边界不丢失 |
| 字段 `source.field` | `snapshot_map`；显示结果作为实际内容节点 | 字段指令、显示结果和 `relation.generated_from` 分别保留 | 不把结果文字误当作字段本身，也不丢失可见结果 |
| 语义超链接 `relation.hyperlink` | `thesis.relations` | 每条边从一个可见 hyperlink 实例指向一个内/外部目标 | 目标有效且显示文字保留 |
| 来源包关系 `source.package_relationship` | `snapshot_map` | 图片、嵌入对象等来源承载关系随对象迁移，不提升成泛化语义边 | 关系目标和二进制对象仍可达 |
| 自定义或未知部件 `extension.opaque_part` | `thesis.preservation` | 未确认前整体保留，不猜测其业务含义 | 未知可见对象与关键关系没有被丢弃 |

### 6.10 论文伴随材料与提交包边界

历史模板中常见任务书、开题报告、答辩记录、题目变更审批、成绩评定等内容。它们可能与
论文装订在同一 DOCX，也可能是独立文件，但不能因此默认成为“论文正文单元”。母稿把它们
放在提交包层，以免丢失，又避免把单校表单提升为通用论文结构。

| 单元 | 例子 | 默认身份 | 处理原则 |
|---|---|---|---|
| 伴随文档 `package.companion_document` | 任务书、开题/中期材料、答辩或审批表 | 当前任务材料 | 保留原身份、来源、顺序和是否装订的证据 |
| 人工表单 `package.manual_form` | 签字、盖章、成绩、意见区域 | school/manual owned | 不从学生正文推造，不自动填充未知事实 |
| 附件 `package.attachment` | 数据、代码、问卷、证明、独立图表 | student/mixed | 记录与论文的引用关系和交付方式 |
| 提交清单 `package.submission_manifest` | 必交文件、命名、版本、状态 | current-task evidence | 只服务本次交付，不进入产品 Knowledge |

是否把伴随材料并入最终论文、放在何处、是否允许修改，只能由当前任务证据或用户确认决定。

## 7. 模板树节点字段目录

模板逻辑节点需要覆盖以下信息，但这里不固定为公共 Schema：

| 字段类别 | 候选字段 | 目的 |
|---|---|---|
| 身份 | semantic role、instance identity、parent、children、sequence | 描述模板逻辑关系 |
| 节点类型 | fixed、inline slot、block slot、container、composite container、repeatable、generated、conditional、manual | 描述承载能力 |
| 可接受内容 | allowed roles、allowed kinds、allowed child roles、cardinality、language | 限制什么内容及哪些复合成员可以进入 |
| 内部结构与顺序 | ordered children、relative-order constraints、adjacency/grouping | 表达当前模板实际观察到的题名、图/表主体、注释、来源和固定内容顺序 |
| 所有权 | school、student、system、mixed、manual | 决定是否允许替换或删除 |
| 空内容行为 | keep、remove、review、fail、inherit | 处理当前任务没有内容的情形 |
| 内容处置 | preserve、fill、generate、remove instruction、manual、unknown keep | 区分模板固定内容、学生槽位、生成域和说明文字 |
| 位置证据 | current-task locator、anchor evidence、mapping quality | 只服务当前文档快照 |
| 条件 | applicability、condition source、confirmation | 防止条件区域被静默处理 |
| 验证 | expected children、order/pairing checks、fixed-content check、visible-result risk | 支持修改后独立复核 |

图表模板不能只记录“这里允许一个 table/figure”。如果模板分别提供中文题名槽、英文题名槽、
图/表主体槽、注释槽或来源槽，它们都进入同一个 `template.composite_container.children[]`，
并按模板实际顺序保存。`allowed child roles` 可以约束 `object.caption`、`object.table_grid`、
`object.asset`、`object.note` 或 `object.source_statement`，但该顺序和必选性只属于当前任务证据。

## 8. 绑定字段目录

绑定是 `task.projection` 中从内容/事实到模板节点的有向边记录，不是包含树。每条绑定通常需要表达：

| 字段类别 | 候选字段 | 说明 |
|---|---|---|
| 来源选择 | content role、instance selection、language、condition | 选择放什么 |
| 目标选择 | template node、container、relative anchor | 决定放到哪里 |
| 写入方式 | replace、append、repeat、generate、preserve | 描述结构行为 |
| 复合成员 | aggregate/member selection、target child、order evidence | 允许整图整表绑定，也允许 caption、grid/asset、note、source 分别绑定到目标有序子节点 |
| 转换 | normalization、generated label、field construction | 仅描述必要语义转换 |
| 空内容 | inherit、keep、remove、review、fail | 当前内容缺失时如何处理 |
| 证据 | source refs、applicability、confirmation | 说明为什么建立该绑定 |
| 验证 | uniqueness、compatibility、no-loss、member order、language pairing、render checks | 防止错位、重排、重复和丢失 |

未来“样式观测与确定性补全合同”可以让绑定引用对应的 `style_observation` 与
`resolved_style`，但不得把样式参数塞回内容字段，也不得让样式相似性反向改写已经确认的
内容语义。

## 9. 内容所有权与处置策略

所有权、出现状态和处置策略是三个独立维度。学校拥有的固定标题可以“已存在 + 保留”，
学生拥有的摘要可以“缺失 + 待填”，系统拥有的目录可以“已存在显示结果 + 重新生成”。
这些都是 `task.decision_overlay` 中的当前任务判断；本节列出通用候选值，不把它们写回
任务内论文逻辑实例。

### 9.1 所有权

| 所有权 | 含义 | 典型内容 |
|---|---|---|
| student | 学生提供并拥有内容真值 | 题名、摘要、正文、图表、参考文献 |
| school | 当前模板或要求提供的固定事实 | 固定声明、校名、表单标签 |
| system | 可由结构关系确定性生成 | 目录、页码、题注序列的生成视图 |
| mixed | 多方共同组成，不能整块按单一规则处理 | 封面、声明签署区、审批信息 |
| manual | 需要人工填写、签署或确认 | 签名、盖章、评审意见、成绩 |

### 9.2 处置策略

| 策略 | 含义 | 安全边界 |
|---|---|---|
| preserve | 原样或按当前任务允许的最小变化保留 | 不因内容为空、未知或外观像占位符而删除 |
| fill | 用已授权且已确认的学生/任务内容填入 | 不猜测姓名、编号、日期、签署或审批事实 |
| generate | 由可验证的结构关系生成 | 保留字段语义，不只改显示结果 |
| remove_instruction | 删除仅用于说明格式或填写方式的模板文字 | 必须有当前任务证据证明其是说明而非固定正文 |
| manual | 保留位置并交给指定的人处理 | 自动化不代填、不伪造完成 |
| unknown_keep | 证据不足或对象混合时保留 | 是默认保守策略，必须产生复核入口 |

### 9.3 内容来源角色

- **模板固定内容**：成稿中应保留的标题、声明、标签或组织信息；
- **模板说明内容**：解释如何填写或排版的文字，是否移除需当前任务证据；
- **学生内容**：来自学生原稿或用户明确提供的信息；
- **生成内容**：由标题、题注、引用目标、分节等结构关系产生的字段或视图；
- **人工内容**：签署、审批、成绩、意见等不能由系统推造的事实；
- **混合/未知内容**：同一段、单元格或对象中包含多个来源角色，拆分不可靠时整体保留。

## 10. 关系与约束目录

### 10.1 内容关系

- 主阅读顺序只由 `thesis.primary_flow` 拥有；脚注、尾注、页眉页脚等附着内容保留各自子树并通过关系连接；
- 论文级共享事实只保存一份任务内事实实例；封面、题名页、书脊、摘要页等通过 ref 表达出现位置，并以 `relation.fact_occurrence` 指向该事实的 `instance_id`；
- 一个事实可以被多个单元引用，一个单元也可以引用多个事实，二者通常是多对多关系；
- 单元固定正文、摘要正文、献词、正文段落和图表等局部内容由单元直接拥有，不强行提升为 metadata；
- 摘要与关键词属于同一语言范围；
- 标题与正文内容块共同形成有序树；同一 `children[]` 中二者可以互相穿插，且允许学校省略某些可见编号层；
- 图和表各自拥有唯一有序 `children[]`，使 label、caption、asset/grid、legend、note、source
  和 unknown 在复合范围内保持真实顺序；陈列公式与编号、引用键保持关联，行内公式保留在所属段落的运行顺序中；
- 脚注标记和脚注正文通过 `relation.note_reference` 一一对应；
- 每条 `relation.citation` 只保存一个文内引文标记到一个文献条目的连接；多目标标记建立多条有序边，同一文献可以被多次引用；
- 目录和图表目录是派生视图，不反向拥有正文内容；
- 附录可以复用正文对象类型，但具有独立编号和目录语义；
- 页眉、页脚和页码受分节边界影响；
- 双语标题、摘要、关键词和图表 caption 需要明确对应关系，但不要求逐字翻译、固定先后或字段数量完全相同；
- 图表局部注释由图表复合对象拥有；脚注/尾注属于附着流，审阅批注属于 preservation；
- 可见来源行、文献引用、任务证据和来源包关系分别进入内容、关系、证据和快照视图；
- 原始内容和规范化视图共同描述同一对象，后者不能覆盖前者；
- 批注、修订和附着内容通过 `relation.anchored_to` 连接内容范围；书签、字段和来源包关系作为匹配 document hash 的快照表示保留，不能孤立迁移；
- `thesis.relations` 下只使用第 3.2 节的单数 canonical 边名；所有 map、backlink 和分组视图只由 `relation_index.by_source/by_target/by_kind` 派生；
- 未知可见对象在主流或附着流原位置保留 `content.unknown_visible`，原始 opaque 载荷另存并回指该实例。

### 10.2 模板承载约束

- scalar 内容不能无规则地写入只接受 block collection 的位置；
- repeatable 内容不能因模板只有一个示例而压缩为单值；
- 图表等复合模板容器必须按当前模板观察保存有序子节点、允许角色和相对顺序约束，不能只留下一个无内部结构的 block slot；
- caption、asset/grid、note、source 等成员可以分别绑定；任何重排都需要当前模板/要求证据并验证复合对象无损；
- fixed 和 manual 对象不能因视觉类似占位符而删除；
- generated 字段不能只替换显示文字而破坏可更新语义；
- 条件区域的出现与删除必须由当前任务证据支持；
- 模板位置只提供承载能力，不重新定义内容语义。

### 10.3 无损与判断约束

- 可见文字相同不等于内容完整；媒体、公式、脚注、批注、修订、字段和关系必须独立检查；
- 来源样式、位置和外观可以辅助识别，但任何一个都不能单独决定内容语义；
- 段落拆分或合并时，原始字符顺序、行内对象和来源覆盖范围必须仍可验证；
- 对象无法可靠分类时保留为 unknown/opaque，不把它塞进语义不准确的现有单元；
- `semantic_id`、当前逻辑 `instance_id` 和 `snapshot_locator` 必须分离；document hash 改变后旧 locator 只能作为历史证据，不得授权新快照编辑；
- 所有权、出现状态、处置、冲突和置信度属于当前任务投影，不能反向污染任务内论文逻辑实例；
- 伴随材料是否属于论文成稿、是否装订以及是否修改，只由当前任务证据决定；
- 任何规范化、生成或绑定结果都必须能回指来源对象和本次判断依据。

## 11. 验证覆盖目录

### 11.1 内容完整性

- 共享事实与各出现位置的引用一致，未产生互相冲突的重复真值；
- 单元局部内容没有被误提升为共享事实，事实引用也没有被误复制成彼此独立的值；
- 学生正文、图表主体、中文/英文题名、图表局部注释、可见来源、公式、引用和附录没有静默丢失；
- 固定学校内容没有被误删；
- 占位符、格式说明和示例内容按当前任务规则处理；
- 未知扩展对象、文本框、嵌入对象和伴随材料被保留并报告；
- 原始内容与规范化字段之间不存在不可解释的删改、翻译或重写。

### 11.2 结构完整性

- 主阅读顺序树、附着内容子树、事实注册表、关系图和保留注册表没有被压成一棵伪包含树；
- 封面、题名页、书脊和摘要等复合前置单元使用同一有序 `children[]`，ref、标签、固定内容、图形、人工区和 unknown 的穿插顺序未被分组重排；
- 标题层级、列表层级和编号关系有效；
- 正文根和每个章节的 `children[]` 保留内容块与子章节的实际穿插顺序，没有因拆成两组而重排；
- 图和表各自的 `children[]` 保留 label、caption、asset/grid、legend、note、source 和 unknown 的实际穿插顺序；“表体 → 注释 → 题名”等非常见顺序不会被自动改写；
- 中文/英文图表题名分别拥有实例、语言和顺序；已确认的对应项通过 `relation.paired_with` 配对，缺失项不会被推造；
- 图题、表题、图表局部注释、公式号、脚注和交叉引用目标存在；
- 行内公式没有从段落文字流中脱落，陈列公式的编号与引用目标有效；
- 文内引文的每个目标均由一条 `relation.citation` 解析到文献条目，多目标顺序和重复引用没有被压缩；
- 可重复内容没有被压缩或错误复制；
- 分节、页眉页脚和页码继承关系有效；
- 生成字段保持可更新语义。

### 11.3 来源、关系与审阅完整性

- 每个内容实例通过当前 `snapshot_map` 回指来源范围，拆分后的子节点没有遗漏来源片段；
- 源、模板和候选文档各自使用匹配 document hash 的有效 `snapshot_locator`，编辑后未复用旧快照 locator；
- 原始证据与 unknown/conflict/处置等判断状态分别保存在 evidence ledger 和 decision overlay；
- 每条 canonical relation 只有一个 source、一个 target 和一个稳定 `relation_kind`；多目标使用多条边，派生索引没有复制关系真值；
- 图表局部 `object.note` 没有被误作 attached note，脚注/尾注没有被塞回图表 `children[]`，审阅批注仍保留在 preservation；
- 可见 `object.source_statement`、文献引用、provenance 证据和 DOCX 包关系分别留在内容、关系、证据和快照视图；
- 图片、超链接、页眉页脚、脚注、外部对象和其他关系目标仍可达；
- 批注、修订、书签、内容控件和字段的数量、范围与状态没有静默变化；
- 无法验证的对象明确标为 unknown/needs_review，而不是伪装成通过；
- 学校固定、学生、生成、说明和人工内容的处置与当前任务证据一致；
- `submission.thesis.artifact_ref` 可解析到最终候选 `document_sha256`，提交包没有重复拥有论文语义树。

### 11.4 可见结果

- 页面没有截断、重叠、不可见文字或异常空白；
- 图、表、公式和题注保持可读与正确关联；
- 标题、目录、页码和页眉页脚在最终渲染中一致；
- 高风险页面和对象经过真实可见结果复核；
- 结构合法或 Tool 成功返回不能替代可见结果验证。

本节只定义“需要看见和验证什么”。具体字体、字号、间距、页面参数及其逐属性来源留给
后续“样式观测与确定性补全合同”。

该合同至少必须能够验证：

- `style_observation` 绑定当前模板 document hash 与有效 `subject_ref`，不是旧快照观察；
- `missing_properties` 在命名样式继承、直接格式、主题和默认值完整展开之后产生；
- `resolved_style` 的每个最终属性都有可解析的 `property_provenance` 和证据/标准引用；
- 国家标准补全使用当前任务已确认适用的版本与条款，未覆盖属性仍在 `unresolved_properties` 中。

## 12. 变化点与扩展方式

### 12.1 学校差异只填什么

当前学校任务通常只需要提供：

- 哪些通用单元必需、可选、禁止或条件出现；
- 每个单元使用哪些当前学校字段、固定文字和顺序；
- 模板中承载每个单元的位置和结构证据；
- 各对象属于固定、填充、生成、说明移除、人工还是未知保留；
- 伴随材料是否属于最终交付、采用什么顺序和边界；
- 局部例外、冲突解决和用户确认。

这些差异不应重新定义整套通用论文内容世界。样式观察、确定性补全和未解决属性留待后续
“样式观测与确定性补全合同”单独承载。

### 12.2 未覆盖对象怎样进入

新对象先作为扩展单元记录：

- 临时语义名称；
- 父单元和邻接关系；
- 内容与结构字段；
- 原始表示、所有权和当前处置策略；
- 当前任务来源；
- 为什么现有通用单元无法表达；
- 是否在多个学校任务中重复出现。

只有经过跨任务证据和去学校化评审后，扩展对象才有资格进入母稿的通用单元目录。

## 13. 识别方法母表

识别方法回答“怎样从当前任务材料中判断对象和关系”，但不规定某个 Tool、XPath、模型
提示词或固定调用顺序。

### 13.1 先建立证据清单

- 记录模板、要求文件、官方示例、学生论文和用户确认各自的身份、来源、日期与适用范围；
- 区分规范声明、文档结构观察、页面观察和用户确认，不把单一观察直接当作规则；
- 同一文件中也可能存在多个适用范围，例如本科/研究生、不同语言或不同章节；
- 来源不明、版本不明或适用范围不明的材料保留为候选证据。

### 13.2 识别文档区域与单元边界

综合使用以下信号，而不是依赖单一外观：

- 标题文字、同义标签、语言和上下文；
- 标题层级、编号序列、目录目标和书签关系；
- 分节、分页、页眉页脚变化和前后邻接对象；
- 表格、内容控件、文本框、字段和其他容器边界；
- 样式名称与可见外观只能作为证据之一；
- 模板示例、说明文字和学生内容的来源角色。

正文中的一级标题通常仍属于 `body.main` 的内部结构，不能仅因层级高就切成新的顶层论文
单元。目录、图目录和表目录即使外观相似，也要根据条目目标和来源对象分别识别。

识别正文时先按来源阅读顺序建立 `body.main.children[]`，再判断每个标题开启哪个
`body.section`，并把后续内容块和直接子章节依次放入该章节同一个 `children[]`。不能先把
全部段落、图表、公式归为一组，再把全部标题归为另一组后尝试拼回顺序。

每个识别结果分别确定候选 `semantic_id`、`node_kind` 和当前逻辑 `instance_id`，再在
`snapshot_map` 中记录包含 document hash、locator kind/value 的当前有效 `snapshot_locator`。
Tool `object_ref`、页码或 bbox 不能直接充当 `instance_id`；编辑后的新快照必须重新建立映射。

主阅读内容进入 `thesis.primary_flow`；脚注、尾注、页眉页脚等进入附着内容子树并建立
锚定关系。无法分类但可见的对象仍在原顺序位置建立 `content.unknown_visible`，不能只把
opaque 载荷扔进保留注册表。

识别标题层级时分别记录：推导出的语义 `level`、来源大纲层级、原始编号及其分量深度、
样式/外观证据和目录层级。它们一致时可以互相印证，不一致时保留冲突；不能选其中任意一个
直接充当最终语义层级。

### 13.3 识别标量、复合对象与关系

- 先区分“论文级事实”和“事实在某个单元中的出现位置”，分别建立拥有各自 `instance_id` 的 fact 与 ref，再用 `relation.fact_occurrence` 连接；
- 同一题名、作者或日期在多个位置出现时，合并语义事实；每个 ref 的来源映射和判断状态分别
  保存在 `snapshot_map` 与 `decision_overlay`；
- 标签—值结构中同时保留标签、值、原始文本和二者关系；
- 图、表先识别完整复合范围，再按来源阅读顺序把 label、caption、asset/grid、legend、
  object note、source statement 和 unknown 写入同一个 `children[]`；不能先按类型分组；
- 表格按复合 table、独立 table grid、逻辑行、单元格和单元格内部对象分层，不用拼接文本
  替代，也不把题名或表注伪装成首尾行；
- 双语题名、摘要、关键词以及图表 caption 分别识别语言和实例后建立
  `relation.paired_with`；不因文字相似就假定配对，也不推造缺失译名；
- 区分可见 `object.source_statement`、其中的文献 citation、任务 provenance 证据和
  `source.package_relationship`；不能把四种来源压成一个字段；
- 区分段落内 `inline.math` 与独立 `object.equation`，同时保留可编辑、图片和 opaque 来源表示；
- 结合显示文字、字段、引文键和文献目标识别 `inline.citation`，不要把上标引文与脚注标记、
  科学上标或主题索引标记混淆；
- 脚注标记—脚注正文、引文—文献条目、交叉引用—目标分别建立
  `relation.note_reference`、`relation.citation` 和 `relation.cross_reference`；每条边只连接一个目标；
- 图片公式、文本框、嵌入对象等无法解析时保留来源表示和 opaque 内容。

### 13.4 识别内容来源角色和处置候选

| 观察问题 | 识别重点 | 证据不足时 |
|---|---|---|
| 是固定内容还是学生槽位 | 是否为组织/声明事实、是否有明确标签、是否等待任务值 | mixed / unknown_keep |
| 是默认标题还是说明文字 | 成稿是否应保留、是否在要求中被称为说明、相邻对象如何使用 | preserve 并请求确认 |
| 是生成字段还是普通文字 | 是否存在字段结构、目标关系和可更新语义 | 保留字段及显示结果 |
| 是人工区还是可自动填充 | 是否涉及签字、盖章、成绩、意见或审批事实 | manual |
| 是论文单元还是伴随材料 | 是否属于论文论证内容、是否独立提交、是否只服务管理流程 | package companion |

识别结果只是当前任务的候选判断；只有证据充分时才能形成实际处置动作。

### 13.5 保留来源覆盖与不确定性

- 每个识别结果用 `evidence.supports` 记录来源范围和使用的信号，并在 decision overlay 记录
  适用范围与置信状态；
- 检查来源对象是否被零个、一个或多个内容节点覆盖，暴露遗漏与重叠；
- 不能可靠拆分的混合段落、run 或单元格整体保留，同时记录候选分类；
- `unknown` 是正式领域状态，不是解析失败后可以丢弃的日志。

## 14. 解释原则母表

### 14.1 适用范围先于具体结论

先确定规则作用于哪类文档、单元、语言、层级和条件，再读取具体要求。局部例外不提升为
全文规则，示例中的偶然内容或外观也不覆盖明确声明。

### 14.2 声明、观察和验证分开

- 要求文件中的文字是声明；
- 从 DOCX 结构、字段或渲染页面读到的是观察；
- 独立检查确认声明与最终结果一致，才是验证。

三者可以互相支持，但身份不能互换。模板里看见某个值不自动证明它对所有对象都具有规范性。

### 14.3 区分空、缺失、未知、冲突和不适用

| 状态 | 含义 | 处理倾向 |
|---|---|---|
| empty | 对象存在且值明确为空 | 按对象所有权和空内容规则处理 |
| missing | 预期对象未出现 | 检查是否必需、是否需要填充或生成 |
| unknown | 当前证据不能确认 | 保留并获取更多证据 |
| conflict | 来源给出不兼容结论 | 记录双方、范围和影响，请求解决 |
| not_applicable | 已确认当前情形不适用 | 不生成、不伪造缺失 |

材料没有声明，不等于允许套用通用默认值；未知也不等于空。

### 14.4 内容保护优先

- 学生内容与模板固定内容冲突时，先避免覆盖学生内容并显式暴露冲突；
- 无法确认的对象、关系或伴随材料默认保留；
- 不能通过删除正文、图表或未知对象来解决结构或可见结果问题；
- 规范化和结构化不得改写姓名、题名、编号、日期、引文或科学表达的事实含义。

### 14.5 通用 Knowledge 不替学校作决定

通用母稿提供对象、方法、原则和候选处理模式，不提供某校的必需目录、固定文字、顺序、
参数或优先级。历史任务多次出现的结论仍需去学校化评审，不能自动晋升。

## 15. 通用处理模式母表

这些模式是可组合的方法，不是固定阶段图、工作流引擎或第二套 Agent loop。

### 15.1 检查—判断—修改—验证

1. 检查源文档、目标材料、结构对象、关系对象和可见页面；
2. 整理已确认规则、未知项、冲突、内容处置和受影响范围；
3. 在源文档只读的前提下，对工作副本执行范围最小且可追溯的修改；
4. 重新检查内容、结构、关系、审阅状态和可见结果。

具体任务可以回看、拆分或重复这些动作，不要求一次线性完成。

这些动作共享第 3.2 节的锚点：检查更新 `snapshot_map` 和 evidence，判断更新
`decision_overlay`，修改消费当前有效 `snapshot_locator` 与 `binding.edge`，验证为同一逻辑实例建立候选快照
映射和结果记录。它们不是写入内容节点的 stage/status，也不形成 checkpoint 或阶段 DAG。

### 15.2 语义判断与确定性执行分离

Agent 解释证据、识别内容和处理歧义；Tool 按已经确认的目标和参数检查、修改或渲染。
Tool 不从长期 Knowledge 猜学校事实，Knowledge 也不保存 Tool 私有 locator。

### 15.3 最小修改与原位保护

- 优先在学生论文副本上做受控修改，能局部改变时不整体重建；
- 跨文档承载时，内容对象与媒体、字段、编号、注释、审阅和关系一起处理；
- 模板占位符只提供当前位置证据，不能把占位内容或说明文字复制成学生事实；
- 无法可靠定位时重新检查或请求确认，不扩大修改范围。

### 15.4 失败、提问和人工复核

- 证据不足、来源冲突、未知可见对象或高风险关系无法验证时，停止相关修改；
- 问题只询问会改变处理结果的最小事实，并说明受影响对象；
- manual/unknown_keep 对象保留原结构，明确负责人和复核要求；
- 不能用重复尝试、文件可打开或某个成功状态掩盖未验证的缺口。

### 15.5 完成证据

完成至少需要证明：学生内容未丢失、学校固定内容处置正确、模板说明和占位符按证据处理、
生成关系仍有效、审阅与未知对象状态已知、可见结果已复核。结构检查成功或产物存在都不能
单独构成完成。

## 16. 母稿完成检查

- [ ] 论文级共享事实字段没有明显大类缺口；
- [ ] 主阅读顺序树、附着内容子树、共享事实、非包含关系、审阅/未知保留对象和任务投影均有覆盖；
- [ ] 总览图已把产品通用词汇、任务内逻辑实例和不可变文档快照放在不同生命周期层；
- [ ] fact/unit/ref/object 统一使用任务内 `instance_id`，并与 `semantic_id`、`relation_id` 和 `snapshot_locator` 明确分离；
- [ ] ID 生命周期已覆盖续接、语义重分类、拆分、合并、复制、删除和 `needs_review`；
- [ ] 任务内论文逻辑实例不再拥有所有权判断、出现状态、处置、置信度、冲突或验证结果；
- [ ] 模板绑定表达为当前任务边记录，不是内容树或模板树的子节点；
- [ ] 每个单元都能说明目的、字段、内容形态、子对象、变化点和验证点；
- [ ] 文本、段落、标题、列表、表格、媒体、题注、公式、字段和未知对象均有容纳位置；
- [ ] 语义字段与节点形态已经分离，复合对象不依赖扁平文本表达；
- [ ] 共享事实、文档单元和事实引用已经分离，封面等单元不重复拥有论文级真值；
- [ ] 封面、题名页、书脊和摘要的可见子节点进入同一有序 `children[]`，没有按 ref/fixed/mark/manual 分组丢失穿插顺序；
- [ ] 正文标题使用开放递归层级，逻辑层级、编号深度和来源大纲层级没有混为一谈；
- [ ] 正文根与章节使用统一有序 `children[]`，内容块和子章节的前后穿插关系不会丢失；
- [ ] 图和表使用有序复合对象；caption、asset/grid、legend、note、source 和 unknown 的内部穿插顺序不会丢失；
- [ ] 中文/英文及其他语言的图表题名拥有独立实例、语言、顺序和可验证的 `relation.paired_with`；
- [ ] 图表局部注释、脚注/尾注、审阅批注以及可见来源/provenance/package relationship 的职责没有混淆；
- [ ] 当前模板能以有序复合容器表达图表成员槽位和相对顺序，绑定可以落到整个复合对象或具体成员；
- [ ] 行内/陈列公式均在正文实际位置表达，文内引文与后置文献条目的多对多关系清楚；
- [ ] `thesis.relations` 只使用单数 canonical 边名且每边只有一个目标；`_map`、backlink 和分组只存在于三个派生索引；
- [ ] 原始内容、规范化视图、来源范围和关系目标能够同时保留；
- [ ] 可选、条件、重复、固定、填充、生成、说明、手工和未知对象都有表达方式；
- [ ] 论文正文与提交包伴随材料的边界清楚；
- [ ] `submission.thesis` 只以 `artifact_ref` 引用最终候选 hash，不重复拥有论文语义树；
- [ ] 当前学校差异与通用领域模型的边界清楚；
- [ ] 没有把示意字段误写成已实现公共 Schema；
- [ ] 没有在本轮提前建立样式角色、属性目录或默认值；样式只保留观察、语义绑定、逐属性来源、确定性补全和 unresolved 的合同边界；
- [ ] Agent 不生成样式缺失值，国家标准无明确适用条款时也不补值；
- [ ] `resolved_style` 的每个已解析属性都有可追踪的 `property_provenance`；
- [ ] 概念、识别方法、解释原则和通用处理模式都能从同一母稿投影；
- [ ] 没有提前拆成四个彼此独立的 Knowledge Reference。

## 17. 稳定以后如何拆解

母稿稳定后，可以从同一套对象和字段中投影：

- 对象定义、关系和职责边界；
- 从模板、文字、样式、页面和上下文识别这些对象的方法；
- 处理缺失、冲突、歧义和局部例外的原则；
- 检查、修改、渲染与验证的通用模式。

随后再单独建立“样式观测与确定性补全合同”，讨论模板样式观察、继承展开、语义绑定、
逐属性 provenance、适用标准条款、确定性补全和 unresolved。它不是样式经验库，不能向
Agent 提供默认格式，也不能反向改变本稿已经确定的内容语义。

这些都是未来工作方向；本阶段不创建四篇正式 Knowledge 草稿，也不修改正式 Knowledge v1。
