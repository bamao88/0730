# 直接 API 的最小字段语义实验

2026-09-11。任务：把上次失败的封面原文字段直接发给同一 MiniMax-M3 API，用简短提示验证语义和耗时。

结论：单条字段可以在约 2–3 秒返回，8 条混合文本在约 4–8 秒返回结构化判断。但关闭推理时，正确性仍不稳定；不能把先前的失败只归因于完整 Skill、Agent SDK 或长上下文。尤其要区分“知道需要填写哪种信息”和“给出正确的原文替换范围”。

## 请求是什么

直接 HTTP 请求既有 MiniMax Anthropic Messages API，没有 Agent SDK、工具调用、文件读取、Registry、Skill、项目指引或对话历史。凭据在内存中从既有配置读取，没有写入产物。记录请求正文、公开回答、耗时及 API usage，不保存推理内容。

输入逐字取自上次真实 `unit_evidence_packet`。主要病例为中文题目、英文题目、姓名、学号、班级、导师；混合组另加校名和固定封面标题作为对照。仅附原模板中的事实“□表示占一个字宽的空格”，没有注入当前病例的正确答案。

三个提示版本：

1. [基础版完整请求](baseline-prompt.txt)：按固定文字、填写内容、格式说明和排版空白识别，要求连续片段逐字覆盖；返回简单 JSON。
2. [Few-shot 完整请求](fewshot-prompt.txt)：只在基础版后增加其他领域的“艺术展报名表 / 展览名称 / 策展人及职务”例子。没有使用当前封面的答案作例子。
3. [自然语言完整请求](natural-prompt.txt)：只有 93 字指令，不要求 JSON、角色枚举或 span。

自然语言版指令全文：

> 这是学校论文封面的模板文字。请逐条简要说明：填写真实信息时，哪些原文需要被替换、分别填写什么；哪些文字应保留；哪些只是格式或排版说明。同一行如含多个含义，请分别指出。用自然语言回答即可。

## 结果

| 请求 | 次数 | 每次耗时 | 正确性观察 |
| --- | --- | --- | --- |
| 基础版，单独英文题名 | 1 | 2.560 秒 | 原题名为 fill_slot，字体说明另拆，正确 |
| 基础版，单独中文题名 | 3 | 2.403 / 3.123 / 2.253 秒 | 只有第一次正确；另两次将题名原文归为 fixed_label |
| 基础版，单独导师行 | 1 | 2.596 秒 | 姓名与职称分开，但“教授”被当作固定文字，未识别为可变职称 |
| 基础版，8 条混合 | 3 | 7.640 / 7.858 / 6.307 秒 | 3 次都漏中文题名填写槽；部分学号、班级标签被吞，导师姓名职称合并 |
| Few-shot，8 条混合 | 3 | 4.548 / 4.533 / 4.008 秒 | 3 次均未整组通过；出现虚构题名片段、漏中文题名、标签误填或过度拆分 |
| 自然语言，8 条混合 | 3 | 18.593 / 18.501 / 22.993 秒 | 能说出中英文题名、姓名、学号、班级、职称需要填，但 3 次都错误保留中文题名前缀；还有格式/占位说明误解 |
| 基础版，8 条混合，开启 adaptive | 3 | 49.127 / 46.611 / 47.197 秒 | 全部达到 4000 输出 token 上限，API 报告 3999 为 thinking tokens，没有最终回答 |

耗时是本机发出单次请求至流结束的墙钟时间，包含网络与服务端时间。所有请求使用 standard tier；API 自动缓存命中情况保存在 usage 中。少量并发重复不能作为稳定的性能 SLA，也不能与完整 Agent 流程的任务量直接相除比较。

推理组沿用基础版的 4000 总输出 token 上限，无单独 effort 参数。它只证明在这个预算下没有可用回答，不能据此判断其语义能力，也不能称为已完成任务的耗时。没有扩大预算继续等待。

## 具体判断

英文题名单条实际输出：

```json
[
  {"text":"TITLE OF GRADUATION PAPER","role":"fill_slot","semantic":"毕业论文英文标题"},
  {"text":"（四号Times New Roman加粗，大写）","role":"style_only"}
]
```

中文题名的失败在极短请求中仍可复现：

```text
毕业论文（设计）中文题目 → fixed_label
```

自然语言组虽能说出要填中文题目，却三次都只建议替换“中文题目”，并把“毕业论文（设计）”保留为前缀。它没有满足本次要求的整段题名示例替换。不能因为提到了中文题目，就算题名槽已经做对。

导师行也有同类差异：基础混合组经常明确说“导师姓名及职称”，说明它认识到两类信息，但输出仍是一个合并填写片段；某次单条输出把职称拆出来保留，却未将其认作可变字段。自然语言解释与可执行拆分不能混为一谈。

Few-shot 不是没有作用：有些运行能正确分开导师姓名和职称，但同时在题名或其他字段出错。该提示改写还不能作为稳定修复。

自然语言回答也不只是输出格式问题：有的运行把对齐方框当作要填写的标签、把两字姓名说明误解为生僻字写法，或用通用学术习惯否定模板明确要求的英文全大写。这些是内容判断错误。

## 验证口径与下一步依据

本次是**真实 API 最小语义实验**，不是产品原生 real replay、E2E agent loop 或 product acceptance。没有修改生产 Skill、运行配置或代码，也没有声称解决最终 Word 的版式问题。

最有价值的结果是把问题压缩成可快速复现的小输入：不用完整 Agent 流程，就能在数秒内观察中文题名角色与替换范围错误。下一步应围绕这个最小病例评估语义指引、输出合同和模型配置，不能预先认定复杂上下文是唯一原因，也不能把长时间推理作为已经完成的性能方案。

原始逐次请求、回答和指标均在对应子目录；[全部指标](metrics-summary.json)。`mixed-1/2` 顶层返回数组而非约定 items 对象，属于独立的结构格式问题；即使容忍该格式，其语义仍有上述错误。原始输出未被修正或覆盖。

官方调用与推理参数依据：[MiniMax Anthropic API](https://platform.minimax.io/docs/api-reference/text-anthropic-api)。所有结论以上述实际响应为准。
